# ADR 0026 — Today becomes one iOS list language: an inset grouped list on a 16px rail, the companion's voice a chip + sheet

- **Status:** Superseded by [ADR 0033](0033-mozaik-2-tile-language.md) (2026-08-29) — the `.td-*` iOS-list render layer is gone; the day model, act-anywhere/dedup and the honest-state discipline this ADR carried forward all survive into Mozaik 2.0.
- **Driving bd:** `mezo-e26w`
- **Spec:** [`docs/superpowers/specs/2026-08-11-today-ios-redesign-design.md`](../superpowers/specs/2026-08-11-today-ios-redesign-design.md) (+ the validated mockup [`assets/2026-08-11-today-ios-redesign-mockup.html`](../superpowers/specs/assets/2026-08-11-today-ios-redesign-mockup.html) and the three-variant decision mockup [`assets/2026-08-11-today-message-variants-mockup.html`](../superpowers/specs/assets/2026-08-11-today-message-variants-mockup.html))
- **Supersedes:** [ADR 0025](0025-today-daypart-tabs.md) (the `.segtabs` daypart switcher, the full-bleed never-truncated `.coach-bubble.cb-band` briefing band, and the frameless `.dayview` panel's `.dv-hero*`/`.dv-act`/`.dv-done*` classes + its `.isl-*` micro-component reuse). ADR 0014's day model, act-anywhere and dedup decisions remain in force through all four render layers now, as does [ADR 0010](0010-gamified-growth-xp-feedback-not-payment.md) (nothing self-completes) — this is the render layer's **fourth** iteration over the same unchanged foundation (`dayFace.ts`, `todayItems.ts` — minus one line, `islandFacts.ts`, `questAction`/`habitAction`, `windDown.ts`).

## Context

ADR 0025's daypart-tabs page fixed the sky-of-islands' hidden-by-default problem (ADR 0022) but reintroduced a different one, in two parts, both surfaced directly from user feedback the day after ADR 0025 shipped:

1. **The briefing sits everywhere.** `MezoMessage` rendered full-bleed under the tabs, unclamped, and — because the design deliberately made it "always the day's briefing regardless of which daypart is selected" — on the mock data this put roughly 600px of the *morning* briefing above the fold on the Nap and Este tabs too, ahead of the content the user actually opened that tab to see.
2. **The "fewer boxes" goal of ADR 0025 overshot.** Once the outer card frame was removed, the panel didn't converge onto one surviving box language — it fractured into five-plus co-existing idioms on the same screen, none aware of the others: a coral text band (the message), a bare hero on the canvas, a bordered fact strip, individually-floating white `ItemRow` cards each with its own shadow, a yellow warn-chip, a lavender creed-chip, and grey action pills. Two secondary noises rode along: every row in a chain carried the same daypart emoji in a large tile (five 🌅 on the morning routine, four 🌙 on the evening), and the section labels (24px) and row cards (48px) didn't share a left edge.

## Decision

`/today` collapses onto **one box language**: the iOS "inset grouped list" — one rounded box per section, hairline-separated rows inside, everything aligned to a single 16px left rail (section headers, the list box, the hero, the stats box, the CTA, the done-fold — the same DS `--sp-4` token, applied elementwise, not a page-level margin).

1. **The companion's voice moves into a 44px `MezoChip`** (avatar · "Mezo" · the latest message's first sentence, ellipsis-truncated · a count badge · a chevron) that opens **`MezoMessagesSheet`** — the day's whole message thread, one bubble per message, never truncated. **Honest absence:** no message, no chip — no empty state, no placeholder. Unread state is a coral dot on the avatar, tracked client-side (`localStorage`, date-keyed, `shared/lib/seenMessages.ts`) — no backend, no server-side read-state, and the key expires on its own at midnight. The thread is composed from the **same two hooks** the old band already read (`useToday().briefing` + `useCompanionNote()`) via a new pure module, `logic/mezoMessages.ts` — no new data source, and the one seam any future generated message threads through without touching the chip or the sheet.
2. **Habit-row icons stop repeating the daypart emoji.** `logic/itemIcon.ts` replaces `todayItems.ts`'s single `DAYPART_EMOJI[chain.daypart]` line with a three-rung ladder: `habitKey` → a curated icon for all 15 seeded habits, else the habit's `LifeSkillKey` → the skill's own icon (the closed 8-value enum, so a future AI-generated or user-created habit always resolves to something meaningful), else the daypart emoji as a final fallback.
3. **A Today-local row/list/stats primitive family, not a `shared/ui/ItemRow` retrofit.** `TodayRow`/`TodayList`/`TodayStats` (`features/today/components/`) implement the list box, the hairline row separators, and four row-accessory shapes (a pipeable circle for MANUAL habits, an inked text button for every other action, nothing, or — set directly by the view, not derived — a chevron for the two sheet-opening rows that aren't `TodayItem`s at all, evening's Reflexió/Fókusz). `TodayRow` re-implements the four `ItemRow` behaviors worth keeping (`linkUrl` beside the action, never inside it; `disabled` withdraws the control rather than dimming it; a label with no handler renders inert text, never a dead button; a `done` row keeps its own icon — the tick circle alone carries the completion signal) rather than importing `ItemRow` itself. This is the ADR's central, deliberate trade-off — see Consequences.
4. **Everything else is unchanged:** the day model (`dayFace.ts`, `islandFacts.ts`, `questAction.ts`, `habitAction.ts`, `windDown.ts` carry no commits; `todayItems.ts` carries exactly the one-line `itemIcon` swap above), act-anywhere, the guard order, the evening's four wind-down phases, the `?dp=`/`?day=rough` scenario semantics, and every sheet.

## Consequences

- **Two row languages now coexist in the app.** `shared/ui/ItemRow` was deliberately not touched, so Fuel's "Mai" window flow (`features/fuel/components/WindowIsland.tsx`) and the Me routine editor (`features/me/pages/RoutineEditorPage.tsx`) still render the pre-existing `.itemrow*`/`.todaycard*` card language, while Today speaks its own `.td-*` iOS list idiom. This kept the redesign's blast radius to one screen — no Fuel/Me visual-regression risk, no shared-primitive review surface — at the cost of a real, currently-standing divergence. `frontend/src/features/today/todayScope.test.ts` is the structural guard that keeps the boundary from drifting further: it fails the build the moment any Today page-language component (other than the declared `AnchorIsland.tsx` exception, which never adopted the new idiom) imports `shared/ui/ItemRow`. A follow-up (`mezo-jaoy`) tracks unifying the two languages once the `.td-*` shape has proven out past a single screen.
- **The briefing is one tap away, not always on screen.** `MezoChip` renders nothing when the day has no message, so the companion's voice never competes with the daypart's own content for the first screenful — the same honest-absence discipline the fact cells and the niggle warning already followed.
- **One box language, at the cost of losing per-idiom distinctiveness.** The yellow warn-chip becomes a plain `.td-foot.is-warn` footnote; the lavender creed-chip becomes a tinted `TodayList` head (`.td-creed`); the individually-shadowed row cards become hairline-separated rows inside one bordered box. Nothing here is a functional loss — every prior affordance survives — but the visual variety that used to distinguish "this is a warning" from "this is a to-do" from "this is my creed" now rides on color/icon/position within one shared frame rather than a distinct box shape each.
- **The habit icon ladder is frontend-only.** There is no `icon` field anywhere in the habit data model (mock or backend) — the curated table in `logic/itemIcon.ts` is a lookup keyed on the 15 seeded `habitKey`s, and anything outside that set (a user-created or AI-suggested habit) falls to its `skillKey`'s shared icon rather than a distinct one. A follow-up (`mezo-zo1c`) tracks adding a real `icon` field to the data model plus a routine-editor icon picker.
- **Two prior render layers' CSS goes orphan-but-undeleted.** `MezoMessage.tsx`'s retirement leaves the entire `.brief-*` prose family (`.briefing-body`/`.brief-rest`/`.brief-refs*`/`.brief-foot`/`.brief-meta`) with zero consumers on Today (stacking on top of the pre-existing `.brief-bubble`/`.brief-clamp`/`.brief-more` orphan from `BriefingCard`'s retirement two layers back); `IntentionBanner`'s switch to `TodayList`/`.td-creed*` leaves `.creedchip*` with zero consumers too. Both families stay in `prototype.css` pending a dedicated sweep, consistent with this project's practice of not deleting CSS mid-feature on a hunch.
- **`.dayview` sheds its last `.isl-*` reuse.** ADR 0025's panel still borrowed several Fuel-owned `.isl-*` micro-components by compound selector (`.dayview .isl-facts`/`.isl-warnchip`/`.isl-cta`/`.isl-grouph`); this layer's self-contained `.td-stats`/`.td-foot`/`.td-cta`/`.td-sech` replace every one of them, so `.dayview` now carries zero `.isl-*` dependency. `.isl-*` remains exclusively Fuel's; `AnchorIsland.tsx` (the rough-day melt, unchanged by this branch) is Today's one remaining direct consumer of individual `.isl-*` rules.
- **Visual regression goldens — the darwin half regenerated, the linux half pending CI.** The 16-task implementation plan's first pass skipped the design spec's goldens step; a follow-up task (17) regenerated the six `today-{reggel,nap,este}-{light,dark}-darwin` Playwright snapshots and eyeballed all six against the new DOM. The linux baselines still need `update-visual-baselines.yml` to run — they are not produced locally. Tracked as `mezo-vhsg` (narrowed to the linux half).
- **No backend/API/data-model change; no new data source.** Purely a frontend re-composition over the unchanged day model, exactly as the three render layers before it.

## Alternatives considered

Three shapes for the companion's voice were mocked in-browser (`assets/2026-08-11-today-message-variants-mockup.html`) before this decision:

- **(a) An in-place-opening bubble** (the chip/summary stays on the page and expands inline into the full text on tap — no sheet). Rejected: an inline expansion still pushes the selected daypart's own content down every time it opens, and a growing message thread (more than one generated message on a day) has nowhere natural to live once it outgrows one bubble — a sheet scales to N messages, an inline expand does not.
- **(b) A daypart-filtered bubble** (only that daypart's own message shows — the briefing only on Reggel, nothing on Nap/Este). Rejected: the morning briefing is the day's one generated narrative; hiding it on Nap/Este leaves a user who opens the app after breakfast with no briefing at all, and there is no natural "evening briefing" content to fill that gap.
- **(c) Promote `TodayRow`/`TodayList` straight into `shared/ui` and migrate Fuel/Me onto them in the same change.** Rejected on scope: migrating `WindowIsland.tsx` and `RoutineEditorPage.tsx` onto a brand-new row idiom in the same branch that also rewrote Today's entire page risked exactly the kind of cross-feature visual regression this screen's own history (ADR 0022 → 0025 → this) has been trying to avoid repeating a fourth time. Ship Today-local first, prove the idiom, unify later (`mezo-jaoy`).
