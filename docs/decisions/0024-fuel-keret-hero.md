# ADR 0024 — Fuel Mai's Keret-öv becomes a Keret-hero: top-of-page kcal/macro readout, AI-score re-entry, a rost ring

- **Status:** accepted (2026-08-09)
- **Driving bd:** `mezo-c9t5`
- **Spec:** [`docs/superpowers/specs/2026-08-09-fuel-keret-hero-design.md`](../superpowers/specs/2026-08-09-fuel-keret-hero-design.md) (+ the validated mockup [`assets/2026-08-09-fuel-keret-hero-mockup.html`](../superpowers/specs/assets/2026-08-09-fuel-keret-hero-mockup.html))
- **Precedent:** [ADR 0023](0023-fuel-window-river.md) — the window-river sky this ADR iterates on, one day later, off direct user feedback on the shipped `KeretBelt`.

## Context

ADR 0023 shipped Fuel's Mai as a non-scrolling sky of window-islands with an always-visible daily-budget **belt** (`KeretBelt`) riding the shared `Island` shell in its `belt` variant, tucked in the river right after the NOW-island. The morning after it shipped, the user's own read of it (the driving signal for this ADR, worked through a **v1→v4 mockup iteration** with the user rather than a written brief) was that the budget readout — the single most-glanced-at number on the page — was buried mid-river instead of being reachable "any time, one glance", and that tapping a thin 54px bar to expand a whole second card felt like a detour rather than a hero moment. The same session surfaced a second, independent gap: ADR 0023 had **deliberately left a real feature dark** — the AI meal-score surface (`MealScoreChip`/`MealScoreSheet`/`useMealCoach`, all backend-scored since Fuel P7) rode only on the retired `ZoneSlotRow` and had no opening path anywhere in the app once window-islands shipped (tracked as `mezo-cs8b`, filed as ADR 0023's own follow-up).

## Decision

1. **The Keret-öv retires; a `KeretHero` takes the top of the page**, above the sky, between `AppHero` and `.sky-islands` — a halo-sage band with no card frame (visually closer to the retired pre-window-river `DayBudgetCard` than to a belt), not an `Island` at all. Anatomy top→bottom (`components/KeretHero.tsx`): a 46px Geist-200 remaining-kcal number with a **2s ease-out count-up** on load (`prefers-reduced-motion` → instant final value — a local rAF fork of `shared/ui/CountUp`'s hook, HU-grouped display needs the raw intermediate value CountUp itself doesn't expose), an "eddig X / Y · n/m ablak" of-line (no percent), a segmented day-bar (logged-window segments + a gold now-marker), three signed energy chips (unchanged `EnergyBreakdownSheet` wiring), and **five macro/rost/víz progress rings** (`RingBody` inside `KeretHero.tsx` — Fehérje/Szénhidrát/Zsír/Rost/Víz, SVG `stroke-dashoffset` fill that sweeps in lockstep with the count-up). `logic/keretHero.ts`'s pure `buildKeretHero()` is the VM: ring percents, day-bar segments, the now-marker fraction, and the signed energy chips, all table-tested independent of React.
2. **The víz ring is a real `button`** (not a passive ring like the other four) — tapping it opens `sheets/WaterLogSheet.tsx` (250/400/500 ml chips + a manual ml input, "kézi input felülírja" the chip selection, `Mentés` calls the caller-supplied `onLog` then dismisses) riding the shared `Sheet` primitive; the opener (`FuelMaiPage`) owns `useWaterActions().logWater` — `WaterLogSheet` itself carries no `@/data/*` import.
3. **AI-score re-entry, resolving `mezo-cs8b`.** The day's DONE meal windows no longer get their own per-window island or belt-summary line — they merge into **one expandable `DoneWindowsCapsule`** (`components/DoneWindowsCapsule.tsx`), sitting first in the sky (chronologically earliest, independent of the `?w=` selection mechanism, never "big"): a closed summary line (`"✓ {n} kész ablak · {kcal} kcal · AI-átlag {avg} p"`, the avg segment omitted when no done meal carries a score) that expands into one row per done meal — name + a **MealRole tag** (EDZÉS ELŐTTI/EDZÉS UTÁNI/STANDARD) + time/kcal/protein + a **✨ score-chip** (present only when the meal actually carries a score, never fabricated) — and tapping a scored row reopens the existing `MealScoreSheet` **unchanged** (ScoreHero, Mezo-olvasat, weighted dimensions, tool-chips — the sheet itself was never touched, only its opening path). Since no field anywhere on the FE (`FuelMeal`, `FuelSlot`, nor the `MealResponse` wire contract) carries a `MealRole`, the role is a **frontend-only derivation** — `logic/keretHero.ts`'s `deriveMealRole(mealTimeHHmm, workoutTime)`: `'pre'` when the meal lands 0–90 min before the day's own workout start, `'post'` when 0–120 min after (the boundary tie at diff 0 resolves to `'post'`, a meal logged exactly at kickoff reads as "after the whistle"), else `'standard'`; no workout today → always `'standard'`. `workoutTime` is the same `blocks.find(b => b.kind === 'gym')?.time` signal the window subtitles already used — no second source. A row's `clickable` mirrors `MealScoreSheet`'s own `if (!meal.breakdown) return null` guard, so a breakdown-less done meal is inert copy, never a dead tap.
4. **A rost ring (frontend-only extension).** Consumed rost = Σ `fiberG` across the day's logged meals (`FuelMeal.fiberG`, additive on the existing type — a meal with no `fiberG` contributes `0`, never fabricated); target = a **static `FIBER_TARGET_G = 30`** constant (`data/fuel/fuelConfig.ts`) — no settings field yet (filed as scope-out in the spec, §4). Mock and real mode run the identical derivation; **real-mode meals carry no `fiberG` today** (`mealApi.ts`'s `fromResponse` doesn't map it — the backend `meal`/`meal_item` wire contract has no fiber column yet), so a real-mode day's Rost ring is honestly `0%` rather than silently omitted — the target is known even when the number isn't yet backend-sourced. The mock seed (`data/fuel/fuel.ts`) got `fiberG: 8`/`fiberG: 6` added to its two meals so the ring shows non-zero in mock mode/goldens.
5. **`FuelSettingsSheet`'s entry point moves off the retired belt onto `FuelSection`'s `SubNavDropdown` `extraAction`** — the exact `MeSection.tsx` precedent (a ⚙️ "Fuel-beállítások" row in the Fuel sub-nav dropdown, `FuelSection.tsx`), settings state (`settingsOpen`) hoisted from `FuelMaiPage` up to `FuelSection`. `KeretHero` itself carries no settings entry, per spec §1.2 — the kitchen-close/caffeine-cutoff note that used to live in the belt's footer isn't relocated at all (see Consequences).
6. **`Island`'s `belt`/`beltContent` props and the `'keret'` `IslandTone` value are retired along with `KeretBelt`** — `KeretBelt.tsx` was their only consumer (grep-verified: after this branch, zero references outside comments and its own now-deleted test), so the shared shell sheds the belt variant entirely rather than carrying dead optionality. `WindowIsland`'s `doneSummary` prop (a leftover ADR-0023-era "✓ N ablak kész ma" line meant for the now-island, superseded by `DoneWindowsCapsule` before it was ever wired to a real value — `FuelMaiPage` was passing it `null` unconditionally) is retired the same way.

## Consequences

- **Retired outright, component + test + CSS:** `KeretBelt.tsx` + `KeretBelt.test.tsx` (zero consumers besides its own test, grep-proved); `Island`'s `belt: boolean` / `beltContent: ReactNode` props + the `WindowIsland`/`FuelMaiPage` `doneSummary` plumbing; the `.kbelt*` CSS family (`.kbelt-kv/-v/-vu/-l/-bars/-bar/-bar-track/-bar-t/-stackbar/-eaten/-left/-stackcap/-bd/-bdrow/-ic/-bdlabel/-val/-bdsep/-bdrow-total/-macrofull/-mf*`), `.isl.isl-belt`/`.isl.isl-big.isl-belt`/`:where(.isl.isl-belt)`, the `.isl[data-tone="keret"]` blob tint + its two nested override rules. `Island.test.tsx`'s three belt-specific cases and `WindowIsland.test.tsx`'s `doneSummary` case go with them.
- **New CSS families, Fuel-scoped, riding `prototype.css` directly (not `shared/ui`):** `.khero*` (`KeretHero.tsx`'s hero band — number/of-line/day-bar/chips/rings) and `.kdone*` (`DoneWindowsCapsule.tsx`'s merged done-capsule — it rides the shared `.isl` shell for chrome via a bare `.isl.kdone` class but overrides the shell's fixed-height belt/big sizing with content-driven height, since this capsule is never "big"/selected and carries no `data-tone`, deliberately, so a page-level `.isl[data-tone="fuel"]` query for "the window islands" can't accidentally match it).
- **`windowIslands.ts` gained a `doneGroup` output field** (`{ count, kcal, avgScore } | null`, `null` when nothing is done yet — no fabricated empty capsule) and an additive `meals: FuelMeal[]` input, replacing the old always-null `doneSummary` placeholder; **islands now exclude done windows entirely** (`buildWindowRiver` filters `state !== 'done'` before building the `islands` array). `defaultKey` changed from `nowKey ?? 'keret'` to `nowKey ?? islands[0]?.key ?? null` — there is no more belt to fall back onto when every window is done, so the sky can now legitimately render nothing big (only the done capsule).
- **`?w=keret` is a dead key now, handled the same way any other unrecognized `?w=` value always was** — silently falls back to `defaultKey` (`FuelMaiPage`'s existing `validKeys.has(raw)` guard needed no new special-case; the `'keret'` value simply stopped being a member of `validKeys` once the belt stopped contributing an island).
- **Accepted trade — stack-dose still has no surface on a done window.** ADR 0023 already flagged that a done zone's still-pending stack dose is unreachable once done windows merge into a capsule with no dose slot; this ADR doesn't change that. On reflection this is closer to correct than it first looked: a stack dose tied to a meal window is by nature a **pre-log reminder** ("take this with/before this meal") — once the window is logged done, the moment the reminder existed for has passed, and the dose still belongs on `/fuel/stack`'s own timeline (where `onStackDose` already deep-links every open window's doses). Left as-is rather than re-opened as a follow-up.
- **Two Task-3 review findings closed in the same change as this ADR:** `FuelMaiPage.test.tsx`'s water-log test now asserts the víz ring's own aria-label (which encodes current/target liters) actually **changed** after a chip-log, not merely that the sheet closed; the dead `doneSummary` prop (§6 above) is gone from `WindowIsland`, its test, and its `FuelMaiPage` pass-through.
- **No backend/API change** — every addition here (rost sum, MealRole derivation, done-capsule merge) is a frontend view-model layered on data `useFuelTimeline`/`useFuelDay` already compose; `mezo-cs8b` closes as a pure re-wiring of an already-real, already-backend-scored surface (`MealScoreSheet`/`useMealCoach`) onto a new opening path, not new scoring work.
- **Scope-out, unchanged from the spec:** a settings-editable rost target (still the static `FIBER_TARGET_G`); the kitchen-close/caffeine-cutoff note (not re-homed onto the hero — spec §1.2, "a hero nem hordozza"). Of the two, only the **caffeine cutoff** is actually user-visible today, editable in `FuelSettingsSheet`; the **kitchen-close note has no surface anywhere in the app** — an honest accepted gap of this iteration, not merely "moved off the hero". The central `+` FAB stays the only ad-hoc/no-plan log entry (the belt's own "＋ Log bármikor" row is not replaced, its job was already redundant with the FAB).
