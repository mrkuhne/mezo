# ADR 0033 — Mozaik 2.0: a washed tile mosaic with clay 3D icons replaces the Today iOS list language, app-wide

- **Status:** accepted (2026-08-29)
- **Driving bd:** `mezo-d20` (epic; foundation `mezo-d20.1.2`–`mezo-d20.1.5`)
- **Spec:** [`docs/superpowers/specs/2026-08-27-design-2.0-implementation-spec.md`](../superpowers/specs/2026-08-27-design-2.0-implementation-spec.md) §1 (fidelity rule) and §3 (canonical patterns), over the nine validated prototypes in [`docs/design_2.0/prototypes/`](../design_2.0/prototypes/)
- **Companion ADR:** [ADR 0032](0032-five-tab-ia-dissolved-section-shells.md) decides the map; this one decides the surface.
- **Supersedes:** [ADR 0026](0026-today-ios-list-language.md) — the `.td-*` inset-grouped-list idiom, the 16px-rail alignment rule, `TodayRow`/`TodayList`/`TodayStats`, the `MezoChip`, and the `rowAccessory` derivation. ADR 0026's *substance* survives untouched: the day model, act-anywhere, dedup ([ADR 0014](0014-today-daypart-faces.md)) and "nothing self-completes" ([ADR 0010](0010-gamified-growth-xp-feedback-not-payment.md)) all still hold. This is the **fifth** render layer over the same foundation, and the first one that is not confined to a single screen.

## Context

ADR 0026 solved Today's five-competing-idioms problem by collapsing that screen onto one box language — and explicitly scoped itself to that screen, leaving Fuel and Me on the older `ItemRow`/`.itemrow*` card language and accepting "two row languages now coexist in the app" as a named, tracked cost (`mezo-jaoy`).

A year of features later, the cost had compounded rather than resolved. The app spoke the iOS-list idiom on one screen, the card idiom on several, and a scattering of per-feature micro-languages (`.isl-*`, `.segtabs`, section dropdowns) elsewhere. Three further facts forced the decision:

1. **Emoji were carrying real semantic weight.** Habit rows, source markers, quest and check-in indicators, and the daypart switcher were all keyed on emoji — glyphs whose rendering the app does not control, whose weight and colour vary by platform, and which cannot be tinted to a domain palette. `logic/itemIcon.ts`'s three-rung ladder existed precisely because there was no real icon field anywhere in the model.
2. **A list is the wrong shape for glanceable state.** The product's dominant read is "how am I doing right now, across five domains" — a scan, not a sequence. A vertical list of equal-weight rows makes every datum cost the same eye-movement, which is why every screen kept growing hero/stat/chip exceptions on top of its list.
3. **Daniel built and validated nine full-fidelity HTML prototypes** ([`docs/design_2.0/prototypes/`](../design_2.0/prototypes/)) before any code was written, and set an explicit **1:1 fidelity requirement**: colours, gradient stops, sizes, shadows and motion timings are to be copied verbatim from the prototype CSS, not approximated. Deviations are allowed only where real data or a contract demands one, and must be flagged in the PR.

## Decision

**One visual language for the whole app: a two-column mosaic of washed tiles carrying clay 3D icons, with a one-shot entrance choreography and then calm.** It is implemented once, as shared primitives, and every tab uses it.

1. **Tile anatomy is fixed: eyebrow + clay spot + exactly one datum.** Detail belongs to the page the tile opens, never to the tile. A tile that wants a second number is a page.
2. **Shared primitives, not per-feature CSS** — `frontend/src/shared/ui/mozaik/`: `Tile`, `Mosaic`, `StatStrip`/`StatCell`, `MCells`, and the page scaffold `MozaikPage` / `PageHead` / `PageHero` / `PageBody` / `CollapsibleStrip`. A feature composes these; it does not re-cut its own tile.
3. **Clay 3D SVG icons replace emoji everywhere** — `frontend/src/shared/ui/clay/`. The sprite sheets (`clay-icons.svg`, `clay-spots.svg`) are copied **verbatim** from `docs/design_2.0/assets/`, injected once as a hidden sprite (`ClaySprites`) and referenced by `<use href="#name">` (`ClayIcon`, `ClaySpot`). `frontend/scripts/sync-clay-assets.sh` re-syncs from the design source of truth, which stays authoritative — the React side is a copy, never a fork. **The PWA app icon is the same clay orb**, so the thing on the home screen and the thing in the header are one mark.
4. **Domain colour rides on wash tokens, not on ad-hoc values.** The `--mz-*` custom-property family in `frontend/src/styles/prototype.css` carries the washes (`--mz-wash-*`), tones (`--mz-tone-*`), tinted shadows (`--mz-shadow-*`) and mini-cell palettes (`--mz-cell-*-bg`/`-ink`), declared in **both** the light and dark `:root` blocks. `mozaikCssTokens.test.ts` fails the build if a token exists in one theme and not the other.
5. **Motion is a one-shot entrance, then stillness** — `mozaik/motion.tsx`. `EntranceGroup` arms a `.mz-play` class once per mount so `.rise` children stagger in (60–80ms via a `--d` per-child delay) and then stop; it replays only on an explicit `replayKey` change (a daypart switch, for instance). `useCountUp` animates hero numbers with an ease-out quad at ~30fps. **Every infinite animation is reduced-motion guarded**, and `useCountUp` reads the media query itself and jumps straight to the target.
6. **Prototype px values scale by ×1.18.** The prototype phone frame is 330px wide; the real viewport is ~390px. Geometry and proportion are preserved; the foundation primitives fix the scaled values once and pages consume them, rather than each page re-deriving the multiplication.
7. **The guardrails from the handoff outrank aesthetics** and are unchanged by this ADR: never red (terracotta is the maximum); honest states (a missing source renders **nothing** — no placeholder theatre — while a null statistic inside a stat cell renders `—`); XP is feedback, not payment; the companion speaks in first-person plural; Hungarian labels are verbatim from the glossary; 44pt touch targets and ≥16px body text.

## Consequences

- **The two-row-language divergence ADR 0026 accepted is closed.** `mezo-jaoy` is resolved not by migrating one idiom onto the other but by both being replaced. `ItemRow`'s remaining consumers were rewritten or deleted during F1–F5.
- **`prototype.css` became a single high-traffic shared file, and that is now the project's most reliable source of merge damage.** A union merge silently swallowed the closing brace of an `@media (prefers-reduced-motion: reduce)` block **four separate times**, and once terminated a comment early via a `*/`-forming sequence inside its own body — surfacing as a Tailwind `Unterminated string` error that vitest did not catch. `frontend/src/shared/ui/mozaik/prototypeCssStructure.test.ts` now asserts balanced braces, absence of conflict markers, and properly-terminated comments, naming the offending line. Treat that guard as load-bearing.
- **Icons are now a build-time asset with a sync script, not a string in a `.ts` table.** Adding an icon means adding a symbol to the design sprite and re-running the sync — a heavier step than typing an emoji, and deliberately so: it keeps the set curated and the source of truth in one place. The old `itemIcon.ts` emoji ladder and its `LifeSkillKey` fallback are gone.
- **Fidelity is a review criterion, not a preference.** Because the prototypes are the specification, "close enough" is a defect. A deviation is legitimate only when real data or a contract requires it, and it must be stated in the PR that introduces it.
- **Entrance choreography must be armed, and a page that forgets is silently static.** `.rise` alone does nothing without an `EntranceGroup` ancestor. This is the intended failure direction (a missing animation, never a permanently-animating page), but it does mean "the animation is missing" is a real and easy bug class — worth checking on every new page.
- **No backend, contract or data-model change.** Every surface reads the same hooks in the same dual mock/real mode; this ADR is entirely a view-layer decision.

## Alternatives considered

- **Keep the iOS list language and extend it app-wide** (ADR 0026's implied endgame, tracked as `mezo-jaoy`). Rejected on the product's actual read pattern: a list optimises sequential reading, and the dominant task is a cross-domain glance. Every screen that adopted the list had already grown hero/stat/chip exceptions above it, which is the design telling you the container is wrong.
- **Adopt a third-party design system / component library.** Rejected: the product's identity is the warm clay-and-cream palette and the hand-built prototypes; a library would have been fought at every screen, and the app is a single-developer PWA with no need for the governance a DS buys.
- **Render the clay icons as PNG/WebP sprites** rather than inline SVG symbols. Rejected: the icons must tint with the theme and stay crisp at every density, and an inline symbol sheet costs one parse for the whole set while a raster set costs a request per density bucket.
- **Ship the mosaic on the Nap tab first and migrate the other four later**, mirroring ADR 0026's deliberately-narrow scope. Rejected explicitly, on the evidence of ADR 0026 itself: the narrow scope is what produced the multi-year divergence this ADR exists to end. The foundation (shell, clay, primitives, motion, tokens) therefore landed **before** any page work, so the five tabs could not diverge again.
