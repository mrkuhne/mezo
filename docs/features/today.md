# Today — Feature Documentation

> The daily home screen, now the **Nap** tab at route `/nap` (`/today/*` redirects), the PWA's default landing page. **Status: 🟢/🔶 mixed** — every surface is real in real mode or an explicit honest state, the briefing prose is real when generated (proactive B1.2, `mezo-h4wp.2`). Since the **Design 2.0 redesign** (`mezo-d20`, 2026-08-27–29) the screen speaks **Mozaik 2.0** — a Huawei-Health-inspired tile mosaic: the app shell's single header (`AppHeader`, mounted by `AppLayout` on every chrome-bearing route — section (clay spot + name) · daypart switch · Mezo-messages circle · notification bell · orb avatar; unified across all five hubs, `mezo-atry`, sticky with an aurora background since `mezo-8az6`) sits above **one long hero tile per daypart panel**, then a **two-column mosaic** of tiles, each tile navigating to a **full-page sibling** under `/nap/*`. The old iOS inset-grouped list (`TodayList`/`TodayRow`), the daypart segmented control, the standing `MezoChip`/`DailyQuestsChip`/`NeedsRow`, `AppHero`, and the whole `TodayPage` composition root are **deleted** (F8 cleanup, `mezo-d20.9.1`). This is the **fifth** render layer over the same day model: it replaced the iOS list language ([ADR 0026](../decisions/0026-today-ios-list-language.md), `mezo-e26w`), which replaced the daypart-tabs page ([ADR 0025](../decisions/0025-today-daypart-tabs.md)), which replaced the sky of three islands ([ADR 0022](../decisions/0022-today-three-islands.md)), which replaced the daypart-faces stack ([ADR 0014](../decisions/0014-today-daypart-faces.md)) — **the day model underneath is unchanged across all five.** `dayFace.ts`, `todayItems.ts`, `questAction.ts`, `habitAction.ts`, `windDown.ts`, `needs.ts`, `mezoMessages.ts` carry the same behaviour they did four layers ago; only the view swapped. Driving decisions: **[ADR 0032 — five-tab IA, dissolved section shells](../decisions/0032-five-tab-ia-dissolved-section-shells.md)** (the route + navigation shape) and **[ADR 0033 — Mozaik 2.0 tile language](../decisions/0033-mozaik-2-tile-language.md)** (the visual language; **supersedes ADR 0026**), over [`specs/2026-08-27-design-2.0-implementation-spec.md`](../superpowers/specs/2026-08-27-design-2.0-implementation-spec.md).

## 1. Summary

**Nap** (formerly "Ma") is mezo's daily aggregation surface. Since `mezo-d20.2.x` it is not one long page but a **hub + five full-page siblings**, all under `frontend/src/features/today/pages/`:

| Route | Page | What it is |
|---|---|---|
| `/nap` | **`NapHubPage`** | the hub: one hero per daypart + the tile mosaic (the header above it is the shell's `AppHeader`, not the hub's — see below) |
| `/nap/uzenetek` | `NapMezoPage` | "Mezo · ma" — the day's companion thread as a page |
| `/nap/rutin` | `NapRutinPage` | the habit chains (`?dp=reggel\|este` preselects which group leads) |
| `/nap/kuldetesek` | `NapKuldetesekPage` | the day's quests as cards, with `Csere` |
| `/nap/checkin` | `NapCheckinPage` | the four check-in slots as a day overview |
| `/nap/eletjel` | `EletjelPage` | the six Életjel rings, each ring its own tile |

### The header is the shell's, not the hub's

Until `mezo-atry`, `NapHubPage`'s `.nap-head` was copy-pasted verbatim into the Edzés, Fuel, Mezo and Én hubs — five near-identical blocks with drifting content. It now lives once, as **`AppHeader`** (`frontend/src/app/AppHeader.tsx`), mounted by `AppLayout` as the first child inside `ScreenContent` on every route except the three chrome-free ones (`/train/session`, `/me/sleep/night`, `/ritual` — the same `hideChrome` flag that also gates `TabBar` and `QuickLogFab`). Since `mezo-8az6` the header **kitapad** (`position: sticky`, `top: 0` in the `.screen-content` scroller) instead of scrolling away with the page, and carries a napszak-követő aurora background (`HeaderAurora.tsx`) that fades to a translucent glass bar past a 14px scroll threshold (`useCondensedHeader`). `NapHubPage` itself renders no header at all any more. Six elements (the guide button only where the route has a guide), left to right:

1. **Kalauz „?"** — `.nap-roundbtn.nap-q`, rendered **only when the route has a registry entry** (`findKalauz(pathname)`, `frontend/src/features/tutorial/registry`), always the first button so the daypart switch's presence never shifts it. Opens the page's guide through `useTutorial().open(id)`; carries the `.nap-offnow` amber dot when the route is a T3 guide not yet seen. See [`tutorial.md`](tutorial.md).
2. **Szekció (clay spot + név)** — the mezo-8az6 replacement for the date eyebrow: the dátumot a telefon státuszsávja mutatja, a helyét az „épp melyik szekcióban vagyok" vette át (`app/headerSection.ts` — szekció-szintű, a path első szegmenséből, 115 route mellett tábla nélkül).
3. **Daypart switch** — a round clay button (`.nap-roundbtn`) carrying a daypart's clay icon (`i-hajnal` / `i-nap` / `i-alvas`). It reads `?dp=` **only on `/nap`**; on every other route it shows the real clock-derived daypart, since there is no page there to preselect a mosaic for. Tapping it opens the same three-icon `role="menu"` popover — its items are `role="menuitemradio"` with `aria-checked`, so the selection is exposed, not merely painted by the `.on` class (`mezo-atry` fix wave). Picking a daypart **always navigates to `/nap`**, carrying `?dp=` only when the pick differs from the clock-derived one (picking the clock's own daypart on `/nap` clears the param instead). The navigation **preserves every other query parameter** (`?day=`, `?medCycleDay=`, `?niggle=`, `?vulnerable=`, `?ritual=` — all app-wide scenario switches read by `useTodayScenario`) and uses `replace`, so daypart-tapping neither drops a scenario nor fills the history stack. The `?dp=`-or-clock resolution itself lives in **`logic/useDayFace.ts`**, shared verbatim with `NapHubPage`. The `.nap-offnow` dot — the ADR 0014 dual-signal ("hol tartok" vs "mit nézek") — appears **only on `/nap`**, and only when the shown daypart differs from the clock's.
4. **Mezo-messages circle** — a round button (`i-level` clay icon) with an unread-count `.nap-badge`, navigating to `/nap/uzenetek`. This is the tile that used to sit inside every daypart's mosaic (reggel/nap/este all carried a `Mezo` tile); `mezo-atry` moved it into the header instead, so it now appears exactly once per screen instead of once per daypart. The unread count is watermarked in `localStorage` (`lastSeenMessage`, key `mezo.msgseen.<date>`). **The badge and the page read ONE thread** — `MezoThreadProvider` (`frontend/src/features/today/MezoThreadProvider.tsx`), mounted by `AppLayout` around `ScreenContent`, is the single builder of `buildMezoMessages({ feed, demoBriefing, nudges })` and the single writer of the Életjel nudge log. This is not decoration: while the header built its own **nudge-less** thread and the page stamped the watermark with its own (nudge-bearing) last id, the header's `findIndex` could never match, so the badge fell back to the full count and **never cleared** (`mezo-atry` fix wave). The watermark is also React state in the provider, so the badge goes dark the moment the page marks the thread seen — not one navigation later.
5. **Notification bell** — a second round button with an unread-count `.nap-badge`, opening a `.nap-ntfmenu` dropdown with the three newest notifications (each row navigating to its `deeplink`) and an `Összes értesítés ›` foot → `/me/ertesitesek`, now the notification **feed page** (`NotificationFeedPage.tsx`), not the preferences page. Source: `useNotificationFeed()`. The former gap here — the badge had no reachable path that ever called `markAllRead`, so it could never clear (`mezo-61w0`) — is closed: opening the feed page fires `markAllRead()` once, which zeroes this badge too, since bell and feed read the same unread count. See [`_platform-notifications.md`](_platform-notifications.md) for the feed page itself.
6. **Day orb** — `.nap-avatar` rendering `DayOrb` (`frontend/src/shared/ui/DayOrb.tsx`), the bottom-filling variant of the `#s-orb` sprite, filled/tinted from `useDayOrbFill()` → `/me/week/napok/<today's ISO date>`. It is **not** a profile shortcut — that duplicated the bottom "Én" tab and was retired (`mezo-idz2`); this button is the header's daily status indicator instead, and its `aria-label` speaks the day's fill in words (e.g. "A mai napod · 3 a 6 jelből megvan"), not just in color.

**Popover + landmark contract** (`mezo-atry` fix wave, fixed once here instead of five times): the root is a real `<header>` element; both triggers carry `aria-haspopup="menu"`; either popover closes on **Escape**, on an **outside click**, on a pathname change, on re-tapping its trigger and on choosing an item; the bell menu's eyebrow line is `role="presentation"` (a bare `<span>` is not a valid `role="menu"` child) with the label moved onto the menu's `aria-label`. **Focus management is deliberately NOT here** — no focus trap, no roving tabindex; see §9.

**CSS:** the component still renders `className="nap-head app-head"` — it inherited the `.nap-head` flex row verbatim, plus a new `.app-head { padding-top: 6px; margin-bottom: 7px; }` rule that makes the gap under the header a uniform 13px on all five hubs (it used to be 13px on Nap alone and 11px on the other four, back when each hub hand-tuned its own copy).

### The three daypart panels

Everything below the header sits inside one `EntranceGroup replayKey={face}` — the one-shot entrance choreography (60–80 ms `--d` stagger, `.rise`), re-armed on a daypart switch and otherwise still.

- 🌅 **Reggel** — hero tile (`mz-w-lav`, `s-este` clay spot): **"Éjszakád"** = last night's duration via `fmtHours` + `minőség N/10`, with a sub-row carrying today's weight and the first intention focus. Mosaic: **Rutin** (morning chain) · **Küldetések** · **Check-in** · **Kreed** (the one tile that still opens a sheet, `IntentionSheet`) — the `Mezo` tile that used to open this mosaic moved into the shell header (§ above, `mezo-atry`).
- ☀️ **Nap** — hero tile (`mz-w-sage`): **"Keret · ma"** = remaining kcal as an animated `useCountUp` number + `fehérje x/y g`, over a `.daybar` of the day's meal slots (`done` filled, `now` highlighted, each bar staggered). Mosaic: the **`now` meal window** as the coral `most` tile → `/fuel` · **Edzés** (only when `today.workoutType` exists) → `/train` · **Életjel** (a hand-composed tile whose artwork is the six-arc conic ring, `needRingGradient(needs.states)`) → `/nap/eletjel` · **Víz** (logs `+2,5 dl` **in place**, no navigation) · **Stack** → `/fuel/stack` · **Küldetések** · **Check-in**.
- 🌙 **Este** — hero tile (`.nap-dusk`, `s-napzaras` spot): **"Villanyoltásig"** = a live `minsToBed` countdown formatted `h:mm` + the goal bed time, with the lavender **`Zárjuk le a napot`** CTA → `/ritual`. Mosaic: **Rutin** (evening chain) · **Küldetések** · **Check-in**.

**Tile anatomy is fixed** (ADR 0033): eyebrow + clay spot + **one** datum. Detail is the destination page's job, never the tile's. The `Tile` primitive derives its own accessible name from the eyebrow unless an explicit `aria-label` overrides it, and every tile with an `onClick` renders as a `<button>`.

**Clay, not emoji.** Every icon on this screen is an SVG `<use>` into the sprite sheets mounted once by `ClaySprites` in `AppLayout` (`shared/ui/clay/`, sprites copied verbatim from `docs/design_2.0/assets/`). The emoji ladder `logic/itemIcon.ts` built for the list era (`habitKey → skillKey → daypart`) is **still in the tree and still tested but has no renderer** (§9).

Status per layer: **FE mock ✅** (deterministic; the mock sleep goal wake 06:45 / bed 23:15 still pins the daypart windows), **FE real ✅** (composition over existing reads — no new backend), **Backend ✅ check-in only** (unchanged: the redesign was frontend-only, no API-contract change).

## 2. User-facing behavior

- **Open the app →** lands on `/nap` (`router.tsx`'s index `Navigate`); mock renders synchronously. A bookmarked `/today`, `/today?dp=este`, `/today/anything` lands on `/nap` with its query string intact — `LegacyPathRedirect` does a `pathname.replace(prefix, to) + search`, `replace`d so the back button doesn't bounce.
- **Fixed chrome** is now the app shell's, not the page's: the single **`AppHeader`**, the 5-tab `TabBar` (Nap · Edzés · Fuel · Mezo · Én) and the floating coral **quick-log FAB**, all mounted by `AppLayout` and all hidden on the three chrome-free full-screen flows (`/train/session`, `/me/sleep/night`, `/ritual`).
- **Selecting a daypart** is a shell-header action, reachable from any tab. Tapping the round switch opens the three-icon menu; picking one always navigates to `/nap`, and if the pick differs from the clock's current daypart it carries `?dp=` (picking `/nap`'s current daypart from `/nap` itself just clears the param, `{replace:true}`). Once on `/nap`, `?dp=reggel|nap|este` re-keys the `EntranceGroup` so the new panel's tiles stagger in once; unknown/empty falls back to the clock's daypart. This parse is verbatim inherited from the old hub-only switch — only its consumer (the shell, not the hub) and its always-navigate-to-`/nap` behavior changed.
- **The now-daypart is live.** `useMinuteTick()` (a `Date` that re-renders once a minute) feeds `dayFace(tick, sleepGoal)`, so a session left open crosses a daypart boundary on its own; the same tick drives `useNeeds` and the evening countdown.
- **Everything is act-anywhere** — a tile is actionable while its daypart is merely *selected*, not current. Unchanged since ADR 0014.
- **Tile → own page.** The Mozaik navigation contract (ADR 0032): a tile pushes a full-page sibling that slides in from the right, carries a colored hero zone (clay spot + big number + name), a `‹ vissza` / `‹ Ma` back chip, its content in cards, and a quiet principle line at the bottom. There is **no nested shell and no sub-nav dropdown** — the page is a route, not a panel.
- **In-place logging is the deliberate exception.** Two tiles do not navigate: **Víz** logs `+2,5 dl` straight into `useWaterActions(date)` and the counter moves on the tile, and **Kreed** opens `IntentionSheet`. Everything else is a route.
- **Mezo üzenetei** (`/nap/uzenetek`) — the day's whole companion thread as a page: a breathing-orb hero, one block per message (daypart clay spot + `HH:mm · eyebrow` + `SafeMarkdown` prose + `RefTag` refs + meta), never truncated, and a `Beszélgess Mezóval ›` CTA → `/mezo/chat`. The thread logic is the retired sheet's, verbatim: `buildMezoMessages({ feed, demoBriefing })` over `useCompanionFeed()`, with `resolveBriefing(scenario.dayState)` prepended as an honestly-labelled `Demo tartalom` card only while the feed carries no `morning` kind. **Rating a message** is unchanged: a 👍/👎 `FeedbackChips` row renders **only** on a bubble with an `artifactId` (a persisted `companion_message` row) — the demo card never gets chips (`mezo-kr9v`, §9). **The thread splits into two tabs** (`mezo-ho9k`): a `role="tablist"` segmented control (`.nap-mzseg`, the `mem-seg` pill idiom) right under the hero reads `Üzenetek | Életjelek` and drives a `?tab=eletjelek` query param (`Üzenetek` is the default — no param, `{replace:true}`); the partition itself does not reshuffle or refetch the thread, it is a pure display split of the **same** list (`partitionMezoThread(messages)`) into companion messages vs. Életjel nudges. **Üzenetek** shows only its newest card expanded as a full bubble; every earlier one collapses into a one-line `.nap-mzrow` button (eyebrow + first paragraph preview + `▾`) that expands in place on tap — expansion is one-way, there is no re-collapse (YAGNI, matching the approved prototype). **Életjelek** opens with the `EletjelStrip` (six mini-ring cells, one tap → `/nap/eletjel`) followed by any Életjel nudge cards, or the honest line `"Minden gyűrű rendben — ma nincs teendő. ✓"` when there are none. **Unread dots** (`.nap-mzdot`) come from a mount-time snapshot, not a live count: on first render with a non-empty thread, the last `unread` messages are partitioned once into `{ uzenetek, eletjelek }` booleans and frozen in state; visiting a tab clears only that tab's dot, session-locally (§9 — the snapshot effect's declaration order relative to `markSeen()` matters). **The intervention-push deeplink (`?n=`) always forces the Üzenetek tab**, overriding even an explicit `?tab=eletjelek` — a deeplink target is always a companion message or the b3pp.36 intervention card, never a nudge, so it can only exist in that pane — and the linked/target row renders already expanded regardless of its position in the (now-partitioned) list.
- **Intervention-push deeplink** (`?n=<full uuid>&d=<card's own day>`, `mezo-b3pp.36`) — this is the page an `intervention`-kind push actually lands on ([`_platform-notifications.md` §3d](_platform-notifications.md) for the backend history: three defects — wrong route, no consumer, a truncated id — plus the cross-midnight date gap the push's card can carry). `NapMezoPage` reads `n`/`d` via `useSearchParams`. **The common case is same-day** (`d` names local-today): the linked row is already inside today's own thread, so nothing is fetched or prepended — the page just scrolls/highlights that existing row (matched by `n` against the thread's own `artifactId`s). Only when `d` names a day other than local-today (a card deferred across midnight, generated late and pushed the next morning) does it call `useCompanionFeed(d, { enabled })` — a second, per-date cache entry, fetched only when there is an `n` to look up (a bare `d=` with no `n` fetches nothing, and a past day's feed never polls — it cannot change) — finds the one `FeedMessage` matching `n`, and prepends it to the page's own `displayMessages` (rendered *alongside* today's thread, never replacing it, and never joining the shell's shared unread-watermark list; the hero's `N üzenet` count is `messages.length`, not `displayMessages.length`, so a cross-day deeplink doesn't inflate it). Either way the target row gets the identical `FeedbackChips` wiring as any other persisted row and is `scrollIntoView({block:'center'})`'d on mount, keyed on a stable id string (not asserted under jsdom — no real layout to scroll, but the effect's own single-fire behavior is asserted via a `scrollIntoView` spy). A stale or unknown id degrades silently: no extra card renders, nothing throws.
- **Napi küldetések** (`/nap/kuldetesek`) — quest cards with the slot's clay icon, title, why, an `+N XP` pill, a quiet state line and up to two buttons: the context-aware smart action (`+250 ml`, `Check-in`, `Naplózz`, or navigation) and `Csere · N maradt` while the reroll budget lasts. ADR 0010's tone is enforced in copy: an offered quest reads *"folyamatban · a logjaidból záródik magától"* (or *"az edzésből záródik magától"* for `gym_session_done`); there is no failure state and no countdown. A check-in action is omitted when no slot is fillable, so the page never renders a dead control.
- **Rutin** (`/nap/rutin`) — the habit chains. `?dp=reggel|este` decides which chain group leads; the other follows below with its own group header. The hero group gets a `StatStrip`: `tökéletes N/30` · `lánc-erő N% · 28 nap` · `+N XP ma`. Tick semantics are the Today dispatcher's, verbatim: a MANUAL row checks/unchecks through `useHabitActions`, a DERIVED row opens its log surface via `logic/habitAction` (`LogFlowPage`, `SleepLogSheet`, `IntentionSheet`, `ReflectSheet`, or a nav), and a row whose action is `none` renders a **non-interactive** tick — nothing self-completes. `habitHint(h)` still replaces the anchor copy on a passive row, so `bed_on_time` and an out-of-window `wake_on_time` read as "this ticks by itself", not as broken. A successful check emits `buildHabitRewardToast` on the `toastBus` (level-up inline in the same card, never the full-screen overlay). See [habit.md](habit.md).
- **Check-in** (`/nap/checkin`) — the four canonical slots as rows in one card: a `done` slot carries its measured values as tinted `MCells` (Energia · Stressz · Testi · Mentális), the **next fillable** slot is the hot row with a `Kitöltöm` button that opens the real `CheckInSheet` measurement flow, and every other slot is muted with `később esedékes` and **no** values — the page is the day overview, the sheet stays the flow. Principle line: *"A kimaradt slot nem vész el — Pótold bármikor, a társ nem büntet."*
- **Életjel** (`/nap/eletjel`) — the six needs rings, promoted out of the old `NeedsRow`. Hero = the segmented six-arc ring (`needRingGradient`, the same gradient the hub tile paints) + the animated average `%`. Below it, six tiles: eyebrow + clay icon + a mini conic ring + the `%`, red/critical tinted with `.ej-warn`. Each tile dispatches **exactly** what the retired `onNeedCta` did — Étel → the unified `LogFlowPage`, Víz → an immediate `+2,5 dl`, Alvás → `SleepLogSheet`, Mozgás → `/train`, Kapcsolat → the next fillable check-in slot — and **Rend is deliberately non-interactive** (it has no log surface, the `NeedRingSheet` doctrine). **Honest state:** while `needs.isPending`, *nothing* numeric renders — no ring, no percentage, no `—` placeholder. Full model in **[needs.md](needs.md)**.
- **Scenario deep-links** (dev/demo affordances): `?dp=` and `?day=good|medium|rough` still work (`?day=` selects the demo-briefing variant that feeds the message thread). `?ritual=waiting|open|done` is still parsed and still consumed by the ritual surface. **`?niggle=`, `?vulnerable=` and the rough-day anchor melt no longer have a Today surface at all** — their renderers were deleted (§9).
- **Sleep duration is HOURS on the wire.** `SleepEntry.duration` is `7.5`, not `450` — the Reggel hero renders it through `fmtHours` (hours → minutes → `h:mm`), producing `7:30`. This bit the implementation (§9).

## 3. Architecture & data flow

The single FE↔data boundary stays `frontend/src/data/hooks.ts`; every hook is dual-mode. What changed is the **shape of the composition**: there is no longer one composition root holding every hook for the whole screen. **Each page holds its own hooks** — the hub holds the hooks its heroes and tiles need, and each sibling page re-reads the subset it renders. The pure logic modules are shared and unchanged.

### The logic modules (`frontend/src/features/today/logic/`)

- **`dayFace.ts`** — the day model, **UNCHANGED** since `mezo-ly8c`: three wrap-aware windows off `useSleepGoal()`'s wake/bed anchor (mock: 06:15–11:45 / 11:45–19:15 / 19:15–06:15), the degenerate-anchor guard, `dayFace`/`faceWindows`/`faceOf` + `DAY_FACES`/`FACE_LABEL`/`FACE_EMOJI`. Nobody calls `dayFace()` directly any more: the `?dp=`-or-clock resolution is **`useDayFace.ts`**'s (below). `FACE_ICON` — the clay-icon table — lives in `app/AppHeader.tsx`, the only surface that draws a daypart glyph, and it reads `FACE_LABEL` from here; `FACE_EMOJI` survives for callers that still want an emoji.
- **`useDayFace.ts`** — `useDayFace() → { face, nowFace }`, the ONE place the daypart is resolved (`mezo-atry` fix wave). `nowFace` is `dayFace(useMinuteTick(), sleepGoal)`; `face` is `?dp=` **only when the pathname is exactly `/nap`**, else `nowFace`. Read by `app/AppHeader.tsx` and `NapHubPage` — they had independent copies of the guard, the call and the rule, which is exactly how two surfaces come to disagree at a daypart boundary.
- **`useMinuteTick.ts`** — the 60 s ticker, a **single module-level clock** behind `useSyncExternalStore` (`mezo-atry` fix wave; it used to start a fresh `setInterval` per mount, so two live consumers could sit up to 60 s out of phase and derive different dayparts at the same instant). Every consumer gets the *same* `Date` instance, so memos over it are stable too. One interval runs while at least one subscriber is mounted. Read by `AppHeader` (via `useDayFace`), `NapHubPage`, `MezoThreadProvider` and `EletjelPage`.
- **`needs.ts` / `needsInputs.ts` / `useNeeds.ts`** — the Életjel decay/refill engine, the app-data adapter and the live composition hook. Documented in full in **[needs.md](needs.md)**; the pages only render `needs.states` and dispatch the CTAs.
- **`mezoMessages.ts`** — `buildMezoMessages({ feed, demoBriefing, nudges })`, the day's message thread. For the Nap thread it is called **exactly once**, by `features/today/MezoThreadProvider.tsx` (the shell provider): `NapMezoPage` renders that thread and `AppHeader` counts it. Called directly, on their own domain threads, by Fuel's `FuelMaiPage`/`FuelMezoPage` and the Mezo hub. `NapHubPage` does not read it at all.
- **`MezoThreadProvider.tsx`** (`features/today/`, not `logic/` — it holds React state) — the single Nap-thread instance: `useCompanionFeed` + the labelled demo briefing + the Életjel threshold nudges (`deriveNudges`/`toNudgeMessage`, the `markNudgeShown` log write), plus the read watermark as state (`unread`, `markSeen()`). Mounted by `AppLayout` around `ScreenContent`, so the header (an earlier sibling of the `Outlet`) and the page (under it) share one list and one watermark. **Cost, accepted knowingly:** it pulls `useNeeds` — and with it the ~15 reads the ring engine composes — into the shell, so they fire once per app session on any chrome-bearing route rather than only on `/nap`. That was judged cheaper than two threads that can drift, which is what produced the never-clearing badge.
- **`questAction.ts` / `habitAction.ts`** — the smart-action dispatch tables, **unchanged**. `questAction(quest)` returns `water` / `checkin` / `activity` / a nav target; `habitAction(h)` returns `check` / `nav` / `meal-sheet` / `sleep-sheet` / `intention-sheet` / `intention-reflect` / `none`, and `habitHint(h)` the passive-row explainer.

## 5. Integrations

Nap is an **aggregation surface** — its value is the seams. The seams survived the redesign; only where they surface moved.

- **→ Train** — *live shared data + navigation*. The Nap panel's Edzés tile renders `today.workoutType` (composed by `useToday` off `useTrain()`) and routes to `/train`. **The hub no longer renders the gym hero's done / in-progress / sport-done states** — `useToday` still carries `workoutDone`/`workoutDoneSets`/`workoutInProgress`/`workoutOpenSets`/`loggedSportKinds`, but the tile shows only the session's name; the full session state lives on the Edzés tab now (§9).

## 7. How to extend it

**Add a tile to a daypart panel** — write it inside that panel's `<Mosaic>` with the next `delayMs` in the 40 ms ladder, pick a `wash` from the domain palette, give it **one** datum on `line`, and point `onClick` at a route. If the tile needs a page, add the page under `features/today/pages/` as a `MozaikPage` with `PageHead` + a hero + `PageBody principle=…`, and register the route under `nap/…` in `router.tsx`. Do **not** build a nested shell or a sub-nav — ADR 0032 dissolved those on purpose.

**Add a whole new Nap sub-page** — copy `NapCheckinPage` as the smallest complete example: `MozaikPage tone` → `PageHead onBack` → `PageHero` → `PageBody principle` → `EntranceGroup` around `.rise` content. Hold your own hooks; do not thread data down from the hub.

**Add a new mezo-generated message source** — extend `logic/mezoMessages.ts`'s `buildMezoMessages` (or wire a new upstream hook into `NapMezoPage`). The hub tile only reads `messages.length`, so it needs no change. Test ordering/shape in `mezoMessages.test.ts`.

**Change the day model** — unchanged recipe: constants in `dayFace.ts` (`MORNING_LEAD_MIN` imported from `windDown.ts` on purpose); re-check `dayFace.test.ts` and regenerate the visual goldens.

**Add a clay icon or spot** — the sprites are copied verbatim from `docs/design_2.0/assets/`; add the symbol there first, re-copy, then widen `ClayIconName`/`ClaySpotName`. Never inline an emoji into a tile — the tile language is clay (ADR 0033).

**Promote a mock section to a real backend** — the check-in remains the working template (contract-first → backend package → Liquibase → ITs → dual-mode FE swap); see §4 and the references table in `CLAUDE.md`.

### The DayOrb tone axis — where its regression net actually lives (`mezo-x5va`, `mezo-tzid`)
The orb's **height** (how many of the day's signals are recorded) and its **tone** (colour saturation, from the 6-dimension daily evaluation) are guarded at four separate layers, each with a stricter instrument than the one below: `features/today/logic/dayOrbTone.test.ts` (the provisional day score — the `>= 2 DONE` gate excludes `rhythm`, the weighted sum includes it, and both are asserted separately), `dayOrbFill.test.ts` (score → intensity across the 45/92 floor/ceiling), `useDayOrbFill.test.tsx` (the evaluation response → intensity wiring, with `useDayEvaluation` mocked so it runs identically in both modes) and `shared/ui/DayOrb.test.tsx` (intensity → the **exact** `stop-color` hexes).

**The visual goldens do NOT cover the tone axis, and never will.** `mezo-x5va` rewrote how the orb's colour is derived and moved **zero pixels** on any baseline: the pale↔full shift stays under `pixelmatch`'s 0.2 per-pixel threshold. The hex assertions above are the strictly sharper instrument; do not reach for a screenshot to protect a colour here. The one gap the four layers left was the **composition** — an `AppHeader` that passed a constant instead of `dayOrb.intensity` would keep all four green — and `frontend/src/app/AppHeader.dayOrbTone.test.tsx` closes it by reading the rendered header's `.dayorb stop` colours for a strong, a weak and an absent evaluation. What a golden would still add, and only a golden, is CSS flattening the fill (a future `filter`/`opacity` on `.dayorb-fill`); that is deferred in `mezo-7vdm`, since it costs a test-only surface in the prod bundle.

1. **The wall clock is pinned.** `useMinuteTick` is mocked to a fixed `13:42`, because `setFace` *deletes* `?dp` when the clicked face is already the now-face — on a CI runner whose clock lands in the este band, a `dp=este` assertion would pass vacuously. This exact flake failed a real CI run.

## 9. Decisions, gotchas & deferred

- **Decisions:** the current structure is **[ADR 0032 — five-tab IA, dissolved section shells](../decisions/0032-five-tab-ia-dissolved-section-shells.md)** (5 first-class tabs, no center-FAB tab bar, no `SubNavDropdown`, tile → full-page sibling, the floating quick-log FAB) and **[ADR 0033 — Mozaik 2.0 tile language](../decisions/0033-mozaik-2-tile-language.md)** (tile mosaic, clay icons, the `--mz-*` token family, one-shot entrance choreography), over [`specs/2026-08-27-design-2.0-implementation-spec.md`](../superpowers/specs/2026-08-27-design-2.0-implementation-spec.md). **ADR 0033 supersedes [ADR 0026](../decisions/0026-today-ios-list-language.md)**, which had superseded the *render layer* of [ADR 0025](../decisions/0025-today-daypart-tabs.md), itself over [ADR 0022](../decisions/0022-today-three-islands.md) and [ADR 0014](../decisions/0014-today-daypart-faces.md). **ADR 0014's day model, act-anywhere and dedup decisions remain in force through all five render layers**, as do the honest-completion decisions ([`specs/2026-07-04-…`](../superpowers/specs/2026-07-04-today-honest-completion-design.md)) and **ADR 0010** (nothing self-completes — visible in `NapRutinPage`'s non-interactive tick and `NapKuldetesekPage`'s "záródik magától" copy).
- **The prior layer's central trade-off is now closed by deletion, not by unification.** ADR 0026 deliberately left `shared/ui/ItemRow` untouched, so the app spoke two row languages, and filed `mezo-jaoy` to unify them. The Design 2.0 cleanup deleted Today's whole `.td-*` row family instead: nothing under `features/today/` imports `ItemRow`/`ItemCard` any more. `ItemRow` survives for its other consumers (the Me routine editor, and wherever Fuel still uses it) — `mezo-jaoy` is therefore moot **for Today**, not resolved globally.
- **Accepted trades (this layer):** the always-visible list is gone — the day is a mosaic of tiles, so *every* detail is one tap away instead of on-screen. Concretely: individual habit rows, quest rows, fuel rows, the done-fold and the per-row `↗` link no longer exist on the hub; they live on `/nap/rutin`, `/nap/kuldetesek` and Fuel. The standing `AppHero` identity/XP chrome is gone from this screen (the orb avatar replaces it). The evening's four-phase content swap (normál / ráhangolódás / leállás / éjszaka) is **gone**: the Este panel is one hero + four tiles regardless of phase, with no dim/winddown/night variants (below).
- **GOTCHA — `SleepEntry.duration` is HOURS, not minutes.** The wire value `7.5` means seven and a half hours. `NapHubPage.fmtHours` converts (`hours × 60 → h:mm`) to print `7:30`; the sibling `fmtHm` takes **minutes** and is what `minsToBed` feeds. Mixing them up silently renders a plausible-looking wrong number (`7:30` vs `0:07`) — this bit the F1 implementation and is the reason both helpers carry doc comments.
- **RESOLVED — the dead sheet state this section used to flag is gone.** `NapHubPage` no longer declares `msgsOpen`/`questsOpen`/`checkInIdx`, and imports none of `MezoMessagesSheet`/`DailyQuestsSheet`/`CheckInSheet` — verified against the current file. **`focusOpen` (the Kreed tile → `IntentionSheet`) remains the one sheet the hub owns and genuinely opens.**

- **GOTCHA — the Üzenetek/Életjelek tab split's partition key is `MezoMessageItem.source === 'eletjel'`, not the "Életjel" eyebrow text.** `toNudgeMessage` (`needsNudges.ts`) is the one place that sets `source: 'eletjel'`; `partitionMezoThread` (`mezoMessages.ts`) reads that field, and `NapMezoPage` renders whichever tab a card's `source` puts it in. Relabelling or localizing the nudge eyebrow copy does nothing to which pane a card lands in — only `source` does; do not add a second, string-matching partition rule.
- **GOTCHA — `NapMezoPage`'s unread-dot snapshot is protected by its `dots !== null` one-shot guard, NOT by effect declaration order.** Both the snapshot effect and the `markSeen()` effect close over the SAME render's `unread` value — JS closures capture render-local bindings, and `markSeen()`'s call bumps the shared thread's watermark asynchronously, which only changes what `unread` equals on the *next* render, never retroactively inside the effects that already ran this render. So declaration order between the two effects is irrelevant to correctness: even the "wrong" order would freeze the identical pre-visit `unread` into `{ uzenetek, eletjelek }`. What actually makes the snapshot fire exactly once is the `dots !== null` early-return inside the snapshot effect itself — it is a one-shot guard against React's per-render effect re-run, not a defense against `markSeen()` racing ahead of it. Delete that guard (or otherwise let the effect run again after `dots` is set) and the "snapshot" would recompute every render against whatever `unread` currently is, which — once `markSeen()` has cleared it — would make the dots disappear on the very next re-render, not merely fail to appear at mount.
- **GOTCHA — `logic/dayArc.ts` still belongs to ritual's recap** (`DayStoryStep.tsx`). Do not delete it with anything Today-side. (Unchanged warning — the render layer has now swapped five times without this file moving.)
- **GOTCHA — `prototype.css` merges need a brace + comment check.** A union-merge cut the closing `}` off a `@media (prefers-reduced-motion)` block four times during the redesign, and once terminated a comment early on an inline `*/`; the second failed only at `pnpm build`, which vitest does not run. Never resolve a `.tsx` conflict by union (duplicated imports/JSX); CSS union is fine but must be brace-verified. And never pipe a gate into `tail` — the pipe swallows the exit code.
