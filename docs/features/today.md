### The header is the shell's, not the hub's

**Since Folyadék F1 (`mezo-n4wf5.1`, 2026-10-09) the shell header is the `TitleBar`** (`frontend/src/app/TitleBar.tsx`, replacing `AppHeader.tsx`; see [`_platform-design-system.md`](_platform-design-system.md) §2 item 1), mounted once by `AppLayout` inside `ScreenContent` on every route except the chrome-free ones (`/train/session`, `/train/sport/log`, `/me/sleep/night`, `/ritual` — the `hideChrome` list, `frontend/src/app/AppLayout.tsx:54`, which also gates the bottom bar and `QuickLogFab`) and `/mezo/chat` (own conversation header, `mezo-oq8z`). It is sticky. On a **hub** (the path is one of the domain's four tab routes, or the single parameter segment of a tab flagged `hubChild` — only A napom's `/nap/napom/:date` today; `isHubPath`, `frontend/src/app/navModel.ts:267`, the one rule `frameFor` for the title bar and `TopTabs` both read since F2) it shows the date context line and five round buttons — *Minden oldal* (`/minden#<domain>`), the *Mezo üzenetei* circle (`/nap/uzenetek`, the unread badge — still ONE thread via `MezoThreadProvider`), the **notification bell + panel** (ported unchanged), *Beállítások* and the **day orb** (→ `/nap/napom/<today>`, level only, from `useDayOrbFill`; `shared/ui/DayOrb.tsx` is dead, `mezo-nxb2e`) — then the page title with the kalauz „?" and the four **top tabs** (`TopTabs`, with the „A napom" morning dot and the unread count on „Beszélgetés"). On a **sub-page** it is back · title · „?" · bell, and the back returns where the user came from. There is **no daypart switch, no section label/clay spot, no aurora** in the header any more (`HeaderAurora`, `useCondensedHeader`, `headerSection.ts` are gone); `logic/useDayFace.ts` (the `?dp=` / clock resolution) has no production consumer left after F1 — only its own tests. The six-element list below describes the retired `AppHeader`; items 1 (kalauz „?"), 4 (Mezo circle) and 5 (the notification bell and panel) carried over with the same behaviour, the rest are history.

*History — the retired `AppHeader` (`mezo-atry` … `mezo-8az6`, `mezo-oq8z`):* Until `mezo-atry`, `NapHubPage`'s `.nap-head` was copy-pasted verbatim into the Edzés, Fuel, Mezo and Én hubs — five near-identical blocks with drifting content. It lived once, as **`AppHeader`** (`frontend/src/app/AppHeader.tsx`), mounted by `AppLayout` as the first child inside `ScreenContent` on every route except the three chrome-free ones (`/train/session`, `/me/sleep/night`, `/ritual` — the same `hideChrome` flag that also gates `TabBar` and `QuickLogFab`) and `/mezo/chat`, whose own conversation-control header is the single header on that route (`mezo-oq8z`). Since `mezo-8az6` the shell header **kitapad** (`position: sticky`, `top: 0` in the `.screen-content` scroller) instead of scrolling away with the page, and carries a napszak-követő aurora background (`HeaderAurora.tsx`). Since `mezo-oq8z` that aurora remains fully present after the 14px compact threshold (`useCondensedHeader`); only the spacing tightens, so the daypart color neither disappears nor turns into glass. The control row is 42px high with the header's clay icons enlarged by the same 2px; its aurora is a separate background layer extending 18px below the row with a visible mask fade from 70%, while every label and control stays on an unmasked foreground layer. `NapHubPage` itself renders no header at all any more. Six elements (the guide button only where the route has a guide), left to right:

1. **Kalauz „?"** — `.nap-roundbtn.nap-q`, rendered **only when the route has a registry entry** (`findKalauz(pathname)`, `frontend/src/features/tutorial/registry`), always the first button so the daypart switch's presence never shifts it. Opens the page's guide through `useTutorial().open(id)`; carries the `.nap-offnow` amber dot when the route is a T3 guide not yet seen. See [`tutorial.md`](tutorial.md).
2. **Szekció (clay spot + név)** — the mezo-8az6 replacement for the date eyebrow: the dátumot a telefon státuszsávja mutatja, a helyét az „épp melyik szekcióban vagyok" vette át (`app/headerSection.ts` — szekció-szintű, a path első szegmenséből, 115 route mellett tábla nélkül).
3. **Daypart switch** — a round clay button (`.nap-roundbtn`) carrying a daypart's clay icon (`i-hajnal` / `i-nap` / `i-alvas`). It reads `?dp=` **only on `/nap`**; on every other route it shows the real clock-derived daypart, since there is no page there to preselect a mosaic for. Tapping it opens the same three-icon `role="menu"` popover — its items are `role="menuitemradio"` with `aria-checked`, so the selection is exposed, not merely painted by the `.on` class (`mezo-atry` fix wave). Picking a daypart **always navigates to `/nap`**, carrying `?dp=` only when the pick differs from the clock-derived one (picking the clock's own daypart on `/nap` clears the param instead). The navigation **preserves every other query parameter** (`?day=`, `?medCycleDay=`, `?niggle=`, `?vulnerable=`, `?ritual=` — all app-wide scenario switches read by `useTodayScenario`) and uses `replace`, so daypart-tapping neither drops a scenario nor fills the history stack. The `?dp=`-or-clock resolution itself lives in **`logic/useDayFace.ts`**, shared verbatim with `NapHubPage`. The `.nap-offnow` dot — the ADR 0014 dual-signal ("hol tartok" vs "mit nézek") — appears **only on `/nap`**, and only when the shown daypart differs from the clock's.
4. **Mezo-messages circle** — a round button (`i-level` clay icon) with an unread-count `.nap-badge`, navigating to `/nap/uzenetek`. This is the tile that used to sit inside every daypart's mosaic (reggel/nap/este all carried a `Mezo` tile); `mezo-atry` moved it into the header instead, so it now appears exactly once per screen instead of once per daypart. The unread count is watermarked in `localStorage` (`lastSeenMessage`, key `mezo.msgseen.<date>`). **The badge and the page read ONE thread** — `MezoThreadProvider` (`frontend/src/features/today/MezoThreadProvider.tsx`), mounted by `AppLayout` around `ScreenContent`, is the single builder of `buildMezoMessages({ feed, demoBriefing, nudges })` and the single writer of the Életjel nudge log. This is not decoration: while the header built its own **nudge-less** thread and the page stamped the watermark with its own (nudge-bearing) last id, the header's `findIndex` could never match, so the badge fell back to the full count and **never cleared** (`mezo-atry` fix wave). The watermark is also React state in the provider, so the badge goes dark the moment the page marks the thread seen — not one navigation later.
5. **Notification bell** — a second round button with an unread-count `.nap-badge`, opening the `.nap-ntfpanel` **scrollable, full-width notification panel** (mezo-g9fz). It is a child of the `<header>` itself, not of the bell's wrapper — `left: 0; right: 0` against `.app-head` is what makes it full width — and it has three regions: a pinned head (`Értesítések` eyebrow + live unread count + `Mind olvasott`), a horizontally scrollable filter-chip row (`Mind` · `Olvasatlan` · the six categories of `features/notification/logic/category.ts`, each with its clay icon and count, only drawn when non-empty), and the scrolling list, capped at `max-height: min(600px, 74vh)` with sticky `Ma`/`Tegnap`/dated day labels, over an `Összes értesítés ›` foot → `/me/ertesitesek`, the notification **feed page** (`NotificationFeedPage.tsx`), not the preferences page. It shows the newest **30** notifications (`Date.parse(occurredAt)`-sorted BEFORE the slice — the raw arrival order drew today's OLDEST rows, `mezo-tdzy`), each with its kind's clay icon + tint (`APP_NOTIFICATION_KIND_META`), a `.nap-ntf-when` clock (the day is carried by the group label, so `timeLabel()` not `notificationStamp()`), a `deeplink` tap target, and while `readAt === null` the `.nap-ntfrow.unread` wash, a `.nap-ntf-dot` and an `sr-only` „Olvasatlan". Read state here is the LIVE `readAt`, not the feed page's open-time snapshot: in the panel the un-highlighting IS `Mind olvasott`'s feedback. Source: `useNotificationFeed()` + `useNotificationFeedActions()`. The former gap here — the badge had no reachable path that ever called `markAllRead`, so it could never clear (`mezo-61w0`) — is closed twice over: opening the feed page fires `markAllRead()` once, and the panel's own `Mind olvasott` does it without leaving the page. A `.nap-ntfscrim` dims the page behind the panel while keeping the header lit (a stacking trap — see `_platform-notifications.md` §9). See [`_platform-notifications.md`](_platform-notifications.md) for the feed page itself.
6. **Day orb** — `.nap-avatar` rendering `DayOrb` (`frontend/src/shared/ui/DayOrb.tsx`) — since the Üveg foundation (`mezo-me75u.1`) a glass sphere holding a coral liquid that rises to the day's fill with a slow wave (formerly the bottom-filling variant of the `#s-orb` sprite), filled/tinted from `useDayOrbFill()` (since Kihagyás S1, `mezo-q4xt2.1`, a skipped gym/sport/run occurrence is excluded from the fill exactly like a planning surface, not just sport — see [`train.md`](train.md) "Kihagyás (S1)") → **`/nap/napom/<today's ISO date>`** (`mezo-yjzhw.4` — the retired `/me/week/napok/<today>` target now redirects here). The orb *is* today, so it skips morning mode; the "A napom" tab (§3) is the entry that honours it instead. It is **not** a profile shortcut — that duplicated the bottom "Én" tab and was retired (`mezo-idz2`); this button is the header's daily status indicator instead, and its `aria-label` speaks the day's fill in words (e.g. "A mai napod · 3 a 6 jelből megvan"), not just in color.

**Popover + landmark contract** (`mezo-atry` fix wave, fixed once here instead of five times): the root is a real `<header>` element; both triggers carry `aria-haspopup="menu"`; either popover closes on **Escape**, on an **outside click**, on a pathname change, on re-tapping its trigger and on choosing an item; the bell menu's eyebrow line is `role="presentation"` (a bare `<span>` is not a valid `role="menu"` child) with the label moved onto the menu's `aria-label`. **Focus management is deliberately NOT here** — no focus trap, no roving tabindex; see §9.

**CSS:** the component still renders `className="nap-head app-head"` — it inherited the `.nap-head` flex row verbatim, plus a new `.app-head { padding-top: 6px; margin-bottom: 7px; }` rule that makes the gap under the header a uniform 13px on all five hubs (it used to be 13px on Nap alone and 11px on the other four, back when each hub hand-tuned its own copy).

### The Mai composition (Folyadék F2, `mezo-n4wf5.2`)

Build target: [`vilagos/nap.js`](../design_2.0/prototypes/vilagos/nap.js) `mai()`. Top to bottom (`pages/NapHubPage.tsx`):

1. **Kímélő slot** (`KimeloSlot`) — nothing, or the „Hogy vagy?" warn hero while a recovery period is open (§3).
2. **The tank** (`data-kalauz-anchor="nap-hero"`). The number is `needsAverage(needs.states)` — the rounded mean of the six életjel levels, computed on the client (`logic/needsAverage.ts`); „…" while `useNeeds` is pending, never a fabricated 0. Owner decision 2026-10-10: the app serves no day score before the overnight close, so the prototype's „72 of 100" had no source during the day. Caption „a 100-ból · hat életjel átlaga"; the verdict is `dayReading(evaluation, day)` (the pure rule A napom also prints). The primary button is the next fillable check-in slot („Reggeli / Délelőtti / Délutáni / Esti check-in" → `CheckInSheet`, offered only once the persisted slots are known) or, with none, „Gyors logolás" → `/nap/gyors`. A tap on the air (labelled „Életjelek") opens `/nap/eletjel`. With kímélő mód on the tank is taller and reads „Ma a pihenés a dolgod.". **In the evening** (20:00 → midnight, `useNapzarasState`) `NapzarasCard` draws the same level as a **dusk** tank instead: „Tegyük le a napot." with fact chips (kcal · edzés fact or „edzés · kímélő mód" · check-in x/4 · N/6 terület kész) and „Napzárás indítása" → `/ritual`; once the day is closed „Letetted a napot." and „A napom".
3. **„Mai szintek"** — four `Vials`: Kalória, Fehérje, Alvás, Mozgás (sources in §3 „The composition"); each opens its domain (`/fuel`, `/me/sleep`, `/train/mai`).
4. **„Most következik"** — a `Stream`, hidden when it has nothing: the next check-in (slot time, „N koppintás, kb. fél perc" from the slot's plan, „Kitöltöm"); by day an undone workout („Edzés" → `/train/mai`; kímélő: „Kimarad", not tappable); in the evening window instead „Napzárás" (→ `/ritual`, or „Kész ✓" → A napom) and „Esti rutin" (→ `/nap/rutin?dp=este`). There is no meal row: no source says when the next meal is due.
5. **„Észrevétel"** — `NapPersonalInsight`: the first substantive, non-rejected observation in server order as a Mezo message (`Msg`), with a „Miből látom" toggle over the shared `EvidenceList` and the three replies `Igen, ez igaz rám` / `Nem, ez nem stimmel` / `Beszéljük meg` (shared reply contract, guarded against a double submit); empty / degraded / error states make no personal claim.
6. **„Mai napló"** — the latest eight of today's check-ins, meals, journal notes and activities (`buildNapTimeline`) as a `Stream`, sorted by known capture time; an unknown timestamp says „Ma", a scheduled slot time never poses as a save time. Loading, empty („Az első mai bejegyzésed itt kap helyet.") and partial-error states are visible. „+ Új bejegyzés" → `/nap/gyors`.
7. **„Továbbiak"** — one card: „A napod üzemanyaga" (opens `NapFuelSheet`: `NapFuelGraphic` in a light sheet — consumed kcal against the keret and three macro vials against their own targets, in the app-wide macro colours; zero, unknown target, loading, read failure and the kímélő `GUIDANCE` day are distinct), „Életjelek" (value = the average; the sub names the one need that asks for attention), „Összes észrevétel" (→ `/nap/uzenetek?tab=eszrevetelek`), `AskTeamRow`, the buttons „+ Új bejegyzés", „Napló" (`JournalSheet`) and „Több" (a sheet: Aktivitás → `ActivityLogSheet`, Chat → `/mezo/chat`, Életjelek, Napi küldetések), and last `KimeloEntry` („Nem vagyok jól").

All five capture actions of the former orbit survive: Check-in (tank button and stream row), Gyors logolás, Napló, and Aktivitás + Chat inside „Több". The Boop centre (`NapCompanion`) is deleted. Mai no longer reads `?dp=` or the rough-day scenario; reduced motion leaves every vessel at its final, still frame (kit rule, bible §8).

## 3. Architecture & data flow

The single FE↔data boundary stays `frontend/src/data/hooks.ts`; every hook is dual-mode. What changed is the **shape of the composition**: there is no longer one composition root holding every hook for the whole screen. **Each page holds its own hooks** — the hub holds the hooks its heroes and tiles need, and each sibling page re-reads the subset it renders. The pure logic modules are shared and unchanged.

### The logic modules (`frontend/src/features/today/logic/`)

- **`dayFace.ts`** — the day model, **UNCHANGED** since `mezo-ly8c`: three wrap-aware windows off `useSleepGoal()`'s wake/bed anchor (mock: 06:15–11:45 / 11:45–19:15 / 19:15–06:15), the degenerate-anchor guard, `dayFace`/`faceWindows`/`faceOf` + `DAY_FACES`/`FACE_LABEL`. Nobody calls `dayFace()` directly any more: the `?dp=`-or-clock resolution is **`useDayFace.ts`**'s (below). `FACE_ICON` — the clay-icon table — lives in `app/AppHeader.tsx`, the only surface that draws a daypart glyph, and it reads `FACE_LABEL` from here; the old `FACE_EMOJI` table had no caller left and was removed in `mezo-8slef`.

### A napom — the live day / closed-day review (`pages/NapomPage.tsx`, `mezo-yjzhw.4`)

`/nap/napom` (today, or yesterday in morning mode) and `/nap/napom/:date` (any day) replace the
retired `WeekDayPage` at `/me/week/napok/:date`, which now redirects here (`NapomRedirect`,
`app/router.tsx`). Design of record:
[`specs/2026-09-24-a-napom-design.md`](../superpowers/specs/2026-09-24-a-napom-design.md). Look since
Folyadék F2 (prototype `vilagos/nap.js` `napDay` / `ndDayBody`): a week strip of seven vessels, a tank
hero, numbered card sections.

- **Morning mode.** `isMorningMode(yesterdayEval)` (`logic/napom.ts`) is true when yesterday's
  evaluation is `scored` with a `reviewId` and its `napom.seen.<date>` `localStorage` key is
  unset. In morning mode `/nap/napom` (no `:date`) opens **yesterday** and ends with a
  "Tovább a mai napra ›" card; a page carrying an explicit `:date` always honours it and skips
  morning mode entirely. Yesterday is marked seen (`markSeen`) once its review is on screen.
  Morning mode lasts for the current calendar day only. The tab's lavender dot comes from
  `useMorningMode.ts`, a live `useSyncExternalStore` value (`TopTabs.tsx`'s „A napom" dot, formerly `TabBar.tsx`'s `.tb-dot`, bible §5
  appendix rule 25) — not a render-time snapshot.
- **The header day orb navigates straight to `/nap/napom/<today>`** — it *is* today, so it always
  skips morning mode; the tab is the entry that honours it (§2 above).
- **Frame (Folyadék F2).** `/nap/napom/:date` is the same hub page showing another day, so it
  keeps the hub title bar and the top tabs with „A napom" lit — picking a day on the week strip
  must not turn the hub into a sub-page with a back button. The rule is `NavTab.hubChild` +
  `isHubPath` (`frontend/src/app/navModel.ts:267`), read by both the title bar (`frameFor`) and
  `TopTabs`. The title bar's eyebrow names the viewed week (`useFrameTitle`).
- **The hero is a tank.** While the day is `in_progress` its number is `N/6` (`doneCount`),
  captioned „terület kész · élő · hh:mm" (the query's own `dataUpdatedAt`), and it never shows an
  overall number — the line under it says so („Napközben nincs pontszám. …"). Today additionally
  carries **the reading**, one sentence from `dayReading(evaluation, day)`, and the next step as
  the tank's button (`nextBestAction`: „Napzárás indítása" / „Edzés megnyitása" / „Check-in").
  A `scored` day's number is the score („a 100-ból · hat területből"); its verdict is the week's
  own sentence about the day (`dayVerdict`; without week data the day's key highlight); its
  button is „Beszélgess a napról" (the chat hand-off, on every scored day); and when the review
  carries an adjustment the `fo-tank-shift` control reads „alap X · a Mezo szerint ±Y" and is
  **open by default** (owner 2026-09-26, `mezo-7izrx`) — the reason shows as a Mezo message under
  the tank until it is tapped away.
  **The level is banded, not proportional:** the liquid must leave room for the verdict above
  it, so 0–6 done areas move it inside 44–66 % and a score inside 56–66 %; the numeral carries
  the value (bible appendix F2).
- **Other hero states.** Loading — a pending tank with „…" and „Összeszedem a napodat." (no
  number, `mezo-ahf5b`); failed — a warn hero with „Próbáld újra"; `thin` / `empty` — a jar hero
  „Erre a napra kevés az adat."; `future` — „Még előtted.". A hero of another day offers
  „Vissza a mai napra".
- **„Most érdemes"** (`NapomLeadCard`, a `Step`) renders only for today's open day, from the same
  `nextBestAction(evaluation, day, new Date(), ritualClosed)`: the evening Napzárás while
  `isNapzarasCardWindow` holds, else an undone workout, else a missing check-in, else nothing.
- **The six dimension rows** (`NapomDimensionRow`: Tápanyag, Minőség, Edzés, Alvás, Logolás,
  Ritmus) — each a row with a `Level`, in four modes: `loading` (dim, „betöltés…"), `today` (a
  status word — kész / úton / nyitva — no weight shown), `scored` (the weight % shows; the
  row's detail — fact chips and Mezo's per-dimension note — is **open by default on every row**
  and folds on a tap), `plain` (a thin/empty closed day: value only). A row with no score is dim,
  never a filled level. The section is titled by state: „Ma eddig · 6 terület" / „Miből jött
  össze" / „Amit erről a napról tudunk".
- **Closed-day review — every `DayReviewJson` layer:**
  - `adjustment` — the tank's shift control and the reason card under it.
  - `narrative` + `highlights` + the feedback vote — `NapomReviewCard` („Mezo a napodról": a
    `Msg`, the highlights, `FeedbackChips` mounted on `reviewId` presence, never on `state`
    alone).
  - `dimensionNotes` — in each dimension row's detail, as above.
  - `context` — „A nap körülményei" cells with the note „Ezek nem számítanak a pontba.".
  - A closed day's foot line: "Ha utólag beírsz még valamit erre a napra, a jegyzetet egyszer
    újraírom."
- **„A napod · te és az app" (Check-in 2.0, `mezo-ck2`, spec §3.10).** When the viewed day has an
  evening „A nap mérlege" answer (`useCheckinDayRating(date)` — the latest slot carrying
  `dayRating`), `NapomDayRatingCard` renders two vials — „az app szerint" (the day score /100 and
  its band word, or „hajnalban zárom" before the close) and „szerinted" (the rating /10 and its
  band; `ratingBand` / `scoreRatingBand` in `logic/checkinItems.ts`) — and, when the two bands
  differ, a row saying so. It sits after the six rows on a live and on a scored day alike. Hidden
  while the page is still deciding which day to show. The AI day review also receives the rating
  as its `saját napértékelés` context signal ([`companion.md`](companion.md)).

- **Live today.** The global `MutationCache.onSuccess` (`app/providers/QueryProvider.tsx`) calls
  `invalidateTodayDay(client)` (`data/me/liveDay.ts`) after **every** successful write,
  invalidating `['dayEvaluation', today]` and `['meWeek', monday]` — so no individual logging
  mutation is wired by hand. `useDayEvaluation` additionally polls every 60 s for **today only**,
  in **real mode only** (mock mode keeps `staleTime: Infinity`, the `feedHooks.ts` precedent). The
  hero's "ÉLŐ · FRISSÜLT hh:mm" status line reads the query's own `dataUpdatedAt`, never a clock
  (bible §5 appendix rule 24) — so the header orb, which reads the same query, is live too.
  **By design, today's evaluation therefore polls once a minute in real mode wherever the header
  orb is mounted — i.e. on every screen — so the orb stays live**, not only while A napom is open.
- **One-shot pulse on a changed value (`mezo-yjzhw.6`, spec §4).** When today's evaluation
  refetches (the 60 s poll or a write's invalidation) and a row's displayed value moves — its
  score, status or fact line — that row plays one 1.6 s highlight; the tank's number does the
  same when the `N/6` done count moves. `NapomPage` builds a flat snapshot per render
  (`pulseSnapshot`, `features/today/pages/NapomPage.tsx:61`) and hands it to
  `useChangedKeys(snapshot, date)` (`features/today/logic/useChangedKeys.ts:29`, `FRESH_PULSE_MS`
  at `:13`), which reports the ids that changed since the previous snapshot and clears them after
  the pulse or on the next change. The snapshot is `null` unless the page shows today's open
  evaluation, so the first render, the mock seed, a date change and past days never pulse. A
  fresh row or hero gets `is-fresh`; the look (`@keyframes nn-fresh` / `nn-fresh-n`,
  `styles/folyadek-nap-napom.css`) lives inside `prefers-reduced-motion: no-preference`; reduced
  motion shows nothing.

- **Week strip.** `NapomWeekStrip` renders the viewed week as seven small vessels: a scored day
  filled to its score with the number, a thin day a sliver with „–", today „élő" filled to
  done/6 (only while today's open evaluation is the one on screen), a future day disabled. A tap
  navigates to `/nap/napom/<date>`; the viewed day carries `aria-current="date"`.

- **A malformed `:date` redirects to `/nap/napom`** (bare), unlike the old `WeekDayPage`, which
  redirected to the days mosaic.
- **Evening Napzárás on Mai (`NapzarasCard.tsx` + `useNapzarasState`, owner 2026-09-24).** From
  **20:00 local time** (`NAPZARAS_CARD_FROM_HOUR`) until midnight Mai's tank is drawn by
  `NapzarasCard` as a **dusk** tank at the same level (the életjel average): „Este · napzárás",
  „Tegyük le a napot.", fact chips (kcal, edzés fact, check-in x/4, N/6 terület kész) and
  „Napzárás indítása" → `/ritual`. Once `ritual_day.closed_at` is set for today it reads „Este · a
  nap lezárva", „Letetted a napot." and leads to `/nap/napom`. `useNapzarasState(now)` returns
  `none` outside the window **and** while today's ritual state is still loading (real mode), so a
  closed day never flashes the offer (`mezo-yjzhw.7`); A napom's lead waits for the same answer.
  A day nobody closes simply loses the evening face at midnight (the napzárás itself stays
  calendar-based) — the review still gets written by the overnight warm-up job regardless.

- **Kímélő mód slot on Mai (`KimeloSlot` → `KimeloCard` / `NemVagyokJolSheet`, Kihagyás S2 `mezo-q4xt2.2`, build target `elo/nap.html` `kmCard`).** `KimeloSlot` is the first thing on Mai, above the tank; it reads `useRecovery()` and renders **nothing while the read is pending or errored** (no flash). States: (1) **no period** → the slot renders nothing; the „Nem vagyok jól” entry is `KimeloEntry`, the last row of the „Továbbiak” card, and a tap opens `NemVagyokJolSheet` („Mi történt?” light `fo-sheet`: the 4 serious chips in their own accents — ILLNESS rose, STOMACH sage, INJURY coral, TRAVEL sky — the shared `RecoveryDurationRow` „MEDDIG TARTHAT?", a note, „Kímélő mód bekapcsolása” disabled until a chip is picked; success → toast „Kímélő mód bekapcsolva” + close, failure leaves the sheet with the pick). Works on a rest day. (2) **period open** → the full `KimeloCard` (a warn `Hero`, Folyadék F2): category icon (`t-kimelo` family), „KÍMÉLŐ MÓD · <KATEGÓRIA>”, „Hogy vagy?”, sub „Kímélő mód · n. nap · becslés: …” (or „A becsült idő letelt — hogy vagy?” once the estimate passed), buttons **Még nem / Jobban / Tévedés volt** (Tévedés volt asks in-card: „A kihagyott edzések visszaállnak, mintha be se kapcsoltad volna.” Mégse / Törlöm; success toast). (3) **`checkedInToday`** (after *Még nem*, and also after „Mégsem vagyok jól” in Üdv újra!) → a **slim line** with „Befejezem ›” instead of the full card (the prototype demo shows the full card after undo; production is server-driven). **Jobban** uses the shared `useRecoveryBetter` rule: on the period's first day it **discards** (toast „Kímélő mód befejezve”, no Üdv újra!); later it opens `WelcomeBackSheet` (`showRun={false}` — no run line on Nap; toasts „Jó, hogy jobban vagy” / „Rendben, a kímélő mód folytatódik”) with the active meso week from `useActiveMesoWeek({enabled: Boolean(period)})` (lazy: no meso request without a period). Tests: `KimeloCard.test.tsx`, `NemVagyokJolSheet.test.tsx`, `NapHubPage.test.tsx`, layout `nap-kimelo.spec.ts` (320 px).
- **Overnight close (backend).** `DayReviewWarmupJob` pre-warms `day_review` for yesterday (and a
  catch-up window) every night at 02:30, so the morning read of a closed day is a cache hit, never
  a synchronous LLM call. A later log for that day re-writes the review exactly once, on its next
  hash miss. See [companion.md](companion.md).

## 7. How to extend it

**Extend Mai** — keep the five capture actions reachable and the skeleton intact (one hero, numbered sections, deeper things behind rows). Every graphic must name the served field or the pure rule that feeds it (bible appendix F2.1): add data through existing hooks, keep loading/error distinct from zero, and never introduce an invented number or invented observation copy. A generic piece (button, pill, field, numeral) belongs in the kit; page rules go into the area stylesheet under its prefix (`.nm-` for Mai). Honour reduced motion (the base rule is the final frame) and 320px reachability.

**Add a whole new Nap sub-page** — copy `EletjelPage` as the smallest complete example: `Page` → `FrameBack` → `Hero` → `Section` + `Card` of `Row`s. Hold your own hooks; do not thread data down from the hub. A new screen gets a route in the Folyadék prototype (`vilagos/nap.js`) and the owner's OK before code.

**Add a new mezo-generated message source** — extend `logic/mezoMessages.ts`'s `buildMezoMessages` (or wire a new upstream hook into `NapMezoPage`). The home observation reads `useObservations`, independently of the messages thread. Test ordering/shape in `mezoMessages.test.ts`.

**Change the day model** — unchanged recipe: constants in `dayFace.ts` (`MORNING_LEAD_MIN` imported from `windDown.ts` on purpose); re-check `dayFace.test.ts` and, if the change touches `/nap`'s structure, `frontend/tests/layout/layout.spec.ts` (screenshot goldens are retired, `mezo-ryb6` — there is nothing left to regenerate).

**Add an icon** — Nap's icons are Folyadék-jel glyphs (`Icon3D` names). Where nothing fits, draw a new one per bible §5, put it on the prototype's „Új ikonok" sheet for the owner's OK, then add it to the shared sprite ([`_platform-design-system.md`](_platform-design-system.md)). Never an emoji, never a near-miss glyph.

**Promote a mock section to a real backend** — the check-in remains the working template (contract-first → backend package → Liquibase → ITs → dual-mode FE swap); see §4 and the references table in `CLAUDE.md`.
