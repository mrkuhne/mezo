# Today — Feature Documentation

> The daily home screen at route `/today` (tab "Ma"), the PWA's default landing page. **Status: 🟢/🔶 mixed** — every section is real in real mode or an explicit honest state (Slice T, `mezo-t16y.3`), the briefing prose is real when generated (proactive B1.2, `mezo-h4wp.2`). Since the **iOS list-language redesign** (`mezo-e26w`, 2026-08-11) the screen speaks **one box language** end to end — an iOS inset-grouped list, every section a header on a 16px rail above one rounded box with hairline row separators (`TodayList`/`TodayRow`) — under `AppHero` → a single-track **daypart switcher** (`DaypartTabs`, Reggel · Nap · Este) → a 44px **`MezoChip`** (opens `MezoMessagesSheet` for the day's whole message thread — the old full-bleed briefing band is gone) → the selected daypart's hero, facts, optional CTA, and every row, one collapsed done-fold. This is the **fourth** render layer over the same day model: it replaced the daypart-tabs page (`.segtabs` pills + a full-bleed, never-truncated briefing band identical on all three dayparts, [ADR 0025](../decisions/0025-today-daypart-tabs.md), 2026-08-10), which replaced the sky of three islands ([ADR 0022](../decisions/0022-today-three-islands.md)), which replaced the daypart-faces stack ([ADR 0014](../decisions/0014-today-daypart-faces.md)) — **the day model underneath is unchanged across all four.** Driving decision: **[ADR 0026](../decisions/0026-today-ios-list-language.md)** over [`specs/2026-08-11-today-ios-redesign-design.md`](../superpowers/specs/2026-08-11-today-ios-redesign-design.md). **Deliberate scope boundary:** `shared/ui/ItemRow` was **not** touched — Fuel's "Mai" window flow and the Me routine editor still speak the old row language; Today's `TodayRow`/`TodayList` are a new, Today-local family, held to that boundary by a structural test (§9, `todayScope.test.ts`).

## 1. Summary

**Today** ("Ma") is mezo's daily aggregation surface. Since `mezo-e26w` it renders top to bottom as one iOS inset-grouped list on `.screen-content`'s own scroll (unchanged carrier since `mezo-puci`):

- **`AppHero`** (unchanged chrome) → **`VulnerabilityCard?`** (`?vulnerable=on`).
- **`DaypartTabs`** — one `--surface-recess` track (`.td-seg`, `role="group" aria-label="Napszak"`) holding three buttons (🌅 Reggel · ☀️ Nap · 🌙 Este), each `aria-pressed`; the pressed segment lifts onto `--surface-card` with a `.5px` contour rather than a shadow. The chronologically-current daypart still wears a small gold `.td-now` dot **independent of the pressed segment** — the ADR 0014 dual-signal ("hol tartok" vs "mit nézek") inherited a fourth time. This replaces the three separate `.segtabs` pills `mezo-puci`/ADR 0025 shipped the day before (a second DaypartTabs iteration inside this same slice, commit `ad5091fa`) — the switcher is now the iOS **segmented control** idiom, not the Sport/Futás `.segtabs` one.
- **`MezoChip`** — the companion's voice compressed into one 44px row: a coral-gradient avatar (✦) · "Mezo" · the **latest** message's first sentence, ellipsis-truncated · a message-count badge · a chevron. **Honest absence:** renders **nothing** when the day has no message at all — no empty state, no placeholder (mock mode always has one: the briefing, so the badge reads `1`). An unread coral dot sits on the avatar until the day's latest message has been opened; the read-state is `localStorage`, keyed **by date** (`mezo.msgseen.<YYYY-MM-DD>` → `shared/lib/seenMessages.ts`), written the moment the sheet opens — no backend, no server-side read-state, and the key goes stale on its own at midnight. The whole chip is the tap target (`aria-haspopup="dialog"`), not just the chevron.
- **`MezoMessagesSheet`** — "Mezo üzenetei" over the house `Sheet`: the day's **entire** message thread, one bubble per message (own eyebrow + timestamp), oldest first, **never truncated** (no clamp, no `bővebben` — the sheet scrolls instead). Composed by the pure `logic/mezoMessages.ts` (`buildMezoMessages({ feed, demoBriefing })`) — **since `mezo-gst9`** the single data source is the unified companion feed, `useCompanionFeed()` (`data/today/feedHooks.ts`, `['companionFeed', date]`, 60s poll in real mode), not the retired per-surface `useToday().briefing`/`useCompanionNote()` pair. Each `FeedMessage` (kind: morning/sleep/weight/midday/evening) maps 1:1 to a bubble; when the feed carries no `morning` kind yet, `resolveBriefing(scenario.dayState)` is prepended as an honestly-labelled demo card (`meta: 'Demo tartalom'`) — mock mode's only branch, since the mock feed is always `[]`. The morning/sleep/weight bubbles carry the full prose (`SafeMarkdown`) + their `RefTag` refs; midday/evening bubbles carry no refs (ported from the retired heartbeat, which never collected any).
- **`DaypartPanel`** — the selected daypart's content, still frameless (`.dayview`, unchanged carrier component since ADR 0025 — it still owns the tab-switch `isl-phasein` cross-fade and the evening `is-night` darken): a left-aligned hero number (`DaypartHero`, now `.td-hero*`), `TodayStats` — **one** bordered box with a vertical hairline between its 1–2 fact cells (the `IslandFactsStrip` successor; same "no source → no cell" rule), an optional CTA (`.td-cta`/`.td-cta.is-lav`) and/or a footnote line (`.td-foot`, the niggle warning's new home — no longer a chip box), and `DayGroups` — every item group as **one `TodayList` box** of `TodayRow`s, plus the single surviving collapsed element, the done-fold.
  - 🌅 **`DaypartMorning`** — hero = last night's sleep (`7,2 óra alvás`, sub: goal distance + weekly debt); facts = weight trend vs goal + HRV (mock-only); **no promoted CTA** (the chain's first open step is already a row in the list); focus = the creed as its own `TodayList` box (`IntentionBanner variant="chip"`).
  - ☀️ **`DaypartDay`** — hero = the session's start (`13:00 · Pull A`, sub: mezó-week; rest day: `Pihenő` + `Saját edzés`); facts = protein-so-far vs target + energy balance (from the fuel plan); the niggle warning is the one footnote line under the CTA. **A `logged` hero has NO CTA** (`mezo-v84m`): the start button is replaced by a `✓ Kész · N szett` footnote (`.td-foot.is-done`) — `logged` gates *before* `ctaLabel`, so authoring a label cannot reintroduce the dead control.
  - 🌙 **`DaypartEvening`** — hero = a **live countdown to lights-out**; content **swaps by `windDown` phase** (§2) in the same hero/CTA band; the éjszaka phase darkens the **panel itself** (`DaypartPanel`'s `night` prop — theme-invariant dark, the `.isl-night`/`.wdb-night` heritage).
- **The row itself (`TodayRow`)** — `[28px icon] [title + anchor subtitle] [accessory]`, min 56px tall, every tap target ≥44px (`.td-row-hit` stretches the chevron rows' hit box to the full row). Four accessory shapes: a pipeable circle (`tick`, MANUAL habit), an inked text button (`button`, every other labelled action), nothing (`none`, no action), or a chevron (`chevron`, a directly-rendered sheet-opening row, not `TodayItem`-derived) — **implemented, currently no production consumer** (§9). The first three are a pure derivation, `logic/rowAccessory.ts`'s `rowAccessory(item)`, keyed off `action.habit.mode`, never off label text (every `TodayAction` variant already carries a `label`, so "no label" is not a distinguishing signal). `TodayRow` is a **new, Today-local** component — not `shared/ui/ItemRow` — but re-implements the four `ItemRow` behaviors worth keeping: `linkUrl` renders a trailing `↗` beside the action (never inside the row's own `<button>`), `disabled` (an in-flight write) **withdraws** the control rather than dimming it, an `actionLabel` with no `onAction` renders inert text rather than a dead button, and a `done` row keeps its **original** icon — the tick circle carries the completion signal instead of swapping the icon to `✓`.
- **Habit-row icons** — `logic/itemIcon.ts`'s three-rung ladder (`habitIcon(habitKey, chain)`) replaces `todayItems.ts`'s old one-line `emoji: DAYPART_EMOJI[chain.daypart]`, which used to put the same 🌅 on all five morning-chain rows: (1) a curated per-habit emoji for all 15 seeded habits (`morning_pushups → 💪`, `morning_coffee → ☕`, …, mirroring the mock/backend habit catalog, each icon unique); (2) failing that, the habit's `LifeSkillKey`'s emoji off the chain's own `defs` (the closed 8-value enum, so a future AI-generated or user-created habit always resolves); (3) the daypart emoji, unchanged as the final fallback. Non-habit rows (quest ⚡, check-in 💗, fuel 🍶, session) keep their existing source emoji — untouched, they mark a *source*, not a habit identity.
- **L2** — every sheet unchanged (CheckIn, ActivityLog, LogMeal, SleepLog, Intention, Reflect, CustomWorkout, Creed) **plus** the new `MezoMessagesSheet`.
- **Rough day (`?day=rough`)** still melts to `AnchorIsland`'s content (unchanged, and still the one Today component that imports `shared/ui/ItemRow` — an explicit, tested exception), wrapped in a `DaypartPanel` with a **constant `tone="reggel"`** — unchanged reasoning (§9). Checked before everything else, as ever (`anchorMode` first in the guard order).

Everything in the panel is actionable while its daypart is merely *selected*, not current ("act-anywhere", unchanged). This is the **fourth render layer over the same day model in a row** — `dayFace.ts`/`islandFacts.ts`/`questAction.ts`/`habitAction.ts`/`windDown.ts` carry no commits in this branch, and `todayItems.ts` carries exactly one (the `itemIcon` swap above). Status per layer: **FE mock ✅** (deterministic; the mock sleep goal wake 06:45 / bed 23:15 pins the windows), **FE real ✅** (composition over existing reads; the facts still derive from `useSleep`/`useWeight`/`useGoal`/the fuel plan — no new backend), **Backend ✅ check-in only** (unchanged — the re-composition was frontend-only, no API-contract change).

## 2. User-facing behavior

- **Open the app →** lands on `/today` (`router.tsx`); mock renders synchronously.
- **Fixed chrome:** the shared **`AppHero`** (identity + XP ring + 🔥/⚡/🪙; Today passes the ✨ Insights link as `utilities` — the only Today→Insights route). `VulnerabilityCard` (`?vulnerable=on`) renders between the chrome and `DaypartTabs`.
- **Selecting a daypart.** Tapping a segment cross-fades `DaypartPanel`'s content with an 8px rise (`isl-phasein`, reused verbatim — not a new keyframe) and scrolls `.screen-content` to the top — unchanged since ADR 0025; there is no L1 to close, everything is already visible. `?dp=reggel|nap|este` pins the selection (URL-derived, never mirrored to state; `null`/`''`/unknown → the clock's daypart; selecting the current daypart **deletes** the param; writes `{replace:true}` — this logic is untouched, only its consumer changed).
- **Opening the companion's voice.** Tapping the `MezoChip` (anywhere on it) opens `MezoMessagesSheet` and marks the thread seen (`markMessagesSeen(date, latestId)` — the coral unread dot on the chip's avatar clears immediately, before the sheet's close animation even starts). The chip's own preview text and count badge never change with the selected daypart — the thread is daypart-independent by design, the direct fix for the old band's "same briefing on Reggel/Nap/Este" complaint. Closing the sheet ("Kész" or the house `Sheet` dismissal — backdrop, Escape, drag-down) leaves the chip in its now-read state; only a **new** message (a later `id`) re-arms the dot.
- **The promoted CTA** — day and evening only (morning has none, see §1): `Indítsuk`→`/train` or `Logold` (day session hero; `Saját edzés`→CustomWorkoutSheet on rest days), the Napzárás CTA (evening; `?ritual=` override wins, `waiting` renders a ghost with the opening time — the window only nudges, `/ritual` always works).
- **The gym hero's done-state** (`mezo-v84m`) — `useToday().workoutDone`/`workoutDoneSets`, derived from `useTrain().completedTodayWorkout` (real mode; mock persists no instances → always `false`, so the mock hero stays byte-identical to Phase 1). It is **the same server truth the Train tab's `Kész · N szett` hero gates on**, so the two tabs cannot disagree about whether today's workout is over — the bug it fixes was Today authoring `logged: false` unconditionally and still offering `Indítsuk` hours after the session was finished. Set count excludes skip markers, exactly as Train counts them. **Still open** (`mezo-6kap`): the in-progress state (Train's `● Folyamatban · Folytassuk`) and the sport hero's done-state have no Today equivalent — both still read as fresh.
- **The done-fold** is the one collapsed element left on the page: `✓ N kész · +M XP ▾` expands in place (`DayGroups`' own height animation) to show the done rows, `▴` folds back. Every OPEN row is already visible with no unfold — all row behaviors are inherited unchanged: quest pills wear `questAction`'s own labels as inked text buttons (`+250 ml` logs in place; `Check-in` opens the first fillable slot), MANUAL habits tick via the `td-tick` circle, DERIVED habit kinds route through `habitAction` as text buttons (Logolás / sheets), fuel rows log **in place** (LogMealSheet), a `skipped` check-in slot stays fillable (`Hogy voltál?` · `HH:mm · elmaradt` · `Pótold`), `linkUrl` renders `↗` beside the action, and **no row ever shows a control this screen cannot serve** (`servableAction` strips + `habitHint` explains). An in-flight habit write withdraws differently by accessory shape: a MANUAL row's tick circle disappears entirely (no button, no leftover ✓ ghost — `disabled` withdraws, it does not dim), while a DERIVED row's text button freezes to inert copy (`.td-act.is-inert`); either way the row's own title stays readable.
- **The evening daypart's four phases** (one hero/CTA band, content cross-slides; countdown always live, 30 s tick):
  | Phase | Window | Content |
  |---|---|---|
  | 🌙 normál | evening, `phase === 'none'` | facts + lavender CTA; sub: napzárás-ablak + villanyoltás |
  | 🌘 ráhangolódás (dim) | `[bed−90, bed−60)` | facts swap to the REM-in-cool-room evidence + sleep outlook; sub: fény &lt;30 lux · ~18 °C |
  | 🌒 leállás (winddown) | `[bed−60, bed)` | the CTA row gains the **`Leállás megvolt ✓`** ghost — the `wind_down` MANUAL habit's check (same `['habitDay', date]` cache as its row; the row is filtered **only while this phase shows the ghost**, so the habit is offered exactly once and stays reachable in dim/none — the `mezo-mvb4.1` rule, relocated again) |
  | 🌑 éjszaka (night) | `[bed, wake−30)` | **the panel itself darkens** (`DaypartPanel`'s `night` prop, theme-invariant dark — the `.isl-night`/`.wdb-night` heritage); countdown reads `elmúlt`; a single `Éjszakai mód megnyitása ›` row → `/me/sleep/night`; no facts, no CTA |
  The ritual-owned rows (`ritual:day` + `habit:evening_ritual`) are always filtered from the evening groups — the hero CTA owns that act (`RitualCard`'s rule, relocated into `DaypartEvening`).
- **Ticking something** removes it from the open list (into the done block / the evening retrospective); chain completion still fires the per-chain success toast (`ChainCelebrations` — `🌅 Tökéletes reggel` / `🌙 Tökéletes este` / `✨ {title} kész`), now queued **on top of** the stacking toast host ([design-system doc §2 item 7](_platform-design-system.md)) instead of replacing whatever's on screen. **Since `mezo-k5sa`:** every completion source on this page — the manual habit tick, the DERIVED-habit and quest consume-once effects (both in `TodayPage.tsx`), the wind-down banner's own check (`DaypartEvening.tsx`), `DailyQuestsCard`, and `ActivityLogSheet` — builds a DS reward toast via `frontend/src/features/progression/logic/rewardToast.ts`'s `buildHabitRewardToast`/`buildQuestRewardToast` and emits it on the `toastBus`; a level-up rides **inline inside that same card** (its `meter`/`levelUp` fields), not a separate overlay. The full-screen `LevelUpScreen`/`useLevelUp` overlay no longer fires from Today — it's now exclusively the four Train pages' (`ActiveWorkoutPage`, `SportPage`, `TrainTodayPage`, `RunningPage`).
- **Scenario deep-links** (dev/demo affordances, unchanged semantics): `?dp=`, `?day=good|medium|rough` (rough → the anchor melt), `?niggle=on|off` (the day daypart's `.td-foot.is-warn` footnote), `?vulnerable=on|off`, `?medCycleDay=N` (the medication cycle-day override; the owner tracks no medication, so this stays a dev-only override), `?ritual=waiting|open|done`.
- **Check-in** — the 4 canonical slots bucket onto their daypart's groups by clock time; `CheckInSheet` per slot; real mode reads/writes the server day (unchanged, §4).

## 3. Architecture & data flow

The single FE↔data boundary stays `frontend/src/data/hooks.ts`; every hook is dual-mode. Shape of the screen: **`TodayPage` holds every hook, the pure logic modules derive the day model + item list + facts + the message thread, and the daypart/list components are presentational** (the evening daypart alone self-fetches its phase/ritual/habit wiring, the `WindDownBanner`/`RitualCard` heritage).

### The logic modules

- **`logic/dayFace.ts`** — the day model (UNCHANGED, `mezo-ly8c`): three wrap-aware windows off `useSleepGoal()`'s wake/bed anchor (mock: 06:15–11:45 / 11:45–19:15 / 19:15–06:15), degenerate-anchor guard, `dayFace`/`faceWindows`/`faceOf` + `DAY_FACES`/`FACE_LABEL`/`FACE_EMOJI`.
- **`logic/todayItems.ts`** — the six-source normalizer (unchanged except one line): `buildTodayItems`/`itemsForFace`/`openCountByFace`/`isFillableSlot`, dedup tables, quest CTA labels. The habit branch's `emoji:` now calls `habitIcon(h.key, chain)` (below) instead of indexing a hardcoded `DAYPART_EMOJI` map inline — the map itself moved to `logic/itemIcon.ts` to avoid a `todayItems → itemIcon → todayItems` import cycle.
- **`logic/islandFacts.ts`** — pure fact derivations for the hero/stats band (`mezo-euze`, untouched by `mezo-e26w`). `IslandFact { label, value, unit?, delta?: { text, tone: good|warn|muted } }`, `IslandHero { value, unit, sub }`. Exports: `morningHero` (sleep hours + goal diff + 7-night debt; null without a last night → `fallbackHero(openCount)`), `weightFact` (7-day delta, toward-target tone, goal distance), `hrvFact` (from the QuickStats cells — **null in real mode**, no source), `proteinFact` + `kcalFact` (from the fuel plan's slots/energy), `dayBalance`, `sleepOutlook`, `bedCountdown` (wraps `minsToBed`; >12 h to next bed = the „elmúlt” state). **Every fact is null on a missing source — the cell simply does not render** (strip philosophy; 0 facts ghost `TodayStats`).
- **`logic/itemIcon.ts`** — **NEW (`mezo-e26w`)**: `habitIcon(habitKey, chain): string`, the three-rung ladder (§1) — a curated 15-entry `HABIT_ICON` table (the full seeded catalog, mirrors mock + backend `content/habit-catalog.json`), then `SKILL_ICON` keyed off the chain's own `defs[].skillKey` (all 8 `LifeSkillKey` values), then `DAYPART_EMOJI` as the final fallback. `DAYPART_EMOJI` is exported from **here**, not `todayItems.ts` — `todayItems.ts` imports `habitIcon` from this module, so the map had to move to avoid the cycle.
- **`logic/rowAccessory.ts`** — **NEW (`mezo-e26w`)**: `rowAccessory(item: TodayItem): 'tick' | 'button' | 'none'` — `'tick'` iff `action.kind === 'habit' && action.habit.mode === 'MANUAL'`, `'button'` for every other non-null action, `'none'` when `action == null`. The fourth accessory shape, `'chevron'`, is **not** derived here — it is a plain `TodayRow` prop for a directly-rendered sheet-opening row that isn't `TodayItem`-derived at all; the design spec assigned it to the Reflexió/Fókusz rows, but neither ships on it (§9).
- **`logic/mezoMessages.ts`** — **NEW (`mezo-e26w`), rebound onto the companion feed (`mezo-gst9`)**: `buildMezoMessages({ feed, demoBriefing }): MezoMessageItem[]` — the day's message thread, built from `useCompanionFeed()`'s `FeedMessage[]` (kind→id, `body[].text`→paragraphs, refs pass through) in `generatedAt` order, with `resolveBriefing(scenario.dayState)` prepended as the labelled demo card only while the feed carries no `morning` kind. This is the one place a future feed kind or a future generated-message source gets threaded in without touching `MezoChip`/`MezoMessagesSheet`.
- `logic/useWindDownPhase.ts` — the ONE ticking phase derivation, read only by `DaypartEvening` (content + countdown) since `mezo-puci` — `TodayPage` itself no longer calls it directly. `questAction`/`habitAction`/`growthToday`/`useChainCelebration`/`windDown.ts` unchanged; **`dayArc.ts` still belongs to ritual's recap** (do not delete — see §9).

## 4. Data model & API

### Frontend types (`frontend/src/data/types.ts`) — unchanged
`DayState`, `CheckinValues`/`CheckinState`/`CheckinSlot`, `Briefing` (`confidence?` optional; `tone?` dead data), `Workout*`, `VolleyballSession`, `TodayMeta`/`UserMeta`, `TodayScenario`, `FuelSlot`/`FuelPlanToday`.

**View/logic shapes live OUTSIDE `data/types.ts`:** `DayFace` + consts (`logic/dayFace.ts`); `TodayItem`/`ItemStatus`/`ItemSource`/`ItemAction`/`SessionItemInput`/`TodayItemsInput` (`logic/todayItems.ts`); `IslandFact`/`IslandHero`/`FactTone` (`logic/islandFacts.ts`, mezo-euze); **`MezoMessageItem { id, eyebrow, time, paragraphs, refs, meta }` (`logic/mezoMessages.ts`, NEW mezo-e26w)**; **`RowAccessory = 'tick' | 'button' | 'none'` (`logic/rowAccessory.ts`, NEW mezo-e26w — `TodayRowProps.accessory` widens this by one value, `'chevron'`, declared directly on `components/TodayRow.tsx`)**; `DayHero` stays in **`components/DaypartDay.tsx`** (unchanged shape — `TodayPage.tsx`'s `heroCardOf` still builds it); `DaypartHero` **component** (not the `DayHero` type) lives in `components/DaypartPanel.tsx`; `ItemTone` stays in `shared/ui/ItemCard.tsx` (still imported by `DaypartDay.tsx` for the `DayHero.tone` field — the only remaining `ItemCard`-family type Today's own page language depends on). **No API-contract change** — the re-composition was frontend-only.

### Mock data — unchanged

## 5. Integrations

Today is an **aggregation surface** — its value is the seams:

- **→ Train** — *live shared data + navigation*. The day daypart's hero is Train's today session (`useToday` composes `useTrain()`); `Indítsuk` → `/train`; rest day → `CustomWorkoutSheet`; **a finished session drops the CTA entirely** — `useToday` carries Train's `completedTodayWorkout` through as `workoutDone`/`workoutDoneSets` (`mezo-v84m`, §2), so the Ma and EDZÉS tabs read one done-state, never two. The session is authored once (`DaySession[]`, order = hero precedence, filtered by ID); identity via `sportKinds`. **Since `mezo-e26w` the shared card language (`ItemCard`/`ItemRow`) is no longer what Today renders** — only the `ItemTone` type crosses (`DayHero.tone`, `components/DaypartDay.tsx`); the row/card markup is Today-local now (`TodayRow`, §1).
- **→ Fuel** — *shared data + a shared write surface*. `useFuelPreview` composes the same `useFuelTimeline()` plan the Fuel „Mai” renders, and **since `mezo-euze` also returns that full `plan`** — the day daypart's protein/energy facts read `plan.slots`/`plan.energy`, so Today's facts and Fuel's timeline cannot diverge. Fuel rows are `DayGroups`/`TodayRow`s now (bucketed by `faceOf`), logging in place via `LogMealSheet` — **not** the `ItemRow`s Fuel's own „Mai” window flow still renders; the two surfaces read the same plan but no longer share row markup (§9's scope boundary). The `nextStack.mezoNote` companion line **still has no surface** (the `.tdc-note` slot retired in the islands era — §9).
- **→ Me / sleep & weight & goal** — the sleep anchor (`useSleepGoal`) remains the root dependency (one clock: dayparts = windDown = Napzárás = circadian theme). **Readers since mezo-euze, unchanged:** `useSleep().lastNight/sleepLog` (the morning hero), `useWeight().weightLog` + `useGoal().goal.targetWeight` (the weight fact). Same caches the Me tab uses.
- **→ Insights** — navigation only (the ✨ `AppHero` utility).
- **← AppHero / progression** — unchanged; [growth.md](growth.md).
- **→ Biometrics backend (real)** — `useCheckins` read+write; the companion's context snapshot reads the latest check-in ([companion.md](companion.md) §5.5).
- **→ Growth (`/me/growth`)** — *live shared data + navigation*. Quests render as `DayGroups` rows; the header summary + the ONLY Today→Growth route lives on the **quest group heading** (`DayGroups`' `{d}/{t} · +XP ›` link — the `IslandList`/`TodoCard` header's job before it, relocated twice now). `GrowthPage` still mounts `DailyQuestsCard`/`ActivityLogCard` — **these two components live under `features/today/components/` but their only mount is GrowthPage** (they are NOT orphans; each render-layer swap has kept them for that one consumer — see the gotcha in §9).
- **← AppLayout / shell** — `useTodayScenario().anchorMode` drives both the warm canvas (`PhoneFrame anchor`) and `TodayPage`'s `anchorMode` early return (the constant-`tone="reggel"` `DaypartPanel` wrapping `AnchorIsland` — §9); the two must stay derived from the same hook. The circadian `[data-day]` canvas tint is the app-level „evening cooling” (the spec's screen-cooling is deferred to it — unchanged since ADR 0022).
- **Shared UI consumed:** `Sheet` (the house bottom-sheet `MezoMessagesSheet` sits on), `RefTag` + `SafeMarkdown` (the briefing bubble's refs/prose — the same primitives the retired `MezoMessage` used), `Skeleton`, `Icon` (the ✨ Insights link). **Since `mezo-e26w`, `ItemCard`/`ItemRow` and `CoachBubble` are no longer part of Today's own page language** — `ItemRow` renders only inside `AnchorIsland` (the rough-day melt, an explicit exception — §9), `CoachBubble` only inside `AnchorIsland`'s `anch-coach` voice; the day's briefing/note prose is `MezoMessagesSheet`'s own `.td-bub*` markup now, not a `CoachBubble` instance. `StatStrip` is still not mounted by Today — the fact cells are `TodayStats`'s own `.td-stat` family (the `IslandFactsStrip` successor) on the same glance-strip idiom. **`shared/ui/Island` is no longer Today's at all** — Fuel's `WindowIsland`/`FuelMaiPage` are its only remaining callers; Today's one remaining `.isl-*` footprint is `AnchorIsland` reusing a handful of individual classes directly (`isl-openhead`, `isl-hero-v/-u/-sub`, `isl-anchor-rows`, `isl-act`, `isl-more`), never the capsule↔big shell itself (see §9). **`shared/ui/ItemRow` itself is the one deliberate exception to the "Today owns its own language" rule** — kept for `AnchorIsland` only, structurally guarded by `frontend/src/features/today/todayScope.test.ts` (§8/§9) so it cannot creep back into any other Today component.

## 7. How to extend it

**Add a new TODO SOURCE** — unchanged recipe: emit in `buildTodayItems` (bucket via `faceOf`, group heading, action with the raw domain object; give the row an `emoji` — call `habitIcon(key, chain)` for a habit source, keep a fixed source glyph for anything else), dedup if needed, wire the hook, teach **both** `act()` and `servableAction()`, test in `todayItems.test.ts` + `TodayPage.dispatch.test.tsx`. It surfaces automatically as a `TodayRow` inside a `TodayList` on its daypart — `rowAccessory()` derives its accessory shape from `action.kind`/`habit.mode` with no extra wiring, unless the row needs the fourth (`chevron`) shape, which the view sets directly.

**Add / swap a hero FACT (still the common case):**
1. Write a pure derivation in `logic/islandFacts.ts` returning `IslandFact | null` — **null whenever the source is absent** (the HRV precedent; never fabricate). Delta text is contextual (trend/goal-distance/forecast), tone `good|warn|muted`.
2. Table-test it in `islandFacts.test.ts` (value formatting — Hungarian decimal comma —, tones, the null branch).
3. Wire the source hook in `TodayPage` and add the fact to the relevant daypart's `facts` array (max 2 cells per panel — passed into `TodayStats`; the fact catalog in the ADR 0022 spec §3 lists vetted candidates).
4. If the source is a new hook on the page, mind the real-mode cost (it runs on every Today visit).

**Curate an icon for a new seeded/built-in habit** — add its `habitKey` to the `HABIT_ICON` table in `logic/itemIcon.ts` with a **unique** emoji (the regression test in `itemIcon.test.ts` asserts no duplicates); skip this step for a user-created or AI-suggested habit — it will resolve through the `skillKey` rung automatically, no code change needed.

**Add a new mezo-generated message source** — extend `logic/mezoMessages.ts`'s `buildMezoMessages` to push another `MezoMessageItem` (or wire a new upstream hook into `TodayPage` and pass it through); `MezoChip`/`MezoMessagesSheet` need no changes — they only ever read the array's length/last element and render every item in order. Test the ordering/shape in `mezoMessages.test.ts`.

**Change a daypart's composition** — `DaypartMorning`/`DaypartDay`/`DaypartEvening` are presentational, each wrapping its own `DaypartPanel`: keep the panel to hero + `TodayStats` + an optional CTA/footnote + `DayGroups` (ADR 0025's layer rule, carried into ADR 0026 — there is no deeper layer to push overflow into, so keep the hero/CTA band itself lean). Evening-phase content lives in `DaypartEvening`'s phase blocks; a new phase means a new `windDown.ts` window first. New list content belongs in a `TodayList` of `TodayRow`s — **not** a hand-rolled box, and never `shared/ui/ItemCard`/`ItemRow` (the `todayScope.test.ts` guard will fail the build, §9).

**Change the day model** — unchanged: constants in `dayFace.ts` (`MORNING_LEAD_MIN` imported from `windDown.ts` on purpose); re-check `dayFace.test.ts` + regenerate the today goldens.

**Promote a mock section to a real backend** — the check-in remains the working template (contract-first → backend package → Liquibase → ITs → dual-mode FE swap); see the references table in `CLAUDE.md` and §4.

## 9. Decisions, gotchas & deferred

- **Decisions:** the current structure is **[ADR 0026 — Today's iOS list language](../decisions/0026-today-ios-list-language.md)** over [`specs/2026-08-11-today-ios-redesign-design.md`](../superpowers/specs/2026-08-11-today-ios-redesign-design.md). It supersedes **[ADR 0025 — napszak-tabok](../decisions/0025-today-daypart-tabs.md)** (over [`specs/2026-08-10-today-daypart-tabs-design.md`](../superpowers/specs/2026-08-10-today-daypart-tabs-design.md)), which superseded the *render layer* of **[ADR 0022 — three islands](../decisions/0022-today-three-islands.md)** (itself over [`specs/2026-08-07-today-three-islands-design.md`](../superpowers/specs/2026-08-07-today-three-islands-design.md), brainstormed through three in-browser prototype rounds), which in turn superseded the *render layer* of [ADR 0014](../decisions/0014-today-daypart-faces.md). ADR 0014's day model, act-anywhere and dedup decisions remain in force through all four render layers, as do the honest-completion decisions ([`specs/2026-07-04-…`](../superpowers/specs/2026-07-04-today-honest-completion-design.md)) and ADR 0010 (nothing self-completes). **ADR 0025's `ItemRow`-based card language does NOT carry forward** — this is the one prior-ADR decision this layer actively reverses, see the scope-boundary bullet below.
- **The scope boundary — the ADR's central trade-off, restated here.** `shared/ui/ItemRow` was **deliberately not touched**. Today's rows are `TodayRow`/`TodayList` (Today-local, `components/`), so the app now speaks **two row languages**: Today's `.td-*` iOS list idiom, and the pre-existing `.itemrow*`/`.todaycard*` language `ItemRow`/`ItemCard` still serve to Fuel's "Mai" window flow (`features/fuel/components/WindowIsland.tsx`) and the Me routine editor (`features/me/pages/RoutineEditorPage.tsx`) — untouched by this branch. This kept the blast radius to one screen (no Fuel/Me visual regression risk, no shared-primitive review surface) at the cost of a real divergence. `frontend/src/features/today/todayScope.test.ts` is the guard that keeps it from drifting further: it fails the build if any `features/today/components/*.tsx` (other than the declared `AnchorIsland.tsx` exception) imports `shared/ui/ItemRow`. **Follow-up filed:** `mezo-jaoy` — unify the two languages (promote `TodayRow`'s idiom into `shared/ui` and migrate Fuel/Me onto it, or the reverse) once the `.td-*` shape has proven out past a single screen.
- **Accepted trades (this layer, `mezo-e26w`):** the full-bleed briefing band that stood identically on every daypart is gone — the companion's voice is now a 44px `MezoChip` + `MezoMessagesSheet`, so the briefing is one tap away rather than always-on-screen (the direct fix for the "same briefing on Reggel/Nap/Este" complaint, §1). The five-plus co-existing box languages (corall text band, bare canvas hero, framed fact strip, individually-floating white row cards with shadow, a yellow warn box, a lavender creed box, grey action pills) collapse into **one**: the iOS inset-grouped list on a single 16px rail. The repeated per-row daypart emoji (five 🌅 on the morning routine) is gone, replaced by the `habitKey → skillKey → daypart` icon ladder.
- **Accepted trades still standing from ADR 0025/0022:** the capsule bubble-morph motion language and the L1 unfold-behind-a-tap model are both gone — everything on the selected daypart is visible with no interaction beyond picking the daypart segment. - **GOTCHA — `.isl-*` is Fuel's alone now; Today's `.dayview` stopped reusing it too.** Two separate retirements stack here.
