# Today — Feature Documentation

> The daily home screen at route `/today` (tab "Ma"), the PWA's default landing page. **Status: 🟢/🔶 mixed** — since **Slice T** (`mezo-t16y.3`, 2026-07-04) every section is real in real mode (deterministic composition over existing real reads) or an explicit honest state. Since **proactive B1.2** (`mezo-h4wp.2`, 2026-07-06) even the **briefing prose** is real: the card renders the companion's own generated morning words when present ([proactive.md](proactive.md)), and the static „Demo tartalom" card survives only as the **honest fallback** (loading / 404 / switch off). Since the **daypart-faces re-composition** (epic `mezo-mvb4`, 2026-07-29) the screen is **three sleep-anchored faces of one screen** — 🌅 Reggel / ☀️ Nap / 🌙 Este behind a pill navigator — all rendered in **one card language** (`shared/ui/ItemCard` + `ItemRow`, promoted out of Train's `.todaycard`). This replaced a 13-idiom, ~3-phone-screen stack carrying ~14 co-equal CTAs, and dissolved the two `ZoneDivider` zones („Teendők ma" / „A napod") the action-first re-composition (`mezo-gj2y`) had introduced. Driving decision: **[ADR 0014](../decisions/0014-today-daypart-faces.md)**.

## 1. Summary

**Today** ("Ma") is mezo's daily aggregation surface — the screen the user sees first every morning. Since the daypart-faces re-composition (`mezo-mvb4`) it is not one long stack but **three faces of the same day**, selected by a pill navigator and pinned in the URL by `?dp=`:

- **Fixed chrome on every face:** the shared **`AppHero`** identity header (avatar + XP ring/level badge + equipped title + 🔥/⚡/🪙 counters, plus Today's own `utilities` — the ✨ Insights entry point, and nothing else, gamified-header slice `mezo-k7rn`) → a single-line **`GreetingHeader`** (day label · date · `Reta D{n}` + a daypart headline) → **`DayFaceStrip`**, the three pills, each carrying its own open-item counter.
- **🌅 Reggel** — the morning habit chain as a `FaceHeroCard` (progress bar + the chain's next step promoted with its action), the AI **„Reggeli briefing"** re-dressed as an `ItemCard` (the day's numbers ride along as `.metapill` facts — this is where „Ma eddig" landed), the **creed chip** + `+ Mai fókusz`, the merged **`TodoCard`**, a **„Ma még vár rád"** preview of later faces' items, and the collapsed **`DoneFold`**.
- **☀️ Nap** — the day's session as an `ItemCard` with its real `Indítsuk` CTA (or a rest-day card offering `Saját edzés`), the creed chip, the `TodoCard`, the companion's midday note, an **„Este vár rád"** preview, and `DoneFold`.
- **🌙 Este** — the **`WindDownBanner`** (dim/winddown/night phases) above the **`RitualCard`** Napzárás hero, the `TodoCard`, the evening **intention reflection**, the companion's closing note, and **„Ahogy a nap telt"** — the day's completed rows plus `Ma összesen +N XP` (this face's retrospective replaces `DoneFold`).

Everything on a face is actionable **while that face is merely selected, not current** („act-anywhere"): a retroactive `Pipa` on a morning habit at 22:00, an early evening-stack log at 16:00. On a "rough" day (`?day=rough`) the whole screen is still replaced by **AnchorMode**, a warm-palette, low-demand recovery view — that branch sits *above* the daypart model and is checked before anything else.

Status per layer:
- **FE mock:** ✅ complete — all sections render synchronously from static data; URL-driven scenarios (`?dp=`, `?day=`, `?niggle=`, `?vulnerable=`, `?retaDay=`, `?ritual=`); the demo copy (prediction line, "Stacked day" AI note) renders only in mock mode. The mock sleep goal (`mockSleepGoal` — wake 06:45 / bed 23:15) is fixed, so the three faces are deterministic in mock mode: Reggel 06:15–11:45, Nap 11:45–19:15, Este 19:15–06:15.
- **FE real:** ✅ **Slice T** (`mezo-t16y.3`) — deterministic composition over EXISTING real reads, zero new backend: header from the real date + active meso, the day face's hero from Train's today session (a rest-day card instead when there is none), the sport hero from the real sport schedule, the briefing's number facts from sleep/weight (no HRV — no source), check-in rows **read** today's server rows, fuel rows real since P5, reta day real since mezo-d94. Since **proactive B1.2** (`mezo-h4wp.2`) the **briefing prose is real too** (`useBriefing` → `useToday`): the generated card when present, the „Demo tartalom" static card only as the honest fallback. Since the daypart faces, real mode also renders a **layout-matched skeleton** while `useSleepGoal` resolves (§3, §9).
- **Backend:** ✅ check-in (`feature/biometrics/checkin`) only — **unchanged by the daypart re-composition, which was frontend-only** (no backend, no API-contract change). It lives **inside the biometrics feature** server-side (alongside weight/sleep), not a "today" package. The generated briefing is served by the `feature/proactive` package ([proactive.md](proactive.md)) — Today READS it via `useBriefing`, there is no "today" briefing backend; predictions remain 🟣 proactive-epic (P stage).

Driving design: **[`specs/2026-07-29-today-daypart-redesign-design.md`](../superpowers/specs/2026-07-29-today-daypart-redesign-design.md)** (the current structure — day model, card language, content map, component fate) + its **[ADR 0014](../decisions/0014-today-daypart-faces.md)**; historically [`specs/2026-06-03-mezo-today-design.md`](../superpowers/specs/2026-06-03-mezo-today-design.md) (Phase-1) and the honest-completion slice [`specs/2026-07-04-today-honest-completion-design.md`](../superpowers/specs/2026-07-04-today-honest-completion-design.md) + [`plans/2026-07-04-today-honest-completion.md`](../superpowers/plans/2026-07-04-today-honest-completion.md).

## 2. User-facing behavior

- **Open the app →** lands on `/today` (index route redirects there; `router.tsx:55-56`). Mock data renders synchronously, no spinner.
- **Header (gamified-header slice, `mezo-k7rn`, 2026-07-18):** `BrandRow` is **retired** — Today mounts the shared **`AppHero`** (`@/features/progression/components/AppHero`, `TodayPage.tsx:244-248`) at the top instead, passing Today's per-tab utilities as its `utilities` prop: **only** the ✨ `<Link to="/insights">` Insights entry point (the same ✨ affordance `BrandRow` used to carry, relocated verbatim). A 🔍 search chip sat beside it for a week and was **removed in `03d4e425` (2026-07-25)** — Today's `utilities` is one link. `AppHero` itself is domain-free identity/progression chrome — since the compact-header redesign (`mezo-ugqb`, 2026-07-18) a single sticky row (avatar + XP ring/level badge + equipped title + label-less 🔥/⚡/🪙 counters, `.apphero-chips` retired) — shared by all 5 sections (Insights joined the family the same afternoon, replacing its own `.pghead-np` header). Today owns only the `utilities` it passes in, nothing else about the hero.
- **The face navigator (`DayFaceStrip`, `TodayPage.tsx:344-350`).** Under the greeting sit three pills — 🌅 Reggel / ☀️ Nap / 🌙 Este — as a `role="tablist"` with one `role="tab"` + `aria-selected` each. Each pill shows its face's **open-item counter** (`N tétel`, or `✓ kész` when the face is done and nothing is open, or `—` when it has nothing at all) — **this counter is what replaced `DayArc` as the day-progress indicator**. The pill for the face the clock is actually in is marked `.now` **independently of which pill is selected**, so „hol tartok" and „mit nézek" never blur together; the selected pill is ink-filled (`.sel`). Because `aria-label` replaces a button's content as its accessible name, the counter is spoken there too (`„Reggel · most · 3 nyitott tétel"` / `„… · kész"` / `„… · nincs teendő"`), and the emoji stays decorative.
- **Which face renders — `?dp=reggel|nap|este`.** The selection is **derived from the URL, never mirrored into state** (the `TrainTodayPage` `?day=` precedent), so a reload, a back step and a tab re-entry can never disagree with what renders. With no `?dp=`, the face comes from the clock (`dayFace(new Date(), sleepGoal)`); `params.get('dp')` is `null` when absent and `''` when blank, and **both mean „the current face"** — neither may fall through to a parsed value (the `Number(null) === 0` trap that once pinned Train to Monday). An unknown value also falls back to the current face. Tapping a pill writes `?dp=` with `{ replace: true }` (face-hopping is a view switch, not a history step) and **deletes** the param entirely when the selected face IS the current one, so no stale param survives. `TodayPage.tsx:217-226`.
- **Act-anywhere.** Every action on a face works while that face is merely *selected*, not current — a retroactive `Pipa` on a morning habit at 22:00, an early evening-stack log at 16:00. This generalizes what `RoutineCard`'s midday-expand affordance (`mezo-km27`) existed for; the toggle is gone because retroactive logging no longer needs one.
- **Greeting (`GreetingHeader`).** One line: the day label + date + `Reta D{n}`, over a daypart-driven headline (`Szép reggelt` / `Szia` / `Szép estét`, `shared/lib/daypart.ts`). It keeps its own `daypartNow()` derivation — a *copy-tone* decision, deliberately not the face model (`dayFace.ts`), which is a *content* decision. `DayArc` is **gone from Today** (the pill counters carry its job); the arc lives on in the Napzárás „A napod íve" act ([ritual.md](ritual.md) §2).
- **🌅 Reggel (`FaceMorning.tsx`).**
  1. **`FaceHeroCard`** — the morning habit chain as an `ItemCard`: a `{done} / {total}` state label, a progress bar, and the chain's **first open step promoted** into its own `.fhc-next` row carrying that step's action (and its external `↗` link, e.g. the daily video). The remaining steps are **not** repeated as read-only pills — they are ordinary actionable rows in the `TodoCard` below, so a skipped middle step can still be ticked. Title flips to „Megvan a reggeled" when the chain is finished.
  2. **`BriefingCard`** — the same collapsed/expanded briefing behaviour as before, now dressed as an `ItemCard` with **no display title** (the prose IS the body, so `title=""`; the eyebrow tag carries `briefing.eyebrow`). Collapsed → a two-line `.brief-clamp` preview + `bővebben`; expanded → all paragraphs, the „Hivatkozott" refs row, the „Demo tartalom" label (real mode) or the confidence %, and `összecsuk`. **The day's numbers ride on it as `.metapill` facts** (`Alvás 7.2h · Súly 78.6kg · HRV 64ms`, fed from `useQuickStats()`) — this is where the retired „Ma eddig" `QuickStatsRow` landed.
  3. **The creed chip** (`IntentionBanner variant="chip"`) — a one-line `✦` + creed + `{n} / {cap}` counter + `+ Mai fókusz`, with one `◆`-marked row per live focus underneath. The creed text itself is a button opening `CreedSheet`; full editing stays in the sheets. See [intention.md](intention.md).
  4. **`TodoCard`** — the merged todo card (below).
  5. **„Ma még vár rád"** — a `.zoneline` section label over compact `ItemRow`s previewing the *later* faces' open items; **tapping one switches to that face** rather than acting on it. *This is the guidance the old screen had none of.*
  6. **`DoneFold`** — the collapsed `✓ Kész ma · N tétel · +N XP` row (below).
- **☀️ Nap (`FaceDay.tsx`).**
  1. **Hero** — the day's session as an `ItemCard` with its real **`Indítsuk`** CTA → `/train` (gym) or **`Logold`** (a sport session). The niggle warning renders as a `.warmstrip` child inside the card, and a stacked-day companion line as `.todaycard-note`. On a **rest day** (no workout and no `today:true` sport session) a `🌤️ PIHENŐ · Ma pihenőnap` card renders instead, offering **`Saját edzés`** → `CustomWorkoutSheet`. Session identity comes from `sportOf`/`SPORT_TAGS`/`SPORT_TITLES`/`SPORT_EMOJI`/`SPORT_TONE` (`features/train/logic/sportKinds`, `mezo-rhe5`), so a cross/TRX session reads as itself, not as volleyball.
  2. The creed chip, the **`TodoCard`**, the companion's midday note, an **„Este vár rád"** preview (evening items only), and `DoneFold`.
- **🌙 Este (`FaceEvening.tsx`).**
  1. **`WindDownBanner`** — unchanged behaviour (below), sitting above the ritual hero.
  2. **`RitualCard`** — the three-state Napzárás hero (below).
  3. **`TodoCard`** — the evening chain + the evening check-in + the evening stack + leftover quests. Rows whose act a hero above the list already owns are filtered out here — showing either again is exactly the duplication this redesign removed: the `ritual:day` item and the `evening_ritual` habit row, always (`OWNED_BY_RITUAL_HERO`), and the **`wind_down` habit row while the `WindDownBanner` is showing its own** (`mezo-mvb4.1`). That last one is **phase-dependent**: the banner carries the habit's row + `Pipa` only inside the **winddown** phase, so the filter fires only there — in `dim` (and outside the windows entirely) the banner draws no row and the `TodoCard`'s is the *only* affordance, which must stay reachable („act-anywhere"). Both surfaces read the phase from the same ticking `logic/useWindDownPhase.ts`, so „is the banner showing it right now?" has one answer. Unlike the morning face there is **no chain hero**: every evening step is already an actionable row, so nothing needs promoting.
  4. The **intention reflection** (`IntentionBanner variant="reflect"` — the question + `Igen`/`Részben`/`Nem`, or a `✓` done line) and the companion's closing note.
  5. **„Ahogy a nap telt"** — the day's completed rows with their summaries, closed by `Ma összesen +{dayXp} XP` (quest + habit + activity XP). **This retrospective IS the evening face's done surface, so `FaceEvening` mounts no `DoneFold`** — it would repeat the same rows.
- **The merged todo card (`TodoCard`, `mezo-j7u4`).** One card replaces three (`TodayQuestsCard` + `RoutineCard` + the standalone check-in and ritual sections): a `⚡ {done} / {total} kész` header, one progress bar, small-caps group headings (`REGGELI RUTIN · 4`, `NAPI KÜLDETÉSEK · 1`, `CHECK-IN · 1`, `FUEL · 2`, `ESTI RUTIN · 4`, `NAPZÁRÁS`) and uniform `ItemRow`s. Groups render in **first-appearance order**, which is the order `buildTodayItems` emits them (§3). The header's right cell is the **only route from Today into quest management** — `{done}/{total} · +{xp} XP ›` → `/me/growth`, inherited from the retired `TodayQuestsCard` header (reroll `Csere` + the why-lines stay Growth-only: Today = act, Growth = manage). A trailing `.tdc-note` carries the fuel plan's companion line, but **only on a face that actually has fuel rows**. The card ghosts (`null`) on an empty face.
- **Row actions.** A row's control is dispatched by `TodayPage`'s `act()` through the **same pure mappings the retired cards used** — `logic/questAction.ts` for quests, `logic/habitAction.ts` for habits — so nothing ever self-completes a quest or a DERIVED habit (ADR 0010). **A quest pill wears `questAction`'s own label, never a generic one** (`mezo-mvb4.1`) — the button has to say what it will do, because these are not all the same kind of act. Quest CTAs: `water_target` → `+250 ml`, an instant write that stays on Today (this is the one that makes the rule load-bearing: a pill reading „Naplózz" would make a silent mutation look like a navigation), `checkin_full` → `Check-in`, the first still-fillable slot's `CheckInSheet`, `activity_match`/ACTIVITY → `ActivityLogSheet` pre-bannered with the quest, and the rest navigate, each labelled with its destination (`Mérés`→`/me/weight`, `Alvás`→`/me/sleep`, `Fuel`→`/fuel`, `Főzés`→`/fuel/recipes`, `Edzés`→`/train`). Habit kinds: `check` (MANUAL `Pipa`), `nav`, `meal-sheet`, `sleep-sheet`, `intention-sheet` (`daily_intention` → `IntentionSheet`), `intention-reflect` (`intention_reflect` → `ReflectSheet`). A **fuel** row logs **in place** (`LogMealSheet`) rather than navigating — the retired `FuelTimelinePreview`'s `+ Log` chip. **No row ever shows a control this screen cannot serve:** `servableAction()` (`TodayPage.tsx:85-93`) strips the action from any such row, and a stripped habit picks up `habitHint`'s explainer so a button-less row reads as „this ticks by itself" rather than as broken (§9).
- **Ticking something.** A completed item leaves the open list entirely: on the morning/day faces it lands in **`DoneFold`** (`✓ Kész ma · N tétel · +N XP`, collapsed by default, expanding to `done` `ItemRow`s), and on the evening face in „Ahogy a nap telt". So a face always reads as „what is left", never as a mixed pile. Completing a whole chain fires a quiet `🌅 Tökéletes reggel` / `🌙 Tökéletes este` toast (`logic/useChainCelebration.ts`), and a completion's level-up rides the shared `useLevelUp` overlay.
- **Motion (`mezo-1khu`).** The face swap re-runs the entrance: `TodayPage` gives the `.faceswap` wrapper `key={selected}` so it remounts, and `data-dir` (`fwd`/`back`, derived from the outgoing → incoming face order) makes it read spatially — forward enters from the left, backward from the right (±14 px + a 10 px rise). The children stagger via an `:nth-child` ladder (70 ms steps, capped at 490 ms with an open-ended `:nth-child(n+8)` tail). Everything is disabled under `@media (prefers-reduced-motion: reduce)`, structurally guaranteed by wrapping every `.faceswap` modifier selector in `:where()` (§9).
- **Wind-down banner (sleep slice C-éj, `mezo-d71m`; re-dressed onto `ItemCard` by `mezo-j7u4`):** on the **Este** face, above `RitualCard`, the **`WindDownBanner`** is a self-ticking (30 s) card whose surface is driven entirely by the current phase from the pure `logic/windDown.ts` (the single time source, computed off the **same `useSleepGoal()` wake/bed anchor `dayFace.ts` uses**): **dim `[bed−90, bed−60)`** → a „Esti ráhangolódás" card (dim below 30 lux / warm light / cool the room to ~18 °C, the Walker „+18% REM" evidence line, `🛏️ még {N}` to-bed pill); **winddown `[bed−60, bed)`** → a „Esti leállás" card that **carries the `wind_down` MANUAL habit's `Pipa` check** — it reads `useHabitDay(date)`/`useHabitActions(date)` over the same `['habitDay', date]` cache the face's own rows use (so the two stay in sync), and a completion's level-up rides the shared `useLevelUp` overlay (once `done`, the row flips to a „Leállás megvolt" confirmation); **night `[bed, wake−30)`** → the dark „Éjszakai mód" entry row (`.wdb-night`) linking to **`/me/sleep/night`** (the NightPage, [me.md §2](me.md)). Outside those windows (`phase === 'none'`) and in real mode before the goal resolves it ghosts (`null`) — no flash. Wrap-aware, so a past-midnight bed works. The same `windDown.ts` window (`isDarkWindow` = any phase active) also drives the circadian auto-theme ([`_platform-design-system.md`](_platform-design-system.md)).
- **Daily closing ritual — `RitualCard` (`mezo-ilsj`; re-dressed onto `ItemCard` by `mezo-j7u4`):** the Este face's hero — a three-state entry point into the sleep-anchored `/ritual` 5-act closing flow: **waiting** (a `MÉG VÁR` state label + the opening time, e.g. „21:15-kor nyílik — villanyoltás 22:30"), **open** (a „Zárjuk le a napot" CTA), **done** (a logged card). Derived from `useRitualDay` + the pure `ritualWindowState`; the `?ritual=waiting|open|done` URL param wins over the derived state (the `?day=` demo precedent). The window only nudges — a direct `/ritual` visit always works, any time today. Full behavior: [ritual.md §2](ritual.md).
- **Habit chains (`mezo-d1jb`).** Both chains are now `ItemRow`s in their own face's `TodoCard` (`REGGELI RUTIN` on Reggel, `ESTI RUTIN` on Este) — `RoutineCard` is gone. Each row shows the habit title + its `anchorCopy` cue as the subtitle, MANUAL rows a `Pipa` and DERIVED rows a `Logolás` that taps through to the underlying log surface. A habit with a `linkUrl` renders a small trailing `↗` **next to** its action, never instead of it. While a habit write is in flight, habit controls are **withdrawn** rather than dimmed (`habitPending` → the pill falls back to inert copy), so a double-tap cannot fire a second mutation; quest and fuel rows on the same card stay tappable. Domain doc: [habit.md](habit.md).
- **Scenario deep-links** (no production UI — URL search params only):
  - `?dp=reggel|nap|este` → pins the rendered face (parsed in `TodayPage` itself, not in `useTodayScenario`). Unknown/blank → the current face.
  - `?day=good|medium|rough` (default `medium`, parsed by `useTodayScenario`). `rough` → AnchorMode full-screen replaces the whole screen, **above** the daypart model.
  - `?niggle=on|off` (default `on`) → toggles the amber niggle strip inside the Nap face's session hero.
  - `?vulnerable=on|off` (default `off`) → shows the "sebezhetőbb hangnem" `VulnerabilityCard`, which sits in the fixed chrome (above the swapping faces) so tone lands before demands on every face.
  - `?retaDay=N` (1–7, clamped; top priority in both modes) → moves the greeting line's `Reta D{n}` text. With no override, the **base** is the derived medication cycle in real mode (`useMedication().cycle.retaDay`, falling back to `today.retaDay = 3` when 0/no-dose) and `today.retaDay = 3` in mock mode (mezo-d94).
  - `?ritual=waiting|open|done` → overrides `RitualCard`'s derived window state.
- **Check-in.** The 4 canonical slots (`06:30 · 10:00 · 14:00 · 20:00`) are now **one `ItemRow` per slot, bucketed onto the face its own clock time falls in** — the standalone „Hogy vagy ma?" `.beats` strip is gone. Tapping a row's `Koppints` opens `CheckInSheet` for **that slot's index**, a 5-step wizard: four dimensions — Energia / Stressz / Testi / Mentális tisztaság — on a 1–10 scale with auto-advance, each showing a reactive "Mezo · azonnali olvasat" observation (`CheckInObservation`), then a summary + optional one-line note. **Mentés** → the slot flips optimistically and, in real mode, `POST`s then invalidates the day query. In **real mode the rows also READ** `GET /api/biometrics/checkin?date=today` (Slice T): saved slots survive a reload; a slot with no server row derives its state from wall-clock — current window → `now`, past → `skipped`, future → `pending`. Only a **`done`** slot leaves the open list (into `DoneFold` / the retrospective). **A `skipped` slot stays OPEN and stays fillable** (`mezo-mvb4.1`): its window has passed, but `CheckInSheet` posts `state: 'done'`, so a backfill lands — exactly what the retired `CheckInStrip` allowed by making all four slots tappable. It never pretends it was on time, though: the row reads **„Hogy voltál?"** with a **`{HH:mm} · elmaradt`** subtitle and a **`Pótold`** pill instead of `Koppints`. (This is what the „`skipped` → `missed`" mapping got wrong: nothing on the screen renders a `missed` item, so from 10:00 onward an unfilled morning slot was invisible *and* unreachable, and the `bio_checkin_full` quest — threshold 4 — became unwinnable for the rest of the day.)
- **Cross-slice navigation:** the Nap face's session hero CTA → `/train`; `TodoCard`'s header link → `/me/growth`; a fuel row opens `LogMealSheet` in place; the `AppHero` utilities Today passes in carry a direct `<Link to="/insights" aria-label="Insights">` ✨ button (`TodayPage.tsx:246`) — since the Napív S3 removal of `InsightsTeaser`, this ✨ is the **only** way Insights is reached from Today (the bottom tab bar also dropped its Insights tab, `mezo-8141`).
- **AnchorMode:** the `Kilépés` chip calls `navigate('/today')`, dropping the `?day=rough` param and returning to the normal screen.

## 3. Architecture & data flow

The single FE↔data boundary is `frontend/src/data/hooks.ts`. Since Slice T every Today hook is dual-mode via `isMockMode()`: mock returns the byte-identical Phase-1 statics; real **composes existing real reads** (`buildDayPlan` precedent — no new backend). Since the daypart faces, the shape of the screen is: **`TodayPage` holds every hook, two pure logic modules turn that into a day model + a normalized item list, and the face components are presentational.**

### The two logic modules

**`features/today/logic/dayFace.ts` — the day model (`mezo-ly8c`).** Pure, no React. Derives the three windows from `useSleepGoal()`'s `wakeTime`/`bedTime` — **the same anchor `windDown.ts` and the Napzárás window use, so the app has one clock and no drift.**

| Face | Window | Example (wake 06:45, bed 23:15 — the mock seed) |
|---|---|---|
| 🌅 `reggel` | `[wake − MORNING_LEAD_MIN, wake + MORNING_SPAN_MIN)` | 06:15 – 11:45 |
| ☀️ `nap` | `[wake + MORNING_SPAN_MIN, bed − EVENING_LEAD_MIN)` | 11:45 – 19:15 |
| 🌙 `este` | `[bed − EVENING_LEAD_MIN, wake − MORNING_LEAD_MIN)` | 19:15 – 06:15 |

- Constants: **`MORNING_LEAD_MIN = 30`** (imported from `windDown.ts`, not re-declared), **`MORNING_SPAN_MIN = 300`**, **`EVENING_LEAD_MIN = 240`**. `MORNING_LEAD_MIN` is deliberately the exact minute `windDownPhase`'s `night` ends, so the day closes a circle: `night → reggel → nap → este (dim → winddown) → night`. The `dim`/`winddown`/`night` sub-phases live **inside** the `este` face and keep their own behaviour.
- All math is **minute-of-day and wrap-aware** (a past-midnight bed works), mirroring `windDown.ts` — `toMin`/`wrap`/`inWindow` are duplicated from it because that module does not export them.
- **Exports:** `dayFace(now, goal)` (which face the clock is in), `faceWindows(goal)` (the three `{start, end}` minute ranges), `faceOf(hhmm, goal)` (which face an item anchored to a time belongs to), plus `DAY_FACES`/`FACE_LABEL`/`FACE_EMOJI`.
- **Degenerate-anchor guard** (`dayFace.ts:32-36`): with an extreme sleep goal the evening window can open before the morning one closes. `faceWindows()` then keeps the morning span intact and collapses `nap` to **zero length** rather than letting it invert — `dayFace()` simply never returns `'nap'` at that anchor, but **every minute still resolves to a face** (`este` is the fallback and the only window guaranteed non-empty). See §9.

**`features/today/logic/todayItems.ts` — the normalizer (`mezo-ly8c`).** Pure: no React, no hooks, no `@/data/*`. Collapses **six sources** onto one `TodayItem` shape, buckets by face, deduplicates and partitions open/done. This is what kills defect 4 (the duplication).

- **`TodayItem`** = `{ id, source, face, status, tone, emoji, tag, title, subtitle, time, xp, group, action, linkUrl }`. `face: 'all'` means day-wide (open quests, rendered on **every** face — only one face is mounted at a time, so this is not visual duplication). `status: 'open' | 'done' | 'missed'`.

Separately, a `gym_session_done` quest is dropped whenever a session is present (it is already the hero). A **completed** item appears only in the done surface, never in the open list.

That last one is the **single predicate** behind both the `checkin_full` quest CTA's servability and the slot index `act()` opens for it, so the two can never disagree about what „a slot is available" means (`mezo-mvb4.1`).

## 6. How to use it (consume)

Mount the screen (already wired at `frontend/src/app/router.tsx:55-56`):

```tsx
import { TodayPage } from '@/features/today/pages/TodayPage'
// route: { path: 'today', element: <TodayPage /> }
```

```tsx
import {
  useToday, useCheckins, useTodayScenario, useFuelPreview, useQuickStats,
  useSleepGoal, useDailyQuests, useHabitDay, useRitualDay, resolveBriefing,

const date = localDateString()

const {
  today, user, briefing, briefingDemo,               // briefingDemo: true in real mode → honest label
  workout, workoutTime, prediction,                  // workout: Workout | WorkoutPlan | null (null = rest day)
  volleyballSessions, volleyballNote,                // prediction/volleyballNote: demo copy, null in real mode

const { visible: fuelSlots, nextStack } = useFuelPreview()
const stats = useQuickStats()                        // QuickStatItem[] — real: sleep+weight, no HRV

saveCheckIn(idx, { state: 'done', values, note, savedAt }) // optimistic; real also POSTs + invalidates the day read
```

Then turn that into the day model + the item list with the two pure modules (neither takes hooks):

```tsx
import { dayFace, DAY_FACES } from '@/features/today/logic/dayFace'
import { buildTodayItems, itemsForFace, openCountByFace } from '@/features/today/logic/todayItems'

const items = buildTodayItems({ quests, habits, checkins, fuelSlots, sessions, ritual, goal })
const current = dayFace(new Date(), goal)            // which face the clock is in
const selected = isFace(params.get('dp')) ? params.get('dp') : current   // ?dp= wins; null/'' ⇒ current
const { open, done } = itemsForFace(items, selected)  // includes the face:'all' day-wide items

```

`useTodayScenario` is safe to call anywhere under the router (it only reads search params), so scenarios can be driven by links: `/today?dp=este`, `/today?day=rough`, `/today?niggle=off`, `/today?retaDay=5`.

## 7. How to extend it

**Add a new TODO SOURCE (the common case — it should be rows, not a new card):**
1. Add a branch to `logic/todayItems.ts`'s `buildTodayItems` emitting one `TodayItem` per unit: bucket it with `faceOf(hhmm, goal)` (or `face: 'all'` for day-wide), pick a `tone` from `ItemTone`, set a `group` heading, and give it an `action` — carry the **raw domain object** for a source that has its own action mapping, or a `nav` route for one that does not.
2. If it can duplicate an existing row, add the pair to `DEDUP_PAIRS` (or an explicit skip, the `gym_session_done` precedent) and cover it in the dedup table test.
3. Wire the hook in `TodayPage.tsx`'s hook block and pass it into the `buildTodayItems` memo (mind the memo's dependency array).
4. Teach `act()` how to serve the action **and** `servableAction()` when it can't be served — **both**, or the row shows a pill that does nothing (§9).
5. Extend `logic/todayItems.test.ts` (bucketing + dedup) and `TodayPage.dispatch.test.tsx` (the dispatch + the pill-less case).

**Add a new CARD to a face** (only when it genuinely isn't a row):
1. Build it on `shared/ui/ItemCard` — do **not** introduce a new card idiom; that is the defect ADR 0014 exists to fix. Card-local prose goes in the `children` slot (`.todaycard-note`/`-tip*`/`.warmstrip`).
2. Put it under `features/today/components/`, keep it presentational where possible (the faces receive pre-derived props), and mount it in the face(s) it belongs to — **not** in `TodayPage`, unless it is fixed chrome above the `.faceswap` wrapper.
3. Remember the two early returns in `TodayPage` (`anchorMode`, then `sleepGoalPending`) — anything below them renders on neither branch.
4. If it changes a face's top-level child count, re-check `TodaySkeleton`'s two-hero assumption (§9) and regenerate that face's visual golden.
5. Add a colocated `*.test.tsx`.
Follow [`specs/2026-07-29-today-daypart-redesign-design.md`](../superpowers/specs/2026-07-29-today-daypart-redesign-design.md) + [ADR 0014](../decisions/0014-today-daypart-faces.md).

**Change the day model** (the face windows): the constants live in `logic/dayFace.ts` (`MORNING_SPAN_MIN`, `EVENING_LEAD_MIN`) — but `MORNING_LEAD_MIN` is **imported from `windDown.ts`** on purpose, so the `night → reggel` handover stays a single value. Any change here needs `dayFace.test.ts`'s boundary + wrap + degenerate-anchor cases re-checked **and** all three `today-*` visual goldens regenerated (a window shift can move an item to another face).

**Promote a mock Today section to a real backend (the check-in is the working template):**

## 9. Decisions, gotchas & deferred

- **Decisions:** the current structure is **[ADR 0014 — Today is three sleep-anchored daypart faces, in one card language](../decisions/0014-today-daypart-faces.md)** (why faces, why the sleep anchor, why the four context blocks dissolve, the four rejected alternatives, the four accepted trades) over [`specs/2026-07-29-today-daypart-redesign-design.md`](../superpowers/specs/2026-07-29-today-daypart-redesign-design.md). Earlier layers: the Phase-1 design in [`specs/2026-06-03-mezo-today-design.md`](../superpowers/specs/2026-06-03-mezo-today-design.md) and the honest-completion decisions (check-in read-model, briefing „Demo tartalom" label vs trim, HRV cell drop, demo params surviving real mode) in [`specs/2026-07-04-today-honest-completion-design.md`](../superpowers/specs/2026-07-04-today-honest-completion-design.md). Tone throughout: ADR [0010](../decisions/0010-gamified-growth-xp-feedback-not-payment.md) — nothing on Today ever self-completes a quest or a DERIVED habit, and an expired item dims quietly rather than turning red.
- **GOTCHA — `logic/dayArc.ts` OUTLIVED its component.** `DayArc.tsx` was deleted from Today (`mezo-j7u4`; the `DayFaceStrip` pill counters are the day-progress indicator now), but the module stayed: the Napzárás „A napod íve" act (`features/ritual/components/DayStoryStep.tsx:2`) reprises the same Bézier and imports `buildArcPoints`/`pointXY`. **Do not delete the logic file with its namesake**, and do not "clean up" its test. The file carries this warning in its own header comment. Only `arcProgress` (the sun-dot cursor — the one export `DayStoryStep` does not use) was dropped, in `mezo-1khu`.
- **GOTCHA — the degenerate-sleep-anchor guard in `dayFace.ts`, and what actually protects it.** With a very short waking day (wake 06:00 / bed 10:00) the evening window opens *before* the morning one closes. `faceWindows()` (`dayFace.ts:32-36`) detects this and lets `nap` collapse to **zero length** rather than invert, and `faceForMinute` also skips a zero-length `nap` window explicitly (`dayFace.ts:49`, `w.nap.start !== w.nap.end`). **The never-`undefined` invariant is NOT what guards either half** — `faceForMinute` ends in an unconditional `return 'este'` (`dayFace.ts:50`), so every minute resolves to a face no matter what the two window checks do, and `inWindow` already treats `start === end` as the empty window, which makes `:49`'s length check *redundant* with it. What the guard really buys is that `este` stays the fallback **instead of `nap` swallowing the collapsed range**: without `faceWindows`' `napEnd` clamp the `nap` window would invert and `inWindow`'s wrap branch would claim most of the day for `nap`. **The assertion that actually goes red is `dayFace.test.ts:80`'s `expect(seenFaces).toContain('este')`, at the wake 06:00 / bed 10:00 anchor** — the only anchor in the file where the clamp actually fires (at wake 06:00 / bed 22:30 it never triggers, and at the „2h awake" 06:00/08:00 anchor `eveningStart = 240` is *outside* the morning window, so `nap` legitimately wraps — see `dayFace.test.ts:105-115`). So: `:49` is **belt-and-braces and provably redundant** (removing it reddens nothing), the `faceWindows` clamp is **live code** (removing it reddens the `'este'` assertion), and neither is protected by the every-minute assertions. Verify against `:80` before touching either.
- **GOTCHA — the dead-control class, and the honest limit of the net that closes it.** Three separate review rounds on the re-composition each found rows labelled with an action the new host could not serve — a pill that does nothing — and **every one of them passed a green suite**. It is closed at class level by **`servableAction()`** (`TodayPage.tsx:85-93`) inside the `items` memo, which strips the action from any row this screen cannot serve, in one place, for every source: a habit whose `habitAction` is `'none'` (a pending DERIVED habit with no log surface, e.g. `bed_on_time`, which *tomorrow's* sleep log decides), a quest whose `questAction` is `null`, and a `checkin` quest on a day where every slot is already done or skipped. A stripped habit row picks up **`habitHint`**'s explainer as its subtitle, so a button-less row reads as „this ticks by itself" rather than as broken. `act()`'s own early returns are belt-and-braces, not the guard — **any future action kind must be handled in BOTH places.** The class net is backed by a real-fixture test that clicks every control on all three faces and requires an observable effect. **Its honest limit: it cannot detect a *missing* `questAction` mapping** — the mock fixtures contain no such quest, so nothing renders for the net to click. That gap is covered by targeted dispatch tests instead (`TodayPage.dispatch.test.tsx`'s „an unmapped metric renders NO button" case, written against the production `growth_intention` quest, whose `intention_focus_set` metric `questAction.ts` does not map). Two layers, neither oversold.
- **CODEBASE-WIDE TEST GOTCHA — a just-typed string is never proof a write landed.** jsdom reflects a **controlled `<textarea>`'s live `.value` into its `.textContent`**, and `Sheet.tsx`'s close animation keeps the sheet **mounted ~300–380 ms** (`EXIT_MS + 80`) after the submit click. So `findByText('<the text I just typed>')` can match the *still-open textarea* rather than the saved output — and would pass even against a no-op writer. **Assert the rendered destination** (a container class, a count, the row that should now exist), never the typed string alone. `IntentionBanner.test.tsx:77` is such a decorative assertion (harmless — lines 78-79 carry the real proof). This bites any test that types into a sheet and then looks for the text, not just Today's.
- **GOTCHA — one fixed skeleton cannot match all three faces.** `TodaySkeleton` reserves **two** hero cards, which is exactly `FaceMorning` (chain hero + briefing, both unconditional) and the common `FaceEvening` shape (`WindDownBanner` + `RitualCard`, whenever `windDownPhase !== 'none'` — true for most of the evening face's span, given `EVENING_LEAD_MIN` 240 vs. `DIM_LEAD_MIN` 90). `FaceDay` always renders one, and so does the first ~150 min of `FaceEvening`, so those shrink by ~150–160 px on the swap. Two cards is the honest majority match, chosen over a perfect match for one face; the count is asserted by `TodaySkeleton.test.tsx` so it cannot silently drift back to one. **The header half of the same problem is fixed, not traded** (`mezo-mvb4.1`): the skeleton used to render *instead of* `AppHero`, so the sticky 65 px identity row was inserted above everything on resolve — a *downward shove*, not a shrink, and undocumented. `TodayPage` now renders the same `appHero` element in both branches (§3).
- **Accepted trades (approved, not defects — ADR 0014 records all four):** the four check-in slots now live on **separate faces** (the at-a-glance „Hogy vagy ma? 2/4" strip is gone by intent); **„Ma eddig" survives as the briefing card's facts on the morning face only**; **`ritual:day`'s `nav` action is unreachable** because the `RitualCard` hero owns the route (the hero *is* the route, soft-gated per ADR 0010; `/ritual` stays reachable by URL); and the **real-mode level-up double-fire inherited from `RoutineCard`** (the mutation's resolved payload plus the invalidated day read's cached payload) is unchanged — parity over a silent behaviour change.
- **GOTCHA — the sport hero never renders in MOCK mode's default screen.** `TodayPage` does `volleyballSessions.find(s => s.today)`, and no mock session carries `today:true` — the sport path is exercised in mock only via tests. In **real mode** `today:true` derives from the weekday in `toSportSchedule` (`trainHooks.ts`), so on a real schedule day the Nap face's hero is the workout if there is one and the sport session otherwise.
- **GOTCHA — one session object, two roles: the row and the hero (`mezo-mvb4.1`).** `TodayPage` authors the day's sessions **once** (`sessions`, a `DaySession[]` = the normalizer's `SessionItemInput` + the hero's `ctaLabel`), and the array's **order is hero precedence**: the gym session wins, a sport session heroes only on a rest day. The Nap hero is that same object (`heroCardOf` — the session minus its id, plus the CTA handler), and **its item is filtered out of every face's rows by ID**, not by `source`. Two bugs lived in the earlier shape, both from the hero and the row being independent computations over the same data: a real **early gym slot** (real mode schedules 07:30, so this was the default day — mock hides it because `data/today/today.ts` pins `workoutTime = '17:00'`) rendered as an inert `GYM` row on **Reggel** *and* as the Nap hero with a different eyebrow and a CTA the row lacked; and on a **stacked day** the `source === 'session'` filter swept away the session that is *not* the hero, so a 17:00 sport session next to a gym day had no surface at all (`later` only carries `este`). Now: the promoted session's **face follows its hero** (it is `nap` whatever its clock time, because `FaceDay` is where it renders), so an early gym is previewed on Reggel as a „Ma még vár rád" row that jumps to Nap, and every non-hero session is an ordinary — actionless, informational — row on its own face, carrying its time, duration, court and role.
- **GOTCHA — the mock-mode water CTA never completes the quest.** The `+250 ml` row action updates the fuel ring in mock mode, but the mock quest day is a static seed (no evaluation), so the row stays `offered` — the same accepted demo limitation as the deterministic activity classifier. Real mode completes it on the invalidated re-read.
- **GOTCHA — after midnight the evening face writes to the NEW day's rows.** Every date-keyed hook uses `localDateString()`, so once the wall clock passes midnight (with a past-midnight bed the `este` face and the winddown window straddle it) a `Pipa` writes to the *new* day's `habit_day` row. Deliberately consistent with `WindDownBanner` and the pre-faces `RoutineCard` — the local-date string, never a UTC slice.
- **GOTCHA — `useToday()`'s meso fields (`today.mesoPhase`, `user.weekInMeso`, `user.dayInWeek`, `user.mesoLabel`) are unconsumed by any Today component** since `DateMesoHeader.tsx` was removed (`mezo-8141`) — kept on the `TodayData` shape only for signature stability (Train still reads the equivalent data from `useTrain()` directly).
- **GOTCHA — `briefing.tone` is dead data.** Set in `briefingVariants` (`energetic` / `supportive`) but `BriefingCard` never reads it. (The only consumed `tone` is the in-sheet `CheckInObservation` tone, computed locally.)
- **GOTCHA — the niggle strip is a mock-only surface.** Its copy renders from `workout.niggleWarning.detail` (the human-authored provenance text), but real workouts (`toWorkoutPlan` in `trainHooks.ts`) never set `niggleWarning` (a Phase-3 AI extra), so the strip never renders in real mode regardless of copy source.
- **`useInsightsTeaser` + `InsightsTeaserItem` were DELETED in Napív S8** (`mezo-mifi`, 2026-07-15): orphaned since the S3 removal of `InsightsTeaser.tsx` (`mezo-8141`), they are gone from `todayHooks.ts`, the `data/hooks.ts` barrel, and `types.ts`. The `usePatterns` import they pulled into `todayHooks.ts` went with them.
- **Real-mode check-in derivation:** a past slot with no server row renders `skipped` — an honest "missed", not `pending`; the current window is `now`; the rows reconcile with the server after every save (invalidate), so multi-device/day-reload states converge.
- **Local-date correctness:** every day read + `saveCheckIn` use `localDateString()` (`Intl en-CA`, local tz) — deliberately not UTC slicing, so evening entries don't shift to the next day. See `shared/lib/dates.ts`.
- **Scenario duplication:** `useTodayScenario` is called in both `TodayPage` and `AppLayout`; both must derive `anchorMode` consistently for the warm canvas and the content to match.
- **Known console noise (pre-existing, `mezo-edrv`):** `useGoal`'s queryFn-less `['weightLog']` read-only query floods the console with TanStack errors on every Today load (mounted via `useFuelTimeline`); present before Slice T on the baseline too.
- **Generated briefing shipped (proactive B1.2, `mezo-h4wp.2`).** The briefing card is real in real mode (`useBriefing` → `useToday`, `briefing: Briefing | null`, fallback at `TodayPage.tsx:359`); the „Demo tartalom" static card is only the honest fallback (loading / 404 / switch off) and the mock-mode card. `resolveBriefing` + `briefingVariants` shape ONLY that fallback, never a generated briefing. `Briefing.confidence` went optional to model the server shape. Full behavior + backend in [proactive.md](proactive.md).
- **Deferred / follow-ups:** `FaceMorning`/`FaceDay`/`FaceEvening` have no colocated tests (§8); `shared/ui/ItemCard.tsx` imports `DoneBar` from `@/features/train/components/DoneBar`, so a `shared/ui` file reaches into a feature (inherited, not new — filed to move `DoneBar` into `shared/ui` rather than widening the re-composition); `questAction.ts` does not map `intention_focus_set`, so the `growth_intention` quest is honest but CTA-less (filed). Proactive-epic: real predictions (`prediction` stays null), real niggle/vulnerable sources, AnchorMode triggered by real signals, HRV (needs a data source first). (`QuickInputSheet` was re-mounted by the Napív redesign, `mezo-8141` — see [_platform-design-system.md](_platform-design-system.md).)
