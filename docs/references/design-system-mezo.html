Typography

Two type families: Geist for all UI, numerals, headings, and the Coach voice (in 200 ultralight). Fraunces italic at variable opsz for soft meta-text — meal source-lines, empty-state subtitles, AI insight callouts. Numerals always tabular; large hero numbers at weight 200 with -0.04em tracking.

MOBILE_UX role mapping · which design-system token = which MOBILE_UX role
MOBILE_UX §6.1 defines 5 typographic roles with size ranges. Each design-system token maps to one MOBILE_UX role. Sizes outside divisible-by-4 are only permitted where the role range explicitly allows them (Title 16–22 covers 22; Display 32–57 covers 56) — every other size is divisible by 4. Eyebrow/Overline is a documented exception: 12px is allowed only with uppercase + 0.18em+ tracking, never for sentence-case body text.

Colors · 12 UI roles + data-viz exception

UI palette (MOBILE_UX §7.1 cap): 1 primary (coral) + 1 secondary (warm ink) + 1 accent (gold) + 4 semantic (success / warning / error / info via primary-soft) + surface scale + text scale = ~12 logical roles. Each brand/status role is exposed as a 5-stop ramp (bg → soft → base → hover → deep) so the same role works across surfaces — these stops do not count as separate UI roles.

Data-viz exception: the 7 macro colors and 5 halo colors are reserved for charts, heatmaps, and progress visualisations only — they are outside the §7.1 UI cap and must not be used for buttons, badges, links, or surface backgrounds. On top of the source DS's 52 variables the Mezo edition adds the 6 domain accents (--dv-*, see Domain accents), the CTA gradient tokens (--cta-g1/g2, --gradient-cta, --shadow-cta), and a full dark override block (see Dark mode · Pulse). Every UI surface uses a token, never an inline hex.

Dark mode · „Pulse" warm graphite

Mezo ships a 3-mode theme: light (default, this document's ramps), dark „Pulse" (:root[data-theme="dark"]), and a circadian mode that resolves to light or dark by the time of day and re-tints the sky band (the CircadianTheme resolver — an app-side extension, see Mezo extensions). Every ramp has dark stops; the swap is token-level — components never branch on theme. Two inversions to internalise: (1) bg/soft darken into tinted graphite while base lifts (coral #FF6B4A → #FF7E5C); (2) deep lifts lighter than base — in both themes „deep" stays the stop you write text with (dark coral text = #F0966B, never #A84A26 on graphite). Surfaces are warm graphite (#191614 / #221E1B / #2A2521), ink becomes warm cream (#F5EFE6), shadows collapse to borders (--card-elevation: none — depth via --divider hairlines), and halos drop to ~60% alpha over the graphite page.

Motion rules:
  • Default for any state change: 250ms / ease-out. Buttons, alerts, focus, chip toggle.
  • Continuous loops (halo float, twinkle, breathing) cap at 6s and ≤5% transform — must NOT distract.
  • prefers-reduced-motion: disables every loop + reduces sheet/modal slide to opacity-only fade. Focus ring stays.
  • Tap feedback: scale(0.96) on active, 150ms. Always reverts on release.
  • Page transitions: duration-normal (250ms) slide + fade for full-page navigation, same 250ms fade for tab swap. Hard cap: 300ms per MOBILE_UX §15 perf budget — never use duration-slow for page-level navigation.
  • Always use var(--duration-*) + var(--ease-*) tokens — never inline hardcoded values.

Accessibility

Mobile-first means thumbs-first. Every interactive element ≥ 48×48 dp (MOBILE_UX §3 Rule 4 + §13.1 — "legbiztosabb"), coral focus ring on every focusable, semantic HTML + aria-labels for icon-only controls. Color contrast min. AA, aim AAA for body text.

Accessibility rules:
  • Tap target: minimum 48×48 dp hit zone for any interactive element (MOBILE_UX §3 Rule 4). 44 pt acceptable on iOS-only. 24 px is the WCAG 2.5.8 absolute floor — never go below it. Expand padding if visual is smaller.
  • Focus ring: 3px coral @ 32% (rgba(255,107,74,0.32) = --shadow-focus; Pulse: rgba(255,126,92,0.38)) + 1px solid primary.base border. Use :focus-visible only — not on mouse click.
  • aria-label on every icon-only button (FAB, IconButton, BottomNav tabs).
  • aria-current="page" on the active BottomNav tab.
  • Color contrast: AA minimum (4.5:1 for body, 3:1 for UI). Aim AAA (7:1) for body text. Verify with webaim.org.
  • Don't rely on color alone: success/warning/error must also have text or icon distinguishing them (we use leading "●" + label).
  • prefers-reduced-motion: respect via @media (prefers-reduced-motion: reduce) — disable continuous loops, reduce slide animations to opacity fades.
  • Semantic HTML: <button> for actions, <a> for navigation. Never <div onclick>.

Breakpoints · responsive scaling

Mobile-first by default — every component is designed for 380px portrait phone. These breakpoints handle tablet + desktop fallback (mostly for the Me/Profil + Insights surfaces, plus future iPad use). Don't add desktop-only features — every primary flow must work on phone first.

4 stops · mobile → tablet → desktop → wide
bp-base 0+ Mobile-first default. Container: 100% — 16px page padding-x (sp-4) per MOBILE_UX §4.5 compact. Stack everything vertically.
bp-tablet ≥ 768 iPad portrait. Container: max 720px. 2-col grids OK (StatCards, MealCard pairs). BottomNav still active.
bp-desktop ≥ 1024 Laptop / iPad landscape. Container: max 960px. BottomNav swaps to side rail (future). 3-col grids for Insights.
bp-wide ≥ 1440 Desktop wide. Container caps at 1200px. Center the content; the page never feels stretched. Insights gains a wider multi-col layout.
Breakpoint rules:
  • Always design at 380px first. Tablet + desktop are progressive enhancement.
  • Container max-widths: none → 720 → 960 → 1200. Use max-width: var(--container-tablet) tokens.
  • Hero stays centered at all sizes. Typography scale doesn't change above tablet — content gets wider, type stays the same.

Anti-patterns · what NOT to do

The cheat-sheet of mistakes that creep in when devs reach for the keyboard before opening this doc. Each row: ✗ banned on the left, ✓ correct on the right, with the rule that connects them.

21 anti-patterns · always look here first
Rules 1–14 are token / pattern discipline (DS-internal). Rules 15–21 are the canonical MOBILE_UX §21 forbidden patterns — they exist as code-level guardrails for the rules in the mobile UX rulebook.
Rule 1 · Never inline a hex / rgba color. Use a token. The whole color system breaks the moment one component "knows" it's #d4a853.
✗ BANNED color: '#d4a853'; background: 'rgba(154,184,143,0.18)';
✓ CORRECT color: var(--accent-base); background: var(--success-soft);
Rule 2 · Don't write font-style: italic inline. Italic = Fraunces (meta) only. Use the font-fraunces class. The Coach voice is NOT italic — it's Geist 200 ultralight.
✗ BANNED <span style="font-style: italic"> Az ütem pont ott van, ahol lennie kell. </span>
Coach quotes default to Fraunces italic — wrong vibe.
✓ CORRECT <CoachBubble> Az ütem pont ott van, ahol lennie kell. </CoachBubble> {/* renders Geist 200 / 22 / -0.02em */}
Rule 3 · Never invent a z-index number. Pick from the ladder. z-index: 9999 means a battle is already lost.
✗ BANNED z-index: 9999; z-index: 100; z-index: 12345;
✓ CORRECT z-index: var(--z-modal); /* 60 */ z-index: var(--z-toast); /* 70 */ z-index: var(--z-tooltip); /* 80 */
Rule 4 · Empty number input must STAY empty. Never auto-fill 0 when the user clears a field. Parent state is number | null, never just number.
✗ BANNED <input type="number" value={weight} onChange={e => setWeight(parseInt(e.target.value) || 0)} />
User backspaces → field jumps to 0. Maddening.
✓ CORRECT <NumberInput value={weight} onChange={setWeight} // accepts null />
Local string state, commit on blur.
Rule 5 · Tappable elements are <button> or <a>. Never <div onClick> — breaks keyboard, screen readers, focus.
✗ BANNED <div className="card" onClick={open}> Étkezés naplózása </div>
✓ CORRECT <button type="button" className="card" aria-label="Étkezés naplózása" onClick={open}> Étkezés naplózása </button>
Rule 6 · Tap target ≥ 48×48 dp. MOBILE_UX §3 Rule 4 picks the strictest of the platform thresholds (Apple 44 pt / Material 48 dp / WCAG 24 px) — we ship 48 universally. If the visual is smaller (a 16px close icon), expand the hit zone with padding.
✗ BANNED <button className="w-6 h-6"> <X /> </button>
24×24 hit zone — fat-fingers everyone.
✓ CORRECT <button className="w-12 h-12 grid place-items-center"> <X className="w-4 h-4" /> </button>
48×48 outer · 16×16 visual.
Rule 7 · Use motion tokens. Never write a literal 200ms or 300ms — pick from the duration scale.
✗ BANNED transition: all 200ms ease; animation: pulse 0.3s linear;
✓ CORRECT transition: all var(--duration-normal) var(--ease-out); animation: pulse var(--duration-fast) linear;
Rule 8 · Never re-implement a canonical primitive inline. If you find yourself building a Tabs / FAB / SectionHeader / EmptyState from scratch, you missed the design system. 11 such duplicates just got merged — don't add them back.
✗ BANNED function MyOwnTabs() { ... } function FabPlus() { ... } function CategoryChip() { ... }
✓ CORRECT import { Tabs } from '@/shared/ui/Tabs'; import { Fab } from '@/shared/ui/Fab'; import { Chip } from '@/shared/ui/Chip'; // deep absolute imports — no barrels // (frontend_conventions.md)
Rule 9 · The coral CTA gradient has ONE definition (--gradient-cta). Don't re-paint linear-gradient(135deg, #FF7A55, #FF5B36) in every page.
✗ BANNED <button style={{ background: 'linear-gradient(135deg, #FF7A55, #FF5B36)', width: 56, height: 56, borderRadius: '50%' }}>+</button>
✓ CORRECT <Fab icon={<Plus />} onClick={openLog} aria-label="Gyors logolás" /> {/* background: var(--gradient-cta) — one source */}
Rule 10 · Always respect safe areas on mobile. Bottom-fixed elements that ignore env(safe-area-inset-bottom) get covered by the iOS home indicator.
✗ BANNED <div className="fixed bottom-0 left-0 right-0 h-22"> ...nav... </div>
✓ CORRECT <div className="fixed bottom-0 left-0 right-0 h-22 pb-[env(safe-area-inset-bottom,0)]"> ...nav... </div>
Rule 11 · Never communicate state with color alone. A red border + green check are useless to ~8% of men. Always pair with text or icon.
✗ BANNED <div style={{ border: '1px solid #c4634b' }} />
Just a red border, no signal text.
✓ CORRECT <Alert tone="error"> ! Kalóriatöbblet — 540 kcal a cél felett </Alert>
Color + ! prefix + clear text.
Rule 12 · Use the radius scale. Don't pick 17px because "it looked right". Snap to 6/10/14/18/22/28/9999.
✗ BANNED border-radius: 17px; border-radius: 11px; border-radius: 23px;
✓ CORRECT border-radius: var(--r-xl); /* 18 */ border-radius: var(--r-md); /* 10 */ border-radius: var(--r-2xl); /* 22 */
Rule 13 · Icon-only buttons MUST have aria-label. Otherwise screen readers say "button". Useless.
✗ BANNED <button onClick={remove}> <Trash /> </button>
✓ CORRECT <button onClick={remove} aria-label="Étkezés törlése"> <Trash /> </button>
Rule 14 · Sheet snap heights are 40 / 65 / 95 vh. No 85vh, no 50vh. Pick one of the three.
✗ BANNED <Sheet height="85vh">...</Sheet> <Sheet height="50vh">...</Sheet>
✓ CORRECT <Sheet snap="md">...</Sheet> <Sheet snap="full">...</Sheet> <Sheet snap="sm">...</Sheet>
Rule 15 · Halation: never pair #000000 on #ffffff. Pure black on pure white vibrates on OLED screens and exhausts the eye in dark reading conditions. Use the off-black + off-white tokens. (MOBILE_UX §6.6)
✗ BANNED color: #000000; background: #ffffff;
High contrast, but burns retinas after 30 seconds.
✓ CORRECT color: var(--text-primary); /* #2B2118 */ background: var(--surface-card); /* #ffffff */
Off-black token; canonical app bg is surface.page #FBF6EF.
Rule 16 · Body text is ≥16px; label / caption max 14px. Going below 16 on body forces iOS auto-zoom on input focus and fails accessibility for older readers. 12px is reserved for three documented exceptions only: Overline (uppercase + tracking), form helper text under inputs, and bottom-nav tab labels. Rule 17 · Form fields always have a visible label. Placeholder-only inputs disappear once the user starts typing — they lose context, fail screen readers, and break re-entry. (MOBILE_UX §9.5 + §21)
✗ BANNED <input placeholder="Email" type="email" />
No label — when the field is filled, what is it?
✓ CORRECT <label>Email</label> <input type="email" placeholder="you@example.com" />
Visible label above; placeholder optional, only as example.
Rule 18 · Internal padding ≤ external gap. If a card's inner padding is bigger than the gap between cards, the visual grouping breaks — the user can't tell where one card ends and the next begins. (MOBILE_UX §4.4)
✗ BANNED <div className=" flex flex-col gap-3"> /* gap = 12 */ <Card className="p-6" /> /* padding = 24 */ <Card className="p-6" /> </div>
24 inside, 12 outside — cards visually merge.
✓ CORRECT <div className=" flex flex-col gap-6"> /* gap = 24 */ <Card className="p-4" /> /* padding = 16 */ <Card className="p-4" /> </div>
External (24) ≥ internal (16) — clear separation.
Rule 19 · Primary CTA stays in the green thumb zone (bottom third). Top-right corner is the red zone — hardest to reach one-handed. Reserve it for low-frequency or destructive actions. (MOBILE_UX §5)
✗ BANNED <AppBar> <Title>Új étkezés</Title> <Button variant="solid">Mentés</Button> </AppBar>
Save in top-right = repeated thumb stretch on a frequent action.
✓ CORRECT <Page> ...content... <StickyBottomBar> <Button variant="solid">Mentés</Button> </StickyBottomBar> </Page>
Sticky bottom CTA — green zone, one-thumb reach.
Rule 20 · Modal alerts give the user something to do. A single "OK" button is a dead end — it tells the user a thing happened, then forces a tap to dismiss. Either give a real action (Retry, View, Undo) or use a Toast that auto-dismisses. (MOBILE_UX §12.5)
✗ BANNED <Modal> Nem sikerült menteni. <Button>OK</Button> </Modal>
No path forward — user has to dismiss, then re-trigger.
✓ CORRECT <Toast tone="error" duration={6000}> Nem sikerült menteni az étkezést. <Button onClick={retry}>Újra</Button> </Toast>
Auto-dismiss + actionable retry, no forced confirm tap.
Rule 21 · Every tappable element has visible press feedback. Without ripple / opacity / scale on press, the user can't tell if their tap registered. The 100ms feedback is the difference between "responsive" and "broken". (MOBILE_UX §13.2)
✗ BANNED <button onClick={save}> /* no :active, no transition */ Mentés </button>
Button looks identical pressed and resting.
✓ CORRECT <button className="active:scale-95 active:opacity-80 transition-transform duration-fast" onClick={save}>Mentés</button>
Scale + opacity on press, motion-token duration.
