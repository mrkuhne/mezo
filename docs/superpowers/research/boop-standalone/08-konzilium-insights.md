# 08 — Konzílium, domain agents, insights, proactive, goal engine, csapatfal

Mapper: area 08 of `mezo-r36n9.9` (Boop standalone re-plan). Date 2026-11-10. Research only.

## TL;DR

1. The "konzílium" is real, large and working in code: 7 domain personas + a Szkeptikus + Mezo as chair, in `backend/.../feature/character` (203 Java files, 47 deterministic detectors, ~95 test classes). It is a *profile-building* system (claims about "who the user is"), NOT a "what should I do today" system.
2. Domain agents do NOT see raw data. Each expert sees only (a) the pre-digested signal sentences from its own deterministic detectors (nightly pass) and (b) its own observations (weekly/daily proposal). The only cross-domain / raw access is a bounded read-only tool session (personal records + period comparison, 8 tool calls) used in the cross-talk and verdict rounds.
3. Cross-checking is a fixed pipeline: propose (each expert, own evidence) → cross-talk (SUPPORT/CHALLENGE/NUANCE by other experts, up to 3 rounds / 4 participants / 6 calls) → Szkeptikus verdict (KEEP/WEAKEN/KILL, evidence only) → Mezo ruling (accept, dedupe, contradiction, sensitivity, chapter). Output = claim lifecycle changes (NEW/UP/DOWN/RETIRE/REVISE/MOVE) with a revision log and undo.
4. Production reality (shape only): 18 ACTIVE claims, all created 2026-09-06..09-20; **zero claim changes since 2026-09-20**. Nightly observation run is FAILED on 48 of 55 days since 2026-09-23 (failure_count capped at 5). Only 4 weekly + 1 monthly + 2 daily konzíliums ever; 3 of 6 daily council editions FAILED. The Szkeptikus call hits `CHARACTER_COUNCIL_QUOTA_EXHAUSTED` 17 times (vs 8 successes). The dossier is effectively frozen while the *csapatfal* (team wall) keeps producing daily (48 editions, 117 posts).
5. "Short/mid/long-term conclusions" are not one concept anywhere: horizons are scattered — day (day review, daily council, morning/midday/evening feed, team chat cases), week (weekly review, weekly suggestion, predictions, experiments, challenges, weekly konzílium), month/quarter (monthly deep read, quarterly pass in companion, memoir, life goals, goal engine segments). No component reads all of them together and emits a horizon-tagged conclusion.
6. The "live day re-examination + dynamic adjustment" (core 12) exists only in a narrow, rule-based form: composite flags (≈20 coaching rules) → team-chat "ügy" with offered one-tap actions (e.g. lighten tomorrow's workout). It is rule-driven with code-chosen text, not an LLM re-planning the day.
7. Goal engine (weight goal, TDEE, kcal segments, guards, Monday adaptive review) and life goals (PERMAH pillars scored from existing signals) are solid, deterministic, and testable; both are consumed by chat context as blocks/tools.
8. For Boop: reusable as-is = `/api/companion/pattern` (+decision), `/api/proactive/*` (weekly review, predictions, experiments), `/api/goals/*`, `/api/life-goals/*`, `/api/character/team-chat`. A "Boop konzílium" (core 9) is a new, smaller, day-scoped thing — the existing one is too slow, too expensive and too profile-centric to drive a live day view.
9. Strongest candidate to drop/shrink: the Gépterem / 47-detector transparency surface, chapters/maturity ring, claim-feedback UI. Strongest candidate to keep: detectors as a deterministic signal bank, the claim store + `[Karakter]` prompt block, flags + team chat.
10. Doc drift: `docs/features/insights.md` §1 still says every surface renders hand-authored mock copy (false; all tabs are real); `character.md` "Status" line still lists `weight-gap` as remaining while its own header says catalog is 47.

## 3. How it works

**Nightly → daily council (profile pipeline).** 02:50: `CharacterSignalReads.gather(owner, day)` builds a 14-day `DetectorInput` → `DetectorRegistry.runAll` → signals grouped by `expertKey` → for each expert ONE cheap-tier `CompanionLlm` call: system = `OBSERVATION_MARKER + systemPersona + outputContract` (0-3 observations `{text, salience 1-5, dimensionKeys}`, "only from the listed signals, invent nothing"), user = the day's signal summaries. Rows land in `character_observation` unconsumed. From 21:00 `CharacterCouncilService.run(owner, day)` (owner/day lease, advisory lock): takes up to `maxTopics`(6) pending observations + due follow-ups → **proposal round** (`KonziliumProposalRound`, per expert, persona + evidence + the expert's own active claims → 0-3 proposals `NEW|UP|DOWN|RETIRE|REVISE|MOVE` with confidence, sensitivity, observed/valid windows; the contract forbids inventing numbers and treats "FELHASZNÁLÓ VÁLASZA" lines as self-report) → **cross-talk** (`KonziliumCrossTalkRound`; invited relevant experts across dimensions, stances SUPPORT/CHALLENGE/NUANCE with a short argument, may call read-only tools `list_personal_sources`/`read_personal_records`/period comparison; caps: 3 rounds, 4 participants, 6 calls, 8 tool calls) → **Szkeptikus** (`KonziliumVerdictRound`, marker `KARAKTER-SZKEPTIKUS-FELADAT`: sees only the proposal + its evidence, no dossier, no peer stances; grade KEEP/WEAKEN/KILL + suggested confidence) → **Mezo/Integrátor** (five questions: duplicate? contradicts? how far may confidence move? belongs in a permanent person dossier (sensitive)? deserves a chapter?; may overrule Szkeptikus except sensitive KILL; new/up sensitive claims need an explicit KEEP/WEAKEN) → `ClaimLifecycle.applyAndBind` writes claim changes + `character_claim_revision` (undoable), marks portraits stale, observations consumed, `DAILY` conference + threads persisted; `CharacterCouncilBudget` caps (14 calls / 4 smart per cycle, 90 autonomous + 120 total per day, 30 units reserved for user replies).

**Weekly (Sun 19:30)** repeats proposal→cross-talk→verdict over the week's observations plus the week's daily discussions as "interpretation history, not new data"; **monthly** re-reads existing claims, can open/retire chapters; **bootstrap** reads the whole history once. Confirmation = Mezo accepting; "shown" = the conference/threads surface on the wall, claim list in Rólad/dimension pages, `[Karakter]` block in prompts. Users can answer per claim (`TALAL`/`NEM_IGAZ`/`PONTOSITOM`) which re-enters as a `user` observation; confidence uses `CharacterConfidenceWords`.

**Evening edition.** After the council settles (or at 23:30) `TeamEditionService` collects candidates (patterns, predictions, experiments, konzílium threads, team chat), selects/ranks, LLM-voices each post per character with fact guard, stores `team_edition(_post)`. Wall = `GET /api/character/feed`.

**Day-live (flags → chat).** `FlagSweepJob` hourly + event listeners evaluate composite rules over today's data; a raise opens a `team_chat_thread` (code picks owner, library text, offered actions); a clear resolves it; user replies are parsed by `TeamChatReplyService` (decision close/EXCUSED); "apply" executes an `AdviceMutationPort` (shorten tomorrow's workout, move sleep anchor, skip a sport slot…). No LLM chooses the adaptation.

**Horizons as built.** Day: flags/team chat, day review, morning/midday/evening feed, daily council. Week: weekly review, suggestion, predictions (next-week), challenges, weekly konzílium, goal Monday adaptive review. Month+: monthly deep read, memoir, quarterly companion pass, goal segments, life-goal 21-day arrow, experiments (3-28 d).

## 4. Quality assessment

Solid:
- Honest-data discipline is pervasive and tested: unknown ≠ zero, renormalised scores, `ProseNumberGuard`, `EditionVoiceGuard`, claim revision + undo, source-fingerprinted period comparison. Detector pre-filtering means the LLM only words what code already found.
- Separation of roles (Szkeptikus evidence-only vs Mezo dossier/duplication) is designed carefully (spec `2026-09-07-konzilium-verdict-roles-design.md`).
- Goal engine and life-goal scorer are deterministic with solid IT coverage (goal 44, lifegoal 21, proactive 122, character 95 test classes); FE dual-mode tests.
- Cost control: per-cycle and per-day LLM budgets, quota ledger.

Half-built / weak:
- **Frozen dossier in production.** `character_run` NIGHTLY: 7 SUCCESS vs 48 FAILED (2026-09-23 → 2026-11-09; failure_count 5 = max attempts); `character_claim`: 18 ACTIVE, last created 2026-09-20, zero `character_claim_revision` rows ever; WEEKLY konzílium rows stop at 2026-09-14; DAILY conferences only 2 (11-08, 11-09) and `character_council_edition` has 3 FAILED / 1 QUIET / 2 COMPLETED. `llm_log_history` shows `CHARACTER_COUNCIL_QUOTA_EXHAUSTED` on the skeptic call 17x (8 successes) and tool-budget exhaustion on cross-talk. Root cause of the nightly failures was not determinable from the DB (not a deploy-log check I could confirm); likely the budget/quota gating or a parse failure — needs an investigation before anything is built on it. The pass still logs successful "observe" calls through 2026-11-10, so the failure is probably downstream of generation (recording failure state when any expert fails or the quota trips).
- Output density is low and slow-moving: 18 claims across 7 dimensions (1-4 each), 1 evidence ref per claim, claim text ~80-170 chars, confidences 0.62-0.90 with the self-audit and discipline dimensions highest. The `physical` (doki) CORE dimension has maturity 0 and zero claims. 55 observations came from `drill` (logging/discipline) vs 4 from `taplalkozo`, 2 from `antropologus` — the team is lopsided toward logging-discipline signals.
- Quality of claims was not verifiable without reading personal content; by shape they are short single-evidence statements. Single-evidence claims at 0.8-0.9 confidence is a calibration smell (the Szkeptikus exists to catch that, but its call is the one hitting quota).
- The expert agents are not really independent agents with their own data access: they are persona prompts over deterministic detector summaries; "cross-checking" is one LLM acting as several personas on the same evidence, plus optional tool reads. It is a review process for slow profile claims, not a team that investigates today.
- Complexity: ~47 detectors, 7 dimensions, chapters, maturity ring, Gépterem (runs, detectors, data-source rounds), run log, quota ledger, claim feedback, reply discussions — most of it is operator/transparency UI the owner explicitly wants to leave behind.
- Patterns pipeline is healthier: 75 pattern rows, 18 statistical confirmed + 9 ai_hypothesis confirmed + 9 reflection confirmed, 1,792 pattern events, still producing as of 2026-11-10. Refutation exists (14 reflection refuted).
- Proactive output is consistent: 365 feed messages (morning 25 / midday 25 / evening 23 in the last 30 days), 9 weekly reviews, 10 memoirs, 20 predictions (6 validated, 7 missed, 7 pending), 7 experiments, 173 challenges (most outcomes empty/unrated), 5 diagnoses (last 2026-09-30), 28 team-chat threads (15 resolved, 9 expired, 4 open; Mezo-owned 12, Mocor 8), 93 flag raises (logging_gap and missed_workouts dominate), 48 editions / 117 posts (mostly `kerdes` and `ertekeles`).
- Doc drift: `docs/features/insights.md:25-44` "Every surface today renders hand-authored Hungarian mock copy" is stale (its own table below says all tabs are real). `docs/features/character.md` summary still says only `weight-gap` remains and mentions "Én-tab surface (not built yet, §9)" while later sections ship it. These docs are huge (proactive.md 4,201 lines, insights.md 1,674) and contain duplicated dated headers; not a reliable map without the code.

## 6. Gaps vs the owner's core

- **8 — one AI that sees ALL data, short/mid/long-term conclusions, chat with full context:** exists, needs fixing. Chat has the widest context (snapshot blocks + ~25 tools + `[Karakter]`), but it is on-demand; no component produces a standing horizon-tagged (short/mid/long) conclusion across all data. `HypothesisPipelineService` (nightly, smart tier) and the weekly review are the nearest. Proposal: one scheduled "synthesis" call over a pre-assembled all-data context that emits three horizon slots, stored and shown on Boop's Ma page.
- **9 — domain agents examining domains and cross-checking (konzílium):** exists, needs fixing / rethink. The mechanism is implemented and tested, but (a) it is frozen in prod (see §4), (b) agents are personas over detector summaries, not domain investigators, (c) its product is slow dossier claims, not day decisions, (d) it is expensive (budgeted 14 calls/cycle) and quota-starved. For Boop either revive and fix the nightly/quota failures and surface only the *verdict sentences*, or build a small day-scoped council (3-5 domain agents each handed its domain's computed state + one cross-domain tool, then one chair) reusing the proposal/cross-talk/verdict code and the `TeamCharacter` voices.
- **12 — AI re-examines each day live with everything and dynamically adjusts:** exists in rule-based form only. Flags → team-chat cases → one-tap `AdviceMutationPort` actions (lighten tomorrow, sleep anchor, skip sport slot). Missing: LLM-driven re-plan of today (extra food, shorter/longer workout, different movement, less food) using goal kcal, remaining intake, workout plan, sleep/energy and calendar load together. Building blocks exist: `GoalOverviewService` day frame, `DayEvaluationEngine`, `PlanFeasibilityCalculator`, `AdviceMutationPort` actions, fuel/train services.
- **3 (partial, this area):** weight goal engine exists and is good (kcal segments, guards, adaptive review, suggestions); biomarker-effect tracking of recipes/ingredients is only partly there via experiments/patterns/`effect_link`; diet plans with fixed recipe sets are not in this area.
- **5 — plans coordinated with meal plan/weight goal:** goal-plan links, `LOAD_FUEL_MISMATCH` and `protein-training-mismatch` give partial coordination; no AI coordinating a plan as a whole.
- **7 — calendar events scored by AI:** missing in this area (flags and day review have no calendar input; `feature/wearable` calendar_event is separate).
- **10 — day goal, end-of-day close-out vs planned goals:** `intention` + evening feed message + `LifeGoal` pillar scoring exist as pieces; not stitched into a single close-out. Candidate to unify.
- **11 — check-in with biomarker snapshot:** check-in 2.0 feeds detectors (`CheckInNeedSource`) but no watch-snapshot link in this area.
- **Candidates to drop for Boop v1:** chapters/maturity ring/Gépterem/47-detector transparency UI, claim-level user feedback UI, Growth quests/XP skins, memoir archive, life-event graph UI. Keep: detectors as signals, claim store, flags, team chat, patterns, weekly review, predictions, goal overview.

## 7. Open questions / risks

1. **Why is the nightly observation run FAILED 48/55 days?** Pull backend logs around 02:50 and the 21:00 council tick; check whether `CHARACTER_COUNCIL_QUOTA_EXHAUSTED` is a real per-day quota hit (the 90/120-call budget vs. chat usage) or a counter bug (32-day retention, owner/day key) before depending on the konzílium for Boop.
2. Should Boop have its own *small* konzílium (day-scoped, 3-5 agents) or surface the existing profile team's verdicts? The former is a new build; the latter inherits a frozen pipeline.
3. Cost/latency: real-time day re-examination needs a smart-tier call per re-plan; budget interplay with `CharacterCouncilBudget` and the global LLM throttle (`throttle-cron-at-percent: 90`).
4. Safety: adjustments touching food/training for a weight goal need guard rails already present in goal guards and `ClinicalOutputCheck`; sensitive claims (medication cycle, self-assessment) must not leak onto a phone lock screen.
5. Personal-memory dependency: claims, facts and patterns are all derived from the current web data model; a "new account" for Boop (as decided) means starting with an empty dossier unless the same account/backend is reused — confirm which.
6. Doc debt: `insights.md`/`character.md` summaries disagree with the code; trust code and this report when planning.
7. Prediction track record (6 validated / 7 missed / 7 pending) and challenge outcome sparsity (most outcomes blank) suggest the evaluation loop is under-used; surfacing predictions in Boop should come with the outcome loop or it adds noise.
