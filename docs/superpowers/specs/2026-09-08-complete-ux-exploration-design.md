# Complete Mezo UX exploration — two coherent product experiences

Driver: mezo-88jw.3. Daniel approved this expanded mock implementation in conversation on 2026-09-08 and delegated routine design choices. Preserve original palette, soften Mérték, replace green Liget with a light companion-centred experience. No further design selection approval is required to make these alternatives reviewable; production migration is outside scope.

The first prototypes covered too little to support an application-wide decision. This iteration represents the user-named Mezo, Fuel, Train, Én and notification functions, reading their documented behaviour first. Shared data and route semantics allow cross-feature journeys; core tools have efficient working surfaces while each concept retains a different organising centre. Mérték prioritises state and direct access. The companion experience opens with a question whose answer changes next actions; local assistance opens the relevant tool without forcing everything through chat.

Five stable tabs are Nap, Edzés, Fuel, Mezo, Én. Chat is globally reachable through Clay and contextual entry points. A single header owns location/back, notifications link to their actual target, and secondary pages preserve history, params and scroll. Feature hubs use small local destination lists and progressive detail rather than nested dashboard tiles. Existing motif, icons and custom SVGs persist with gentler corners.

Coverage: pattern list/detail/evidence/feedback; predictions with uncertainty/outcome; knowledge facts with edit/correction; character profile distinct from the Clay mascot; weekly summary and daily/domain details. Fuel AI text/photo-example recognition review/correction/save, evaluation, pantry and recipes/cooking/shopping. Train mesocycle wizard/preview/activation and overview, sport, running, exercise library/media and medals. Én sleep/weight logging with trends, people/profile/contact/interactions, routines/create/complete, notification inbox/filter/read/detail/preferences. Explicit demo states and bounded fixture choices replace live AI/devices; no personal messages or real uploads are sent externally.

Validation covers pure state transitions and cross-feature updates, two-variant route coverage, mobile/desktop visual checks, and realistic journeys from notification/companion entry to task completion and return.
