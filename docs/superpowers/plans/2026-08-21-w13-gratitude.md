# W1.3 Gratitude Entries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 1–3 gratitude lines a day, persisted with an optional life area, embedded into memory, and visible as a consecutive-day streak on Me/Napló.

**Architecture:** A second aggregate (`gratitude_entry`) inside the existing `feature/journal` backend package, exposed contract-first under the `Journal` tag (so it lands in the single generated `JournalApi` + `JournalController`), embedded via a new `write<Kind>` method on the single `MemoryEmbeddingWriter` with its own AFTER_COMMIT listener (the W1.1 journal pattern, verbatim). Frontend: a `gratitude` mode in the existing `JournalSheet` mode toggle, a dual-mode hook pair, and a streak card on `JournalPage` whose count is **derived in the frontend** from the fetched list (the medals "derive, don't store" rule).

**Tech Stack:** Spring Boot 4 / Java 21 / Liquibase / JPA, OpenAPI contract (`api/`), React 19 + TanStack Query + vitest/MSW.

**Spec:** [`2026-08-18-phase5-deep-memory-personalization-design.md` §4.1 + §5.3](../specs/2026-08-18-phase5-deep-memory-personalization-design.md) · **Driver:** `mezo-b3pp.3` · **Feature doc:** [`docs/features/journal.md`](../../features/journal.md) (§7 :431-449 is the recipe this plan follows)

## Global Constraints

- `text`: **≤ 280 chars**, enforced at contract (`maxLength: 280`) AND column (`varchar(280)`) AND entity (`@Size(max = 280)`).
- `life_area`: nullable `varchar(16)`, CK on the 8 LIFE keys `mindfulness, mindset, cooking, financial, productivity, learning, connection, recovery` (= `ProgressionTaxonomy.LIFE`).
- Ownership + soft delete exactly as `JournalEntryEntity`: `extends OwnedEntity`, `@SQLDelete` + `@SQLRestriction("is_deleted = false")`, reads via `…AndCreatedByAndDeletedFalse…`.
- Embedding `kind = "gratitude"` — **already permitted** by `ck_memory_embedding_kind` (`202608181610_mezo-b3pp.1_expand_memory_embedding_kinds.sql`) and `MemoryEmbeddingEntity` `@Pattern`; no kind migration.
- Feature switches: gratitude beans ride `FeaturesConfiguration.JOURNAL_SWITCH`; the listener is gated on `{COMPANION_SWITCH, JOURNAL_SWITCH}`.
- Changeset name `202608211200_mezo-b3pp.3_create_gratitude_entry.sql`; constraint names `pk_/fk_/ck_/idx_` per the shipped `journal_entry` file (not the spec snippet's inline PK).
- Every new owned table → `ResetDatabase` TRUNCATE list, same change.
- Streak = consecutive days ending **today** (or yesterday — see Task 6 rule), derived, never stored.
- **Deferred (explicit):** the ritual `ReflectionStep` gratitude rows — `ReflectionStep`/`ACT_COUNT=6` do not exist yet (W1.2 `mezo-b3pp.2` unmerged). Task 8 files the follow-up.
- Commit subjects carry `(mezo-b3pp.3)`; `ALWAYS ./mvnw clean`; FE gate both modes.

package io.mrkuhne.mezo.feature.journal.service;

import io.mrkuhne.mezo.api.dto.CreateGratitudeEntryRequest;
import io.mrkuhne.mezo.feature.journal.entity.GratitudeEntryEntity;
import io.mrkuhne.mezo.feature.journal.repository.GratitudeEntryRepository;
import io.mrkuhne.mezo.techcore.configuration.FeaturesConfiguration;
import io.mrkuhne.mezo.techcore.exception.SystemMessage;
import io.mrkuhne.mezo.techcore.exception.SystemRuntimeErrorException;
import java.time.LocalDate;
import java.util.List;
import java.util.UUID;
import lombok.RequiredArgsConstructor;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.context.ApplicationEventPublisher;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@RequiredArgsConstructor
@ConditionalOnProperty(name = FeaturesConfiguration.JOURNAL_SWITCH, havingValue = "true")
public class GratitudeService {

    private final GratitudeEntryRepository repository;
    private final ApplicationEventPublisher events;

    @Transactional
    public GratitudeEntryEntity create(UUID userId, CreateGratitudeEntryRequest req) {
        var e = new GratitudeEntryEntity();
        e.setCreatedBy(userId);
        e.setOccurredOn(req.getOccurredOn() != null ? req.getOccurredOn() : LocalDate.now());
        e.setText(req.getText());
        e.setLifeArea(req.getLifeArea());
        var saved = repository.save(e);
        events.publishEvent(new GratitudeEntrySavedEvent(saved.getId()));
        return saved;
    }

    @Transactional(readOnly = true)
    public List<GratitudeEntryEntity> list(UUID userId, LocalDate from, LocalDate to) {
        return repository.findByCreatedByAndOccurredOnBetweenAndDeletedFalseOrderByOccurredOnDescCreatedAtDesc(userId, from, to);
    }

    @Transactional
    public void delete(UUID userId, UUID entryId) {
        var e = findOwned(userId, entryId);
        repository.delete(e); // @SQLDelete -> soft delete
        events.publishEvent(new GratitudeEntryDeletedEvent(entryId));
    }

    private GratitudeEntryEntity findOwned(UUID userId, UUID entryId) {
        return repository.findByIdAndCreatedByAndDeletedFalse(entryId, userId)
                .orElseThrow(() -> new SystemRuntimeErrorException(
                        SystemMessage.error("GRATITUDE_ENTRY_NOT_FOUND").build(), HttpStatus.NOT_FOUND));
    }
}

```ts
/** Consecutive days with ≥1 gratitude entry, walking back from today (or yesterday if today is empty). Derived, never stored. */
export function gratitudeStreakDays(occurredOnDates: readonly string[], todayIso: string): number {
  const days = new Set(occurredOnDates)
  const cursor = new Date(`${todayIso}T00:00:00Z`)
  if (!days.has(todayIso)) cursor.setUTCDate(cursor.getUTCDate() - 1)
  let streak = 0
  while (days.has(cursor.toISOString().slice(0, 10))) {
    streak++
    cursor.setUTCDate(cursor.getUTCDate() - 1)
  }
  return streak
}
```
