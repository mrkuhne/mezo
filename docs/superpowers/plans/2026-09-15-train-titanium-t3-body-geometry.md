> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development

**Goal:** ship the real-anatomy foundation every later Train slice draws on — the generated
MuscleMap geometry module, the root `NOTICE.md`, the tested 21-token→shape table, and the
`BodyMap` / `MuscleChip` presentational components.

**Architecture:** a committed Node generator converts two vendored MIT Swift path files into one
generated TS module (paths + per-slug bounding boxes + per-view viewBoxes). A pure mapping table
in `logic/` decides which drawable shapes carry each of our 21 muscle tokens (and the legacy
read-only keys). Two dumb components render it: `BodyMap` (one or two views, heat per token) and
`MuscleChip` (zoom crop of one token). The ~90 KB geometry is loaded through a dynamic import so
it never lands in the main bundle.

**Tech stack:** Node `.mjs` generator (style of `scripts/gen-codemap.mjs`), React presentational
components, vitest + RTL.

**Driving artifacts:** owner-approved prototype `docs/design_2.0/prototypes/companion-titanium/`
(`gen-body-geometry.mjs`, `body-geometry.js`, `muscle-taxonomy.js` `TOKEN_SHAPES`, `muscles.js`),
audit handoff §D1–D2, coverage manifest `docs/design_2.0/2026-09-12-train-coverage.md`,
bd `mezo-88iwa.4`.

  built bundle against the 3 MiB workbox precache cap (`frontend/vite.config.ts:47`).

```js
#!/usr/bin/env node
// Converts the MIT-licensed MuscleMap Swift path files into bodyGeometry.gen.ts.
// Source: https://github.com/melihcolpan/MuscleMap (MIT) — the safe upstream named in the
// openGym audit handoff; openGym's own converted paths are AGPL and must never be copied.
import { readFileSync, writeFileSync } from 'node:fs';

const OUT = 'frontend/src/features/train/logic/bodyGeometry.gen.ts';
const FRONT = 'scripts/vendor/musclemap/MaleFrontPaths.swift';
const BACK = 'scripts/vendor/musclemap/MaleBackPaths.swift';

function parse(swift) {
  const shapes = {};
  for (const block of swift.split('BodyPartPathData(').slice(1)) {
    const slug = block.match(/slug:\s*\.([A-Za-z]+)/)?.[1];
    if (!slug) continue;
    const kebab = slug.replace(/([a-z])([A-Z])/g, '$1-$2').toLowerCase();
    const paths = [...block.matchAll(/"((?:[^"\\]|\\.)*)"/g)].map(m => m[1]).filter(p => /^[Mm]/.test(p));
    if (paths.length) shapes[kebab] = (shapes[kebab] ?? []).concat(paths);
  }
  return shapes;
}

function bbox(shapes) {
  // Absolute anchors are plenty for a viewBox: every subpath opens with an absolute M and the
  // large shapes pin the extremes. A 2% margin absorbs whatever the relative curves add.
  let minX = Infinity, minY = Infinity, maxX = -Infinity, maxY = -Infinity;
  for (const paths of Object.values(shapes)) for (const path of paths) {
    for (const seg of path.matchAll(/([A-Z])([^A-Za-z]*)/g)) {
      const nums = (seg[2].match(/-?[\d.]+/g) ?? []).map(Number);
      if (seg[1] === 'H') { for (const n of nums) { minX = Math.min(minX, n); maxX = Math.max(maxX, n); } continue; }
      if (seg[1] === 'V') { for (const n of nums) { minY = Math.min(minY, n); maxY = Math.max(maxY, n); } continue; }
      for (let i = 0; i + 1 < nums.length; i += 2) {
        minX = Math.min(minX, nums[i]); maxX = Math.max(maxX, nums[i]);
        minY = Math.min(minY, nums[i + 1]); maxY = Math.max(maxY, nums[i + 1]);
      }
    }
  }
  const padX = (maxX - minX) * 0.02, padY = (maxY - minY) * 0.02;
  return [minX - padX, minY - padY, maxX - minX + 2 * padX, maxY - minY + 2 * padY].map(v => Math.round(v));
}

const front = parse(readFileSync(FRONT, 'utf8'));
const back = parse(readFileSync(BACK, 'utf8'));
const boxes = shapes => Object.fromEntries(Object.entries(shapes).map(([slug, paths]) => [slug, bbox({ one: paths })]));
const out = `// Generated by scripts/gen-body-geometry.mjs — do not hand-edit.
// Body geometry from MuscleMap (https://github.com/melihcolpan/MuscleMap), MIT License,
// Copyright (c) Melih Colpan. See NOTICE.md at the repository root.
export type BodyView = 'front' | 'back';
export const BODY: Record<BodyView, { vb: string; p: Record<string, string[]>; b: Record<string, [number, number, number, number]> }> = {
  front: { vb: '${bbox(front).join(' ')}', p: ${JSON.stringify(front)}, b: ${JSON.stringify(boxes(front))} },
  back: { vb: '${bbox(back).join(' ')}', p: ${JSON.stringify(back)}, b: ${JSON.stringify(boxes(back))} },
};
`;
if (process.argv.includes('--check')) {
  process.exit(readFileSync(OUT, 'utf8') === out ? 0 : 1);
}
writeFileSync(OUT, out);
console.log('front:', Object.keys(front).length, 'shapes · back:', Object.keys(back).length, 'shapes');
```

**Files:**
- Create: `frontend/src/features/train/components/BodyMap.tsx`
- Test: `frontend/src/features/train/components/BodyMap.test.tsx`

**Interfaces:**
- Consumes: `shapesFor` (Task 3); `regionColor`/`muscleRegion` from `../logic/muscleColors`;
  geometry via `const geometry = await import('../logic/bodyGeometry.gen')` (dynamic).
- Produces:
  `export type BodyHeat = { token: string; level: 'none' | 'below' | 'entering' | 'in' | 'over' };`
  `export function BodyMap(props: { heat: BodyHeat[]; views?: 'auto' | 'both'; className?: string; ariaLabel: string }): JSX.Element`
  — `views:'auto'` picks the single side carrying more heat (prototype `bodyMap` rule),
  `'both'` renders front+back side by side (prototype `bodyMapDuo`). The heat levels are
  `weekZone.ts`'s exact status vocabulary plus `'none'`; opacities: none .13, below .42,
  entering .58, in .72, over 1 (the prototype's scale with `entering` interpolated).

- [ ] **Step 3: Implement** — a `useEffect` loads the geometry into state; before arrival the
root renders `role="img"` + `aria-label` with a fixed `aspect-ratio` box (both: `132/64`,
auto: `66/64` — the reserved-height rule); after arrival it renders per view: one `<g>`

scale, not an additive quantity — this differs from a *weighted* sum map and is documented
