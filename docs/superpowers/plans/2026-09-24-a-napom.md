# A napom Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close yesterday's review overnight, move the day view into its own "A napom" tab (in
place of Napzárás) with a glass re-dress and live updates, add an evening Napzárás card to Mai,
and rewrite the review prompt in a warmer voice.

**Architecture:**
- **Backend.** A nightly `DayReviewWarmupJob` pre-warms the existing hash-keyed `day_review`
  cache through `DayReviewService.assemble`. A prompt version joins the cache key, so the new
  voice regenerates stale prose.
- **Frontend: new page.** A new `NapomPage` under `/nap/napom[/:date]` replaces `WeekDayPage`,
  built from small pure-logic modules (reading, next action, morning mode, napzárás window) and
  glass components.
- **Frontend: live refresh.** A global `MutationCache.onSuccess` invalidates today's day queries,
  so every log refreshes the page. Today's evaluation also polls every 60 s in real mode.

**Tech Stack:** Spring Boot 4 / Java 21 / JUnit 5 + AssertJ (backend); React 19 + TanStack Query +
Vitest + Testing Library (frontend); `prototype.css` üveg kit.

**Spec:** [`docs/superpowers/specs/2026-09-24-a-napom-design.md`](../specs/2026-09-24-a-napom-design.md) ·
**Prototype:** [`docs/design_2.0/prototypes/uveg-napod.html`](../../design_2.0/prototypes/uveg-napod.html) (v5; the source of truth for look and copy)

## Global Constraints

- The Nap domain tabs are exactly four: `Mai /nap` · `A napom /nap/napom` · `Beszélgetés /nap/uzenetek` · `Rutin /nap/rutin`. Napzárás (`/ritual`) leaves the bar and its route stays.
- The warm-up cron is `0 50 2 * * *`, in the server zone Europe/Budapest. It sits between 02:40 patterns and 03:00 SUN hypotheses.
- The catch-up window is 3 days (yesterday plus the two before it).
- The Mai Napzárás card shows from **20:00** local time until the ritual is closed or the next morning. The constant is `NAPZARAS_CARD_FROM_HOUR = 20`.
- Morning mode: yesterday is `scored` with a `reviewId`, and the `localStorage` key `napom.seen.<yesterdayIso>` is absent. Every storage access is wrapped in try/catch.
- An open day NEVER shows an overall score number.
- **No italic serif for Mezo prose.** Use upright Geist: narrative 15px/1.6, notes 14px/1.55, the reading 16px/500.
- No emoji. Icons come from the Titanium 3D set via `Icon3D`. No glass inside glass. Empty and no-data surfaces are dashed.
- Dark only. Every motion has a `prefers-reduced-motion` branch.
- Copy is Hungarian, verbatim from the prototype where given.
- Every commit subject carries the bd id. Run the FE gate in BOTH modes explicitly: `VITE_USE_MOCK=true` and `VITE_USE_MOCK=false`, with `CI=true`.
- Regenerate `docs/CODEMAP.md` (`node scripts/gen-codemap.mjs`) in every commit that adds or removes a class, component, test or route, and again after every merge.

```java
package io.mrkuhne.mezo.feature.companion.service;

/**
 * A napom S1 (spec 2026-09-24 §1): closes yesterday's review overnight so the morning read is a
 * cache hit instead of a synchronous LLM call. It adds no persistence of its own:
 * {@link DayReviewService#assemble} already hashes the day's inputs and upserts {@code day_review}
 * on a miss, so this job simply ASKS for every finished day in the catch-up window. A retroactive
 * log changes the hash, and the next run (or the next read) rewrites that review exactly once.
 * Per user × date failures are isolated: one bad day never stops the run.
 */
@Slf4j
@Component
@RequiredArgsConstructor
@ConditionalOnProperty(
    name = {FeaturesConfiguration.COMPANION_SWITCH, FeaturesConfiguration.DAY_REVIEW_SWITCH,
        FeaturesConfiguration.DAY_REVIEW_WARMUP_JOB_SWITCH},
    havingValue = "true")
public class DayReviewWarmupJob {

    private final UserFanOut userFanOut;
    private final DayReviewService dayReviewService;
    private final DayReviewWarmupProperties properties;

    @Scheduled(cron = "${mezo.companion.day-review-warmup.cron}")
    public void run() {
        LocalDate yesterday = LocalDate.now().minusDays(1);
        LocalDate from = yesterday.minusDays(properties.catchUpDays() - 1L);
        userFanOut.forEachActiveUser("Day review warm-up", user -> {
            int warmed = 0;
            for (LocalDate date = yesterday; !date.isBefore(from); date = date.minusDays(1)) {
                try {
                    dayReviewService.assemble(user.getId(), date);
                    warmed++;
                } catch (Exception e) {
                    log.warn("Day review warm-up failed for user {} on {}", user.getId(), date, e);
                }
            }
            log.info("Day review warm-up for user {}: {} day(s) in {}..{}", user.getId(), warmed, from, yesterday);
        });
    }
}
```

The loop runs **newest first**, so that yesterday gets warmed even if a slow LLM call stalls the
tail of the window.

```ts
// frontend/src/data/me/liveDay.ts
// A napom S3 (spec 2026-09-24 §4): today is LIVE. Any successful write can move a day input
// (a meal, a set, a check-in, a sleep or weight log, a habit tick), so instead of wiring each
// logging mutation by hand, the global MutationCache calls this once per success. Invalidation
// only refetches ACTIVE queries; an unmounted day page just goes stale — cheap by construction.
import type { QueryClient } from '@tanstack/react-query'
import { addDays, localDateString } from '@/shared/lib/dates'

function mondayIso(now: Date): string {
  const dow = (now.getDay() + 6) % 7 // Mon = 0
  return localDateString(addDays(now, -dow))
}

export async function invalidateTodayDay(client: QueryClient, now: Date = new Date()): Promise<void> {
  const today = localDateString(now)
```

```ts
// A napom (spec 2026-09-24 §2–§3, §6) — the day view's pure rules. Nothing here calls an LLM:
// the live day is read by these rules, the closed day by the overnight review.
import type { NormalizedDayEvaluation } from '@/data/me/dayEvaluation'
import type { MeWeekDay } from '@/data/me/meWeek'

export const NAPZARAS_CARD_FROM_HOUR = 20
/** The card's window closes at the morning boundary — a day nobody closed just loses the card. */
const NAPZARAS_CARD_UNTIL_HOUR = 5

const dim = (ev: NormalizedDayEvaluation, id: string) => ev.dimensions.find((d) => d.id === id)
const trainingDone = (ev: NormalizedDayEvaluation) => dim(ev, 'training')?.status === 'DONE'
const proteinGap = (day: MeWeekDay | null) =>
  day?.proteinG != null && day.proteinTargetG != null ? Math.max(0, Math.round(day.proteinTargetG - day.proteinG)) : null
const anyLog = (day: MeWeekDay | null) =>
  !!day && (day.kcal != null || day.sleepMin != null || (day.checkinCount ?? 0) > 0 || (day.workoutCount ?? 0) > 0)

export function doneCount(ev: NormalizedDayEvaluation): number {
  return ev.dimensions.filter((d) => d.status === 'DONE').length
}

export function dayReading(ev: NormalizedDayEvaluation, day: MeWeekDay | null): string {
  if (!anyLog(day)) return 'Még üres a napod. Az első beírással elindul.'
  const gap = proteinGap(day)
  if (!trainingDone(ev) && gap != null && gap > 0) return `Fehérjéből már csak ${gap} g hiányzik, az edzés még hátravan.`
  if (!trainingDone(ev)) return 'A tányér rendben van, már csak az edzés maradt a mai napból.'
  if ((day?.checkinCount ?? 0) < 4) return 'Az edzés megvolt. Egy esti check-in, és kerek a nap.'
  return 'Minden a helyén. Ma este nyugodtan zárhatod a napot.'
}

export function isNapzarasCardWindow(now: Date, ritualClosed: boolean): boolean {
  if (ritualClosed) return false
  const h = now.getHours()
  return h >= NAPZARAS_CARD_FROM_HOUR || h < NAPZARAS_CARD_UNTIL_HOUR
}

export interface NextAction { kind: 'workout' | 'checkin' | 'napzaras'; eyebrow: string; title: string; sub: string; cta: string; to: string }

export function nextBestAction(ev: NormalizedDayEvaluation, day: MeWeekDay | null, now: Date): NextAction | null {
  if (isNapzarasCardWindow(now, false)) {
    return { kind: 'napzaras', eyebrow: 'MOST ÉRDEMES · ESTE', title: 'Tegyük le a napot',
      sub: 'A napzárás innen és az esti rutinból is indul. Hajnalban megírom, milyen napod volt.', cta: 'Napzárás', to: '/ritual' }
  }
  if (!trainingDone(ev) && dim(ev, 'training')?.status !== 'NO_DATA') {
    return { kind: 'workout', eyebrow: 'MOST ÉRDEMES · DÉLUTÁN', title: 'Még hátravan a mai edzés',
      sub: 'Utána egy fehérjés vacsora, és a tápanyag is kész.', cta: 'Edzés', to: '/train/mai' }
  }
  if ((day?.checkinCount ?? 0) < 4) {
    return { kind: 'checkin', eyebrow: 'MOST ÉRDEMES', title: 'Egy check-in hiányzik',
      sub: 'Fél perc. Utána teljes a napod képe.', cta: 'Check-in', to: '/nap/checkin' }
  }
  return null
}

export const seenKey = (dateIso: string) => `napom.seen.${dateIso}`

export function isMorningMode(y: NormalizedDayEvaluation | null, storage: Pick<Storage, 'getItem'> | null = safeStorage()): boolean {
  if (!y || y.state !== 'scored' || !y.reviewId) return false
  try { return storage?.getItem(seenKey(y.date)) == null } catch { return true }
}

export function markSeen(dateIso: string, storage: Pick<Storage, 'setItem'> | null = safeStorage()): void {
  try { storage?.setItem(seenKey(dateIso), '1') } catch { /* private mode: morning mode simply repeats */ }
}

function safeStorage(): Storage | null {
  try { return typeof window === 'undefined' ? null : window.localStorage } catch { return null }
}
```
