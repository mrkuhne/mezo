# Kihagyás S2 — kímélő mód (recovery period, comeback ramp, programme shift) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A multi-day "kímélő mód" opened from a serious skip reason (or from the Nap hub), which
protects every planned gym day, sport occurrence and run inside it (skipped, excused, never
missed). A daily "Hogy vagy?" card ends it only on the user's word. On return the meso calendar
follows a length-based rule and the first 1–2 gym sessions are lightened. Everything is undoable.

**Architecture:** Two new train tables, `recovery_period` and `recovery_day_release`.
`RecoveryPeriodService` answers `protectedDates`. The S1 central read
(`PlannedSkipService.verdictsBetween`) adds virtual `RECOVERY` GYM verdicts for protected dates.
The sport and run key sets become date-aware predicates, so every existing consumer follows
without its own change. The pure `RecoveryReturnPolicy` decides CONTINUE / RESUME / STEP_BACK and
the ramp size. `RecoveryReturnService` shifts or reverts the active meso. `WorkoutService.getToday`
applies the ramp at read time (sets −⅓, load ≈90% on the first ramp session and on released days,
RIR ≥ 3). The FE gets a dual-mode `recoveryHooks`; synthetic `DAY` skip rows feed the existing
`isSkipped` so every planning surface hides protected occurrences. The UI adds a duration row in
`SkipReasonSheet`, a recovery variant of `SkippedBlock`, a comeback pill on the hero, and on Nap a
"Nem vagyok jól" entry plus a `KimeloCard`.

**Tech Stack:** Spring Boot 3 / JPA / Liquibase / PostgreSQL; OpenAPI fragments → generated
`api.gen.ts` + Java DTOs; React 18 + TanStack Query + Vitest; Titanium SVG sprite (generator).

**Spec:** `docs/superpowers/specs/2026-09-28-kihagyas-kimelo-mod-design.md` §9 (S2 delta) + Slice lessons S1.

## Global Constraints

- Serious categories only open a period: `ILLNESS, STOMACH, INJURY, TRAVEL` (`PlannedSkipPolicy.isSerious`).
- Estimate → `expected_end`: `TODAY` = start, `FEW_DAYS` = start+2, `WEEK` = start+6, `UNKNOWN` = null. The estimate only drives copy; **the period never ends by itself**.
- One open period per user (`ended_on is null`, not deleted). Opening while one is open updates category + estimate (start stays).
- Protected date = `start_date ≤ d` and (`ended_on is null` or `d < ended_on`) minus released dates. An open period protects forward without a bound (reads clamp to the queried range).
- Recovery verdicts: `Source.RECOVERY`, always excused, never a free pass, out of the free-pass race.
- Days out `d = ended_on − start_date` (min 1). Rule: `d ≤ 2` CONTINUE + ramp 1; `3 ≤ d ≤ 9` RESUME + ramp 2; `d ≥ 10` STEP_BACK + ramp 2.
- Meso shift in whole weeks only. RESUME: target week = `weekOf(start_date)`. STEP_BACK: `max(1, weekOf(start_date) − 1)`, plus each muscle's `currentSets` minus one weekly step (`props.step()`), floored at MEV, and `volumeRecompute.lastRun = "W"+target`. The shift snapshot (`shift_meso_id, prev_start, prev_end, prev_current_week, prev_last_run, prev_sets jsonb`) is stored on the period for exact undo.
- Ramp sets per exercise: `sets − max(1, round(sets/3))`, min 1 (4→3, 3→2, 5→3, 2→1). RIR target ≥ 3. Load: ramp session #1 and released days ≈ 90% of the reference working load, snapped to the plate grid; ramp session #2 `holdOnly`.
- Ramp counts **completed gym sessions after `ended_on`**; `comeback_waived` switches it off. A released day's lightening can be waived per day (`recovery_day_release.lighten=false`).
- Never a `workout_session` row, never a `workout_day_adjustment` row (the advice "lighten tomorrow" owns that unique index).
- Weekday numbering for SPORT = 0=Hét..6=Vas. Europe/Budapest dates.
- Copy: Hungarian, warm; forbidden: `elrontott|túlléptél|hiba|rossz|bukta|kudarc`. Icons: Titanium sprite only (`t-kimelo` new, `t-sprout`, `t-ill`, `t-digestion`, `t-pain`, `t-travel`, `t-skip`), never emoji.
- ArchUnit: `train` never imports `companion`/`proactive`/`notification`/`quest`; companion may import train services. Layer subpackages. No class-level `@Transactional`.
- Writes take `PlannedSkipLock` (readiness's double-tap 500 must not be copied).
- New tables join `ResetDatabase` TRUNCATE; index prefix `idx_`; no jsonb `?` in Liquibase.
- FE: `VITE_USE_MOCK` unset = mock; the real-mode gate needs `VITE_USE_MOCK=false`; `CI=true`.
- Backend ITs: `-Dmezo.test.use-testcontainers=true`.
- Not switch-gated (plain CRUD like S1). No LLM.

```sql
-- Kihagyás S2 (mezo-q4xt2.2, spec 2026-09-28 §9): kímélő mód — a user-declared recovery period
-- opened by a serious skip reason. Every planned gym/sport/run occurrence on a protected date reads
-- as skipped + excused (PlannedSkipService, read time). It never ends by itself: ended_on is set only
-- by the user's "Jobban". The shift_* / prev_* columns snapshot the meso calendar change applied at
-- "Jobban", so "Mégsem vagyok jól" / "Tévedés volt" revert it exactly.
create table recovery_period (
    id                uuid         not null default gen_random_uuid(),
    created_by        uuid         not null,
    is_deleted        boolean      not null default false,
    created_at        timestamptz  not null default now(),
    updated_at        timestamptz  not null default now(),
    category          varchar(16)  not null,
    estimate          varchar(16)  not null,
    start_date        date         not null,
    expected_end      date,
    ended_on          date,
    last_check_date   date,
    comeback_waived   boolean      not null default false,
    shift_meso_id     uuid,
    shift_days        integer      not null default 0,
    prev_start        date,
    prev_end          date,
    prev_current_week integer,
    prev_last_run     varchar(8),
    prev_sets         jsonb,
    constraint pk_recovery_period_id primary key (id),
    constraint fk_recovery_period_created_by_app_user_id
        foreign key (created_by) references app_user (id) on delete cascade,
    constraint ck_recovery_period_category check (category in ('ILLNESS', 'STOMACH', 'INJURY', 'TRAVEL')),
    constraint ck_recovery_period_estimate check (estimate in ('TODAY', 'FEW_DAYS', 'WEEK', 'UNKNOWN')),
    constraint ck_recovery_period_end check (ended_on is null or ended_on > start_date)
);
create unique index idx_recovery_period_one_open
    on recovery_period (created_by) where is_deleted = false and ended_on is null;
create index idx_recovery_period_user_start on recovery_period (created_by, start_date) where is_deleted = false;

-- "Ma mégis edzek": one released date inside a period (gym + sport + run of that day train normally).
create table recovery_day_release (
    id          uuid         not null default gen_random_uuid(),
    created_by  uuid         not null,
    is_deleted  boolean      not null default false,
    created_at  timestamptz  not null default now(),
    updated_at  timestamptz  not null default now(),
    period_id   uuid         not null,
    date        date         not null,
    lighten     boolean      not null default true,
    constraint pk_recovery_day_release_id primary key (id),
    constraint fk_recovery_day_release_created_by_app_user_id
        foreign key (created_by) references app_user (id) on delete cascade,
    constraint fk_recovery_day_release_period_id_recovery_period_id
        foreign key (period_id) references recovery_period (id) on delete cascade
);
create unique index idx_recovery_day_release_period_date
    on recovery_day_release (period_id, date) where is_deleted = false;
```

**Contract** (`/api/train/recovery`):
- `GET` → `RecoveryState { period: RecoveryPeriod | null, protectedDates: date[] (today−7 … today+13), comeback: { total: 0|1|2, done: int, waived: bool } | null }`
  - `RecoveryPeriod { id, category, estimate, startDate, expectedEnd?, endedOn?, dayIndex (today−start+1), estimateExpired (expectedEnd != null && expectedEnd < today), checkedInToday (lastCheckDate == today), releasedDates: date[], releasedUnlightened: date[], return?: { rule: CONTINUE|RESUME|STEP_BACK, daysOut, rampSessions, shiftDays, newEndDate? } }`
  - `period` is the open one, or the one ended **today** (so "Mégsem vagyok jól" can show).
- `PUT` body `{ category, estimate, startDate? }` (startDate defaults to today; allowed `today−7 ≤ startDate ≤ today`) → `RecoveryState`. Open, or update category/estimate of the open one. Non-serious category → 400 `TRAIN_RECOVERY_CATEGORY_INVALID`.
- `POST /check-in` `{ answer: BETTER | NOT_YET }` → `RecoveryState`.
  - NOT_YET sets `lastCheckDate = today`.
  - BETTER sets `endedOn = today` (400 `TRAIN_RECOVERY_TOO_EARLY` when `today == startDate`) and calls `RecoveryReturnService.apply`.
  - No open period → 404 `TRAIN_RECOVERY_NOT_FOUND`.
- `POST /undo-better` → reverts the shift and sets `endedOn = null`. Only for the period ended today; otherwise 409 `TRAIN_RECOVERY_UNDO_EXPIRED`.
- `DELETE` → soft-deletes the open or today-ended period, reverting any shift. 404 when none.
- `PUT /releases/{date}` `{ lighten: boolean }` (default true) and `DELETE /releases/{date}`. The date must be protected by the open period, else 400 `TRAIN_RECOVERY_DATE_NOT_PROTECTED`.
- `POST /waive-comeback` → `comebackWaived = true` on the latest ended period.
